# Ковка оружия из деталей — гейм-дизайн

Документ РЕШЕНИЙ: что игрок делает, из чего это собрано, какими числами держится и почему
отвергнуто другое. Состояние работ живёт во вкладке «📍 Роадмап» конфиг-редактора.
Экономика сырья, разбор и ступени — в [ECONOMY.md](ECONOMY.md).

Все числа в документе ЗАМЕРЕНЫ по коду и конфигу, а не оценены. Где замера нет — написано
«оценка». Где замер противоречит прежней версии документа — старая строка удалена, а не
поправлена: в §0 перечислено, что именно отменено.

## 0. Что отменено из первой версии

Первая версия писалась до замеров. Шесть независимых разборов кода плюс три сверки вскрыли,
что три её опоры держались на числах, которых в игре нет. Отменённое:

| Было | Почему отменено | Стало |
|---|---|---|
| **Навершие торгует «масса ↔ требования»** | Ось мертва с ОБЕИХ сторон. Масса: вся лестница весов (кинжал 3 → молот 25) двигает шанс сбить с ног на **0.44 п.п.** (4.31 % → 4.75 % по цели массой 100), потому что `knockdown.chanceBase` = 0.85 растворяет вклад оружия, а сопротивление `масса_цели × 0.01` упирается в кап 0.95 у 11 монстров из 13. Потолок ВСЕЙ механики нокдауна — +2.37 % урона. Требования: кап `maxTotalRequirement` 190 душит **42 базы из 50 на t6** и 24 на t5, там −15 % двигают ровно ноль; зато на t3–t4 та же колонка стоит 3.5–7.5 % ДПС — перекос 31:1…260:1 | Гнездо 4 торгует **«укус ↔ упор»**: шанс статуса против блока и стойкости (§7) |
| **Р5: «ковка до t5, t6 только с дропа»** | Решение владельца: t6 куётся, но через счётчик разобранных мифических вещей и по цене ×6 сырьём | t6 куётся (§12) |
| **Чертежи падают с монстров, из сундуков и с боссов** | Решение владельца: чертежей как предметов нет | Разбор вещи у кузнеца открывает и базу, и её четыре детали (§12) |
| **Лезвие ±15 п.п. урона / ∓12 % скорости, «разброс ≤ 6 %»** | Замер на сетке из самого документа (бонусы урона 0…0.9 × скорости 0…0.9): пара 15/12 даёт **19.2 %** разброса, а не 6 %. И сам документ спорил с собой: §14 обещал 6 %, фаза К5 — 8 % | Пара **±10 / ∓8** и один объявленный конверт (§4) |
| **Рукоять: «+20 % дальности ↔ −20 % дуги, ни одна сторона не ДПС»** | `meleeSwing` бьёт ВСЕХ в секторе, площадь сектора = `дуга × дальность²`. Длинная рукоять давала **+27.6 % сметаемой площади** — то есть гнездо, объявленное «ДПС не трогает», было почти втрое сильнее единственной разрешённой оси ДПС | Площадь-нейтральная пара: `дуга × дальность² = const ± 3 %` (§5) |
| **«У лука и арбалета рукоять торгует дальностью против разброса»** | Дальность снаряда — константа `440 × 2.5 = 1100 px` при зрении монстра 240–320 px: стрелять дальше, чем видишь, можно уже вчетверо. Поля «разброс» у оружия не существует вовсе — `spread` принадлежит СКИЛЛУ | Пробой с затуханием, и он требует правки кода (§5) |
| **«Новых семейств сырья не вводим»** | Решение владельца: у деталей свои тиры по материалам. Трёх ступеней железа под лестницу «болотное → кричное → уклад → дамаск → булат» не хватает | Восемь семей по пять ступеней, ровно три на вещь (§10) |
| **«Скованное РАВНО найденному по силе»** | Замер по весам аффиксов: скованная форма 3+2 несёт **2.78** полезных билду аффикса против **2.22** у среднего найденного редкого (+25 %). Правило Р1 не нарушено — такая вещь выпадает у 16.7 % редких, — но формулировка была неверна буквально | «Равно ВЕРХНИМ 17 % найденных редких и платит за это шестикратно» (§2) |
| **«Три клика»** | После всех решений честный флоу — 8 действий при 5 решениях | Пишем 8 и не врём (§17) |
| **Сначала выбирается чертёж (база), потом материал, потом ступень, потом детали** | Решение владельца: «пойдём от обратного, всё начинается с частей». Выбрал семейство (одноручный меч) и детали — окно само пишет, что за меч получился | Семейство → ключевая деталь (она и есть тип) → детали; тип, историческое имя и ступень ВЫВОДЯТСЯ (§3, §11) |
| **Материал один на всю вещь, «полоса ступеней»** | Решение владельца: у каждой детали свой материал («широкое лезвие — из болотной руды или кричного железа»), ступень — по общему уровню частей | Окно материалов у ФОРМЫ; ступень вещи — средний уровень материала по массе (§10, §11) |

## 1. Рамка: решения владельца

| Ось | Решение |
|---|---|
| Что делает крафт | **Создаёт вещь с нуля** из деталей, а не только улучшает найденное |
| Визуал | **Модель собирается из частей** |
| Охват | **Все 10 классов оружия** равным числом деталей — четыре гнезда у каждого |
| Откуда детали | **Разобрал вещь у кузнеца — открылись части, из которых она состояла.** Чертежей как предметов нет |
| Редкость деталей | Прямая гарда часто, изогнутая реже, фигурная ещё реже |
| Тиры деталей | **Материал задаёт уровень детали**: низкокачественное железо t0–2, кричное t2–3, дамаск t3–5, булат t5–7. По магическим, рукоятям и остальному — так же. **Правдоподобно, по историческим источникам** (сделано окнами форм и средним уровнем по массе, §10–§11) |
| Уровень вещи | **Вычисляется из уровня частей** — средним по массе, сам (§11) |
| Тип оружия | **Определяется деталями:** выбрал одноручный меч, выбрал клинок, рукоять, гарду и навершие — окно пишет, что за меч получился. Таблица классификации — по Окшотту, Кирпичникову, Dean и другим историкам оружия, для всех классов (§3.3) |
| Материал детали | **У каждой детали свой**, и форма ограничивает выбор: широкое лезвие — из болотного или кричного железа, пламенеющий клинок — только из хорошей стали (§10) |
| Аффиксы | Сперва куётся **база**, потом отдельно поднимается до магической/редкой. В ковке заложено, **сколько каких аффиксов** база примет, и это **видно в момент создания** |
| Цена | Чем лучше база — тем дороже по ресурсам |
| t6 | **Куётся**, но разобрав некоторое количество t6 предметов, и стоит очень дорого |
| Варианты деталей | **Не по три.** Лезвий много — плоское, широкое, фальшион, узкое, изогнутое; у каждого свои показатели |
| Статусы | Можно сделать **шанс наложения эффекта** от детали, и в противовес что-то поставить |
| Блок | У оружия есть свой небольшой шанс блока — **обыграть его** |
| Сила | Равна найденному, но специализирована под билд |
| ⭐ Главное | **Приятное дополнение, а не вторая работа.** Не ломать флоу D2/PoE 2: можно бегать с тем, что нашёл, и вкладку не открывать |
| Материалы | Не пятнадцать материалов ради одного меча |

## 2. Шесть правил, которые нельзя нарушать

**Р1. Крафт не создаёт мощности, которой нет в дропе.** Каркас скованного — та же база из
`items-base.json` и та же ступень. Ковка меняет не силу, а **её форму**. Точная формулировка
после замера: скованная вещь равна **верхним 17 % найденных редких** и платит за это
шестикратной ценой; больше лучшего дропа она не даёт ни на единицу.
Цифры базы тоже не выше найденных: скованная катается в **той же вилке**, что найденная вещь той же
базы и ступени (§13.1), и доводка поднимает только НИЗ вилки — верх не растёт никогда.

**Р2. У каждой детали заполнены обе колонки — «дал» и «забрал».** Ни одной детали, которая
просто лучше другой. Урок Warframe (Zaw/Kitgun) и Destiny 2: там части давали чистый плюс,
и через месяц все играли двумя-тремя мета-сборками.

**Р3. Случайность — только в ЗНАЧЕНИИ, никогда в том, что выпадет.** Детали выбираются
осознанно, вилка видна заранее; катаются аффиксы и цифры базы внутри вилки ступени (§13.1) —
ровно как у найденной вещи. Что именно выпало, игрок узнаёт после ковки, а до неё видит «от и до».
Отсюда же: детали найденной вещи **выводятся детерминированно из неё самой**, а не катаются
в момент разбора — иначе разбор становится лотереей.

**Р4. Провал не «кирпичит» вещь.** Любую сборку можно переплавить и вернуть часть вложенного.
Главная жалоба на Last Epoch (`Forging Potential = 0` — предмет закрыт навсегда) и на темперинг
Diablo 4 — именно про это.

**Р5. Редкость варианта детали — это ЧАСТОТА, а не сила.** Фигурная гарда не лучше прямой,
она реже. Все варианты одного гнезда сидят на ОДНОЙ его оси, просто в разных её точках.
Сторож обязан группировать замер ДПС по редкости детали и краснеть при расхождении.

**Р6. Ступень вещи задают детали, а не кошелёк.** У каждой детали свой материал в окне её
формы; ступень вещи — средний уровень материала ПО МАССЕ (клинок весит две пятых), сверху её режут
потолок базы и журнал кузнеца. «Одна дорогая деталь + три дешёвые» законна, но и стоит ровно своей
доли: булатный клинок при болотном прочем даёт t2, а мифик требует булатного клинка (§11).

⚠ **Три формулировки уточнены под «тип из деталей»** (смысл тот же, числа те же):
* «одна ось ДПС» → **«одна ось ДПС ВНУТРИ ТИПА»**: смена ключевой детали — это смена типа, то
  есть другая база, как раньше другой чертёж; внутри типа ДПС двигает только гнездо 1;
* «вес не покупается деталью» → **«вес не складывается из деталей»**: ключевая деталь выбирает тип
  ЦЕЛИКОМ (урон, скорость, вес, требования, грань одним пакетом из `items-base`), и ни одна деталь
  не пишет в эти поля поверх типа — собрать «лёгкий вес от одной детали и тяжёлый урон от другой»
  нечем;
* **«грань принадлежит типу, тип — ключу»**: однолезвийный кинжал — режущий тесак, протазан —
  колющий; внутри типа грань не меняет ничто, и имя не обещает чужую грань.

## 3. Конструкция: семейство → детали → тип, имя и ступень выводятся

```
СЕМЕЙСТВО          ЧЕТЫРЕ ГНЕЗДА, у каждого — форма и СВОЙ материал            АФФИКСЫ
(класс × хват)                                                                (потом, отдельным глаголом)

Меч, одноручный    ★1 клинок   «Широкий с долом, X»    урон ↔ скорость     · уклад          форма объявлена при ковке,
                    2 рукоять  «Тесная»                дальше ↔ шире       · варёная кожа   значения катаются как у дропа
                    3 гарда    «Короткое перекрестье»  префиксы ↔ суффиксы · воронёная сталь
                    4 навершие «Трёхчастное»           укус ↔ упор         · воронёная сталь

★ ключевая деталь → ТИП (база):  «Длинный меч» · урон 7–13 · режущий · вес среднее
все четыре детали → ИМЯ:         «Ранний меч» · Свод: клинок X · перекрестье 3 · навершие трёхчастное
материалы деталей → СТУПЕНЬ:     t3 Отличный (Q = 3.0)
```

Игрок не выбирает ни чертёж, ни ступень, ни «материал вещи». Он выбирает семейство и четыре
детали с их материалами, а ядро выводит остальное:

* **ТИП** — ключевая деталь по таблице классификатора выбирает одну из **50 существующих баз**
  целиком: урон, скорость, требования, класс, грань и сигнатурные поля (`stunChance`,
  `armorPenPct`, `arcMult`, `reachMult`). Правило Р1 держится по построению: клинок рыцарского
  класса даёт длинный меч, а не «что-то похожее». Выбор лёгкого клинка — ровно прежний выбор
  лёгкого чертежа, только сделанный одним кликом вместе с точкой оси.
* **ИМЯ** — историческое, по деталям всех четырёх гнёзд (§3.3). Ни одного числа имя не несёт.
* **СТУПЕНЬ** — средний уровень материала деталей по массе (§11).

### 3.1 Гнездо × класс: как деталь называется у каждого из десяти

Гнездо несёт РОЛЬ, класс даёт ИМЯ и МЕШ. ★ — ключевое гнездо, по которому историки узнают тип.

| Класс | 1 · УДАРНАЯ ЧАСТЬ<br>урон ↔ скорость | 2 · ДЕРЖАК<br>дальше ↔ шире | 3 · ОБВЯЗКА<br>префиксы ↔ суффиксы | 4 · ОГОЛОВЬЕ<br>укус ↔ упор |
|---|---|---|---|---|
| Меч `sword` | ★ Клинок | Рукоять | Гарда | Навершие |
| Кинжал `dagger` | ★ Клинок | Черен | Гарда | Оголовок |
| Топор `axe` | ★ Полотно | Топорище | Проушина (щекавицы) | Обух |
| Булава `mace` | ★ Било | Рукоять · у двуручной Древко | Обоймица | Конец рукояти · у двуручной Подток |
| Копьё `spear` | ★ Перо | Древко (хват) | Втулка | Подток |
| Алебарда `halberd` | ★ Полотно | Древко | Обоймица | Подток |
| Лук `bow` | ★ Рога | Рукоять | Тетива | Концы и накладки |
| Арбалет `crossbow` | Дуга | ★ Ложе и стремя | Замок | Взвод |
| Жезл `wand` | Навершие | ★ Ствол (порода) | Оправа | Пята |
| Посох `staff` | Навершие | ★ Древко (порода) | Оковка | Пята |

Почему ключ не всегда в гнезде 1: у арбалета тип различают ложе и стремя (взвод исторически —
съёмный прибор, а дуга — только тугость); у жезла и посоха — порода дерева, она и задаёт стихию
(привязка наша, «по мотивам»: лещина — молния, тёрн — холод, тис — яд, осмол — огонь, эбен — архимаг).

### 3.2 Четыре роли в одной таблице

| Гнездо | Ось | Ближний бой (30 баз) | Стрелковое (10 баз) | Магическое (10 баз) |
|---|---|---|---|---|
| **1 · Ударная часть** | единственная ось ДПС внутри типа, зеркальная | удар ×(1 ± 0.10) ↔ скорость оружия ×(1 ∓ 0.08) | то же: туже натянуто = урон, мягче = темп | то же: болт идёт через тот же `attackCd` |
| **2 · Держак** | дальше по одному ↔ шире по многим | `reachMult` ↔ `arcMult`, площадь-нейтрально | пробой с затуханием ↔ одна цель (**нужна правка кода**) | то же, что у стрелкового |
| **3 · Обвязка** | форма ёмкости аффиксов | узкая 3+1 · равная 2+2 · широкая 1+3 | то же | то же |
| **4 · Оголовье** | укус ↔ упор | шанс статуса своей грани ↔ блок `+0.02` | лук: ↔ `interruptResist`; арбалет: ↔ блок ложа | шанс статуса своей стихии ↔ блок |

⭐ **Внутри типа ДПС двигает ровно одно гнездо.** Замок: `mods` детали **выводятся** из её поля
`axis` (−1…+1) умножением на шаг гнезда, а не пишутся руками. Тогда «деталь написала в чужой стат»
физически невозможно, а не запрещено правилом. Смена ключевой детали — смена ТИПА (другая база), и
поэтому все замеры ДПС идут при фиксированной базе.

⚠ Но одного этого мало: гнездо 4 через шанс статуса всё равно сдвигает ДПС. Поэтому сторож
формулируется не как «гнёзда 2–4 не пишут в `damagePct`/`attackSpeed`», а как
**«суммарный сдвиг ДПС от гнёзд 2–4 на сетке сборок ≤ 3 %»**, и мерится он на реальном бою
(`session/microFight.ts`), а не закрытой формулой.

### 3.3 Классификация: что за оружие получилось

Формы сняты с реальных типологий, но ИМЕНА в игре свои (§3.4). Мечи — **Окшотт** (клинки X–XXII, навершия A–Z,
стили крестовин) и **Петерсен / Кирпичников** для эпохи викингов: у ранних мечей тип задаёт эфес, у
поздних — клинок, поэтому база берётся по классу клинка, а эпоха и каноническое имя — по гарде с
навершием. Кинжалы — **Dean 1929** (прозвание даёт эфес). Топоры — **Кирпичников 1966** (типы I–VIII)
и **Петерсен**: номер складывается из полотна, щекавиц и обуха. Булавы — **Кирпичников 1966, вып. 2**:
имя — форма била. Копья — Кирпичников (⚠ номера по вторичным пересказам, до выпуска сверить).
Древковые — **Уолдман 2005**, **Двуреченский 2008**. Луки — Черненко, Coulston 1985, находки Mary
Rose. Арбалеты — **Payne-Gallwey 1903**. Жезлы и посохи — Catholic Encyclopedia 1908 и гримуары.

Два слоя, и они не смешиваются:

1. **МЕХАНИКА** — тег ключевой детали по таблице `weapon-types.bases` выбирает базу. Таблица
   ТОТАЛЬНА: каждое «семейство × значение ключа» ведёт ровно в одну включённую базу своего класса и
   хвата, и каждая из 50 баз достижима (сторож).
2. **ИМЯ** — упорядоченные правила `weapon-types.names` по тегам всех четырёх гнёзд: первое совпадение
   даёт историческое имя, иначе имя собирается шаблоном («Узкий меч позднего образца»,

**Арбалеты — отдельное исследование** (Payne-Gallwey 1903, Breiding 2013 «A Deadly Art», Met, Royal
Armouries, KHM, DHM; китайские находки — Циньцзяцзуй M47, «Тяньгун кайу», «У бэй чжи»). Исторически
одноручных арбалетов мало, честных типа четыре: цельностальной **балестрино** (20–29 см, винт взвода в
полой рукояти), лёгкий «дамский» каменный арбалет XVI в. (по Payne-Gallwey его наводили одной рукой),
комнатный **арбалет-пистолет** XIX в. и чуский двузарядник IV в. до н. э. ⚠ Прежняя строка данных
«пистолетное ложе = Балестрино» была неверна: пистолетной рукояти у балестрино нет, она у его потомка XIX в.
Двуручные разложены по немецкой размерной типологии Harmuth/Breiding (шнеппер → «полуснаряжение» →
«полное снаряжение» → крепостной) плюс каменные, испанские, ствольный и восточные.
⚠ Спорное место для владельца: исторически кранекинное ложе — СРЕДНИЙ размер (арбалет Ульриха V — 2.97 кг),
а у нас оно стоит на тяжёлом арбалете; привязки «ложе → база» не менял.
Два правила — по способу взвода, а не по ложу («с поясным крюком», «с козьей ногой»): так их и определяют
источники, и иначе вольная сборка другого ложа той же базы получила бы это имя.

Пример — правило «Ранний меч»: одноручный, клинок типа X, хват тесный или обычный,
короткое перекрестье (стиль 3), навершие трёх- или пятичастное либо треугольное (Петерсен).
Любая другая сборка с клинком X даёт либо другое правило («Классический меч» — длинное перекрестье и
навершие-диск), либо шаблон. Правила условиями не несут чисел, поэтому **имя тянет за собой точку
оси, но не силу**: «Ранний меч» требует клинок X (+1), зато любая точка оси доступна у соседнего
имени.

Правила, которые держат сторожа (`craft.test.ts`):

* **Вольная сборка не носит канонического имени.** Шаблон «эпитет + меч» дал бы «Раннгский меч»
  сборке, которая правило НЕ выполнила. Поэтому эпоха в шаблоне — оборотом («Меч каролингской
  эпохи»), а сторож перебирает ВСЕ сборки всех классов и краснеет при совпадении с именем правила.
* **Мёртвых правил нет:** каждое имя срабатывает первым хотя бы на одной сборке. Порядок правил
  молча затеняет нижние — лампа «затенённые правила» есть и в сетке баланса редактора.
* **У каждого имени есть источник или пометка «фэнтези».** Номер Кирпичникова выводится только с
  годом работы; Окшотта в подписях не-мечей нет; «двулезвийного топора», «колющего меча» и
  «эстока» нет вовсе.
* **Приставка тира склоняется по роду ИМЕНИ ТИПА:** «Мастерская дага», «Крепкое балестрино».
* **Кодекс типов** — коллекция имён без единого числа: отмечается «видел» (разобрал вещь, чьи детали
  его дают) и «сковал»; у недоступного видно, чего не хватает («Цвайхендер: гарда — кольца и крюки»).

⚠ **Переименования баз — ПРЕДЛОЖЕНИЯ, не сделаны** (нужна отмашка владельца; id не меняются):
«Длинный меч» → «Рыцарский меч» (одноручный — это рыцарский, «длинный» выдаёт рукоять);
«Клеймор» → «Цвайхендер» (клеймор теперь имя по гарде); «Клинок ассасина» → «Рондель»;
«Тесак» → «Скрамасакс»; «Моргенштерн» → «Шипастая булава» (моргенштерн — древковое кропило);
«Охотничий лук» → «Простой лук»; «Боевой лук» → «Большой степной лук»; «Длинное копьё» →
«Рогатина» (и, возможно, поменять местами дальность с пикой: исторически пика длиннее).

### 3.4 Имена: формы исторические, названия свои (мир фэнтезийный)

Мир игры не знает ни Каролингов, ни Рима, ни Окшотта — поэтому реальные эпохи, места и фамилии
учёных из ВИДИМОГО текста убраны, а формы остались какими были.

| Что убрано | Чем заменено |
|---|---|
| каролингский, «эпоха викингов» | **ранняя эпоха** |
| романский, раннероманский | **классическая эпоха** |
| «позднего образца», позднее средневековье | **имперская эпоха** |
| римский, античный | **архаичная эпоха** |
| Окшотт, Петерсен, Кирпичников, Элмсли, Ульберт, Микс — в подсказках | текст без ссылки на учёного |
| Майнц, Помпеи, Фулхэм, Хиспаниенсис — имена клинков гладиуса | длинный · широкий · прямой · короткий |
| века в подсказках («XIII–XIV вв.», «1270–1340») | эпохи мира или ничего |

**Четыре эпохи** — единственная хронология, которую видит игрок: архаичная (всё древнее, до ранней),
ранняя, классическая, имперская (всё позднее: палаши, рапиры и прочее «современное»).

⭐ **Эпоху меча задаёт КЛИНОК** (решение 25.09): поле `epoch` у значений `strike.type` в `weapon-anatomy`,
шаблон вольной сборки — `{strike.type.adj} {noun} {strike.type.epoch} {head.pommel.with}`. До этого эпоха
бралась от навершия, и двуручник с шаровым навершием звался бы «архаичным» — такого меча не было: древних
клинков длиннее 90 см история не знает. Эфес по-прежнему решает КАНОНИЧЕСКОЕ имя (правила «Ранний меч»,
«Классический меч» смотрят на гарду и навершие), а у навершия эпохи больше нет; шипастое (фэнтези)
дописывает себя оборотом «с шипастым навершием».

⭐ **Слова для самого оружия остаются настоящими** — это решение владельца: меч, клинок, фальшион,
сабля, мессер, гладиус, клеймор, цвайхендер, нагель, рикассо, дол. Уходит привязка к реальной
истории, а не колорит; без этих слов текст становится сухим.

⚠ **Реальная привязка не потеряна, а спрятана.** У детали появилось поле `ref` («Окшотт XII»,
«Gladius Mainz»), у правила имени эту роль играет `source`. Оба поля нужны при моделировании и
правках баланса, и оба НЕ печатаются игроку: окно ковки больше не выводит строку `source`
(раньше выводило — и там стояло «Oakeshott 1964»). Видно их в редакторе.

### 3.5 Четыре класса меча по длине клинка, эпоха — отдельно

полуторный XX — 127 (110–128), двуручный прямой с длинной двуручной рукоятью — 156 (цвайхендер 155–178),
гладиус со щитком и шаровым — 71 (65–75).

**История правок.** До 24.09 классов было пять: «архаичный 45–70» смешивал эпоху с длиной, а «длинный 85–90»
загонял все рыцарские типы в верхний хвост исторического разброса (медианы 73–85): рыцарский меч в сборе
выходил 100–106 см при исторических 90–102. Ещё раньше «короткий меч» был полосой клинков по 50–54 см, а
меч ранней эпохи лежал в «длинных». Длины задаются в `blades.ts` на КАЖДЫЙ тип отдельно, `SWORD_LEN` —
только фолбэк для типов без своего `case`.

**Архаичные формы — четырнадцать.** Четыре клинка гладиуса (I–IV) и десять древних, снятых с настоящих
находок: серповидный (V), листовидный (VI), литой (VII), игольчатый (VIII), щучий язык (IX), падающий,
куцый, тупоконечный, узорчатый, с прямой спинкой. Пяти последним Свод числа не дал — их записали словом;
так же, как в реальности доримские клинки нумеруют буквами или зовут по месту находки. С 25.09 двенадцать
из них — короткие, два — длинные, а «с прямой спинкой» (сакс) — ранней эпохи, не архаичной.

⭐ **Имена у древних форм — настоящие слова оружия**, как и у гладиуса: правила дают «Хопеш», «Ксифос»,
«Копис», «Акинак», «Спата», «Сакс». Это не привязка к реальной истории мира, а обычные названия
предметов — ровно то, что владелец просил сохранить, чтобы текст не стал сухим.

⚠ **Каждая новая форма обязана иметь свой `case` в построителе модели** (`blades.ts`): без него клинок
падает в общий профиль, и сторож «разные детали выглядят по-разному» валится.

⚠ **Дальность пока не привязана к классу.** `reachMult` у мечевых баз не задан, и длина клинка живёт
только в модели. Лестницу дальности (0.90 → 1.20) нужно вводить вместе с обратной правкой дуги
(`дуга × дальность²` = const, §5.1) и мерить на `microFight`, иначе вилки превратятся в лестницу силы.

## 4. Гнездо 1 — ударная часть: урон ↔ скорость

Одна зеркальная пара — **множители самого оружия: удар ×1.10 ↔ скорость ×0.92**.

| Точка оси | Удар | Скорость оружия | Кому |
|---|---|---|---|
| **τ = +1** тяжёлая | **×1.10** | **×0.92** | крит-билды, кровотечение (оно считается от РАЗМЕРА удара), редкие крупные удары |
| **τ = 0** ровная | ×1.00 | ×1.00 | дефолт |
| **τ = −1** лёгкая | **×0.90** | **×1.08** | статусы и проки за удар, вампиризм, серии ударов, вставки «при касте» |

⭐ **У мечевого клинка с измеренной моделью τ руками не ставится:** это место длины клинка внутри его вилки
плюс поправка формы — та же ось и те же ручки, только число снято с модели (§26).

**Как это видит игрок.** Цифры урона в подсказке уже умножены на форму клинка; скорость — одной
строкой **«Скорость: ×0.85 · 51 уд/мин»** от эталона: ×1.00 = 60 ударов в минуту, базовая скорость
движка (удар в секунду без бонусов героя) — как «скорость оружия» в D2. Отдельных строк «+10 % урона»
и «−15 % скор. атаки» у оружия больше нет — ни у скованного, ни у найденного: собственная скорость
базы тоже показывается множителем (клеймор ×0.85, кинжал ×1.20).

**Почему множители, а не проценты.** Удар = `(урон оружия + вклад атрибутов) × (1 + бонусы урона)`.
Первая версия торговала «+10 п.п. к бонусам урона ↔ −8 % скорости», и оба числа СКЛАДЫВАЛИСЬ с бонусами
героя — разброс ДПС зависел от билда и базы: замер реальной цепочкой по всем 50 базам дал от 6.2 до
14.4 %, у 15 тяжёлых баз выше порога 8 % (собственный штраф скорости базы ломал нейтральность пары).
Вписать +10 % прямо в цифры оружия тоже нельзя: доля оружия в ударе — около трети, атрибуты размыли
бы форму, и тяжёлый клинок проигрывал бы лёгкому примерно на 9 %.

Поэтому у вещи **множитель удара** `Item.damageMult` — рядом с `reachMult` и `arcMult`, того же рода:
бой множит на него ВЕСЬ удар вместе с атрибутами (`playerCombat.ts`: реальный удар, раскладка для
панелей, оценка для ИИ и симуляции — три места). Скорость формы — **плоская часть скорости оружия**:
бой считает `(1 + flat) × (1 + increased)`, то есть множит её на все проценты скорости. Тогда

```
ДПС формы = (1 + 0.10·τ) × (1 − 0.08·τ):   тяжёлая ×1.012 · эталон ×1.000 · лёгкая ×0.972
```

**Разброс 4.1 % у любой базы и любого героя** — конверт больше не нужен. Сторож — сквозной тест:
отношение ДПС тяжёлой и лёгкой формы одно и то же у героя 1, 40 и 80 уровня.

⭐ **Статусы едут на этой оси сами, и это ответ на просьбу «шанс эффекта с противовесом».**
Статусы катаются ЗА УДАР, значит темп ими уже торгует: замер ступеньки 1.00 → 1.05 удара/с
даёт **+62 % стаков раны и +41 % кровотечения при НЕИЗМЕННОМ ДПС**. Подпись так и пишется:

> **Лёгкий клинок** — взмахов больше: статусы, вампиризм и проки срабатывают чаще. Каждый удар мельче.
> **Тяжёлый клинок** — удар крупнее: крит и кровотечение считаются от его размера. Взмахов меньше.

⚠ **Второй оси у этой детали нет.** Отдельная ось «заточка» (статус против крита и блока)
рассматривалась и отвергнута: 5 × 5 = 25 ячеек вместо 5, три числа в тултипе вместо одного,
и главное — замер показал, что при дуал-вилде два «зазубренных» клинка складывают вклады и
дают +5.8 % вместо обещанных +3.4 %. Замок «одна ось ДПС» ломается не чужой деталью, а второй
осью на той же самой.

⚠ **Дуал-вилд: удар — у каждой руки свой, скорость — общая.** Множитель удара живёт на вещи и
умножает только удары ЭТОЙ рукой, поэтому не складывается. А плоская скорость попадает в общий
стат-блок обеих рук (`combatStatsOf`): два лёгких клинка дают скорость ×1.16, а не ×1.08. Значит
инвариант объявляется **на руку**, а дуал мерится отдельным прогоном. Форма слотов и блок считаются
по ГЛАВНОЙ руке — иначе четыре слота становятся восемью.

## 5. Гнездо 2 — держак: дальше по одному ↔ шире по многим

### 5.1 Ближний бой: площадь-нейтральная пара

`meleeSwing` бьёт **всех** монстров в секторе. Площадь сектора = `дуга × дальность²`. Значит
честная пара обязана держать произведение постоянным:

| Точка оси | Дальность | Дуга | Площадь | Кому |
|---|---|---|---|---|
| **+1** длинный | **×1.12** | **×0.797** | 1.000 | достать первым, бить из второй линии, одиночные цели |
| **0** обычный | — | — | 1.000 | дефолт |
| **−1** короткий | **×0.89** | **×1.26** | 0.998 | толпы: задеть троих одним взмахом |

⚠ **Прежние числа были дырой.** «+20 % дальности ↔ −20 % дуги» даёт `0.8 × 1.2² = 1.152`
против `1.25 × 0.85² = 0.903` у короткой — то есть длинная сметала на **27.6 % больше
площади**. При пачках по 3–6 монстров это прямой ДПС, почти втрое сильнее всей оси лезвия.

⚠ **Один и тот же рычаг стоит разного на разных классах.** У топоров `arcMult` уже 1.5–2.0
(полудуга до 1.6 рад ≈ 183° полного сектора) — там прибавка дуги почти ничего не даёт, а у
мечей даёт много. Поэтому итоговая полудуга клампится, а сторож мерит **число задетых целей
в симе**, а не формулу.

### 5.2 Стрелковое и магическое: честного рычага сегодня нет

Замер: снаряд живёт `PLAYER_PROJ_SPEED 440 × PROJ_TTL 2.5 = 1100 px` (магический болт 1150)
при зрении монстра 240–320 px. Стрелять дальше, чем видишь, можно уже вчетверо — **+20 %
дальности не покупают ничего**. Поля «разброс» у оружия нет вовсе. А `projectileHit`
сравнивает расстояние ТОЛЬКО с `proj.radius` (16 px) и радиус цели игнорирует, то есть
радиус — это ВЕСЬ коридор попадания, и «радиус ×1.25» было бы второй осью ДПС под видом
геометрии.

Рабочий кандидат уже лежит в коде: **`proj.pierce`** — снаряд летит сквозь цель, `hitIds`
не даёт бить дважды. Сегодня это поле СКИЛЛА. Чтобы оно стало честной осью держака, нужен
один добавок: **затухание урона по числу пройденных целей**.

| Точка оси | Что делает | Цена |
|---|---|---|
| **+1** одна цель | снаряд встаёт в первой цели, урон полный | по толпе бьёт одного |
| **−1** пробойный | летит сквозь, **урон × 0.65 за каждую пройденную цель** | одиночной цели — как обычный |

Это точный аналог дуги: больше целей — меньше на каждую, суммарная «площадь» постоянна.
Стоит примерно десяти строк в `session.ts` (`damage × 0.65 ** hitIds.length`), и до этой
правки гнездо 2 у 20 баз из 50 честно объявляется **косметическим** — меш и имя, без обещаний.

## 6. Гнездо 3 — обвязка: форма ёмкости аффиксов

Ковка выдаёт **обычную вещь** (0 аффиксов) с записанной на ней ЁМКОСТЬЮ — парой «сколько
префиксов, сколько суффиксов». Редкость поднимается отдельным глаголом (§6.3).

### 6.1 Потолок выводится из дропа, а не калибруется

Найденный редкий: 3–5 аффиксов, максимум 3 префикса и 3 суффикса (`rarities.json`). Прогон
самого `rollAffixes` даёт частоты форм у найденных редких:

| Форма | Встречается у редких | Множитель цены M = 1/частота |
|---|---|---|
| 1+1 | 91.7 % | 1.09 |
| 2+1 | 68.8 % | 1.45 |
| **2+2** | **45.8 %** | **2.18** |
| 3+0 | 31.2 % | 3.21 |
| **3+1** | **27.1 %** | **3.69** |
| **3+2** | **16.7 %** | **5.99** |
| 3+3 | **0 %** | — (невозможна) |

⭐ **Отсюда всё и выводится.** Потолок ковки — (3,2) и (2,3), потому что 3+3 дроп не даёт
вовсе. Цена формы — во сколько раз реже дроп даёт такую же или лучшую. Перекошенная форма
дороже сбалансированной при том же числе слотов, и «заплатил больше» перестаёт быть просто
«купил ещё слот».

### 6.2 Потолок ёмкости растёт со ступенью вещи

| Ступень вещи | Потолок Σ | Доступные формы |
|---|---|---|
| t0–t1 | 2 | 2+0 · 1+1 · 0+2 |
| t2 | 3 | 3+0 · 2+1 · 1+2 · 0+3 |
| t3–t4 | 4 | 3+1 · **2+2** · 1+3 |
| t5–t6 | 5 | **3+2** · 2+3 |

⚠ На полной ёмкости форм всего ДВЕ: «равная» схлопывается, потому что 3+3 невозможна.
Обвязка интереснее всего на Σ=3 и Σ=4. Это ограничение данных, а не схемы, и в интерфейсе
ковки «равную» на Σ=5 рисовать нельзя.

**Что игрок реально получает** (замер по весам аффиксов, полезность «билду», 200 000 бросков):

| Что | Полезных аффиксов | Против среднего дропа |
|---|---|---|
| Средний найденный редкий | **2.22** | — |
| Скованная 2+2 | **2.21** | −0.5 % |
| Скованная 3+1 | 2.24 | +1 % |
| Скованная 3+2 | **2.78** | **+25 %**, цена ×6 |

⚠ 3+1 почти не отличается от 2+2, потому что `cruel`, `merciless` и `warlords` лежат в одной
группе `ed` — второй множитель урона взять негде. Это баг данных, и он в списке долгов (§20).

### 6.3 Новый глагол «зачаровать»

Глаголов кузницы сегодня четыре (`forgeUpgrade`, `forgeReroll`, `forgeSalvage`, `forgeRepair`),
и глагола «поднять редкость» среди них нет. Вводим **один**: `forgeEnchant` с целевой
редкостью сразу.

* Лестницу из двух покупок (normal→magic, потом magic→rare) не делаем: она даёт два действия
  и ноль решений — никто не остановится на magic, имея золото на rare.
* Движок не меняется ни на строку: `rollAffixes` (`itemgen.ts:479`) **уже** принимает `slots`
  отдельным аргументом. При `{ minAffixes = maxAffixes = P+S, maxPrefix = P, maxSuffix = S }`
  цикл физически не может лечь другим сплитом.
* Глагол сезона 2 («улучшение аффиксов») он не съедает: зачарование катает всё заново,
  улучшение двигает ЗНАЧЕНИЕ внутри уже сохранённого аффикса.
* ⚠ **В том же коммите обязаны поехать две правки.** `forgeReroll` берёт `minAffixes`/
  `maxAffixes` прямо из `rarities` и снесёт купленную форму первым же нажатием (шанс вернуть
  ровно 3+2 — 16.7 %). `forgeGold` читает ТЕКУЩУЮ редкость и даст скидку ×2.4 ровно на самом
  дорогом действии.

## 7. Гнездо 4 — оголовье: укус ↔ упор

Здесь живут обе просьбы владельца — «шанс наложения эффекта с противовесом» и «обыграть
блок». Ось одна: **чаще вешаешь статус ↔ крепче держишь удар**.

### 7.1 Укус — рычаг по грани, а не одно число

Грань принадлежит ОРУЖИЮ (кинжал колет, меч режет, топор рубит, булава дробит) — на ней висят
анимация, звук и ветки пассивок, деталь её не меняет. Оголовье двигает ШАНС или СИЛУ статуса
этой грани. Магнитуда **пер-грань**, потому что одна общая ручка стоит разного:

| Грань / стихия | Статус | База | Стаков при 1 уд/с | Рычаг «укуса» | Чем это является |
|---|---|---|---|---|---|
| Режущий (мечи, глефа) | кровотечение | 0.25 | 1.51 из 5 | `bleedChancePct` **+0.25** | ДПС во времени |
| Рубящий (топоры, алебарды) | увечье | 0.50 | **3.65 из 5** | `sunderPowerPct` **+0.15** | +получаемый урон |
| Дробящий (булавы) | ошеломление | 0.60 | **6.25 из 8** | `dazePowerPct` **≤ +0.06** | контроль + броня |
| Колющий (кинжалы, копья) | рана | 0.20 | 0.77 из 4 | `woundChancePct` **+0.50** | чистая оборона, ДПС не двигает |
| Огонь | поджиг | 0.10 | 0.30 из 3 | `burnChancePct` **+0.50** | ДПС во времени |
| Яд | отравление | 0.10 | 0.40 из 5 | `poisonChancePct` **+0.60** | ДПС во времени |
| Молния | шок | 0.12 | 0.36 из 2 | `shockChancePct` **+0.60** | +получаемый урон |
| Холод | заморозка | 0.15 | 0.30 из 1 | `freezeChancePct` **+0.50** | контроль |

⚠ **Магнитуды посчитаны по РЕАЛЬНОЙ механике стаков, и это важно.** `addDebuffStack` обновляет
ОБЩИЙ таймер всего стака, а не таймер на стак — поэтому стаки копятся почти до капа и
сбрасываются целиком только при паузе длиннее `durationMs`. Наивная модель «шанс × темп ×
длительность» даёт увечью 2.0 стака вместо реальных 3.65, ошеломлению 2.4 вместо 6.25 — и все
магнитуды, посчитанные по ней, завышены в 1.5–2 раза.

⚠ **У рубящего рычаг РАЗВОРАЧИВАЕТСЯ с темпом:** шанс ×1.5 стоит +4.8 % ДПС при 1.0 уд/с и
всего +1.5 % при 1.4 уд/с, потому что стаки уже у потолка. Значит гнёзда 1 и 4 взаимодействуют,
и сторож обязан мерить ДПС **с включёнными статусами** на реальном бою, а не по формуле.

⚠ **Статус у 20 баз из 50 не накладывается вовсе:** у луков, арбалетов, жезлов и посохов нет
поля `physSub`. Магическим грань заменяет стихия (`damageType`), а стрелковым — нечем; у них
«укус» работает только если оружие несёт стихию с аффикса.

### 7.2 Упор — блок, и он требует правки данных

| Точка оси | Ближний бой | Лук | Арбалет | Магическое |
|---|---|---|---|---|
| **+1** упор | `blockChance` **+0.02** | `interruptResist` **+0.12** | блок ложа **+0.02** | `blockChance` **+0.02** |
| **−1** укус | блок **−0.02**, рычаг статуса на полную | стойкость 0 | блок −0.02 | блок −0.02 |

Цена стороны: **+2.7…3.3 % эффективного HP** против **∓1…2 п.п. ДПС**. Настоящая, но не
решающая развилка — ровно то, что нужно.

⚠⚠ **«У оружия есть свой небольшой шанс блока» — сегодня неверно для 42 баз из 50.** Замер:
блок стоит ровно на восьми — short-sword .08, long-sword .08, greatsword .05, short-spear .05,
mace .04, dagger .03 и с §26 gladius .02, claymore .02. У ВСЕХ топоров, алебард, луков, арбалетов,
жезлов и посохов блока нет вовсе. Пока это так, «упор» у 42 баз платит нулём: `blockChance`
клампится снизу нулём (`stats.ts:150`), то есть отрицательный мод съедается молча и деталь
получает выгоду бесплатно.

✅ **Архаичный и двуручный меч: базовый блок 0 → 0.02** (§26, решение 6 — делегировано владельцем).
Без него рычаг баланса у двух вилок меча из пяти был односторонним: сторона укуса упиралась в ноль и
доставалась даром. 0.02 — ровно ход `headBlock`, поэтому точка баланса двигает блок в 0…0.04 и в минус не
уходит. Лестница «0.08 всем мечам» для этих двух отвергнута: при блоке, гасящем удар целиком, это
+8.7 % eHP всем архаичным и двуручным сразу (1 / (1 − 0.08)) против +2.0 % у 0.02.

**Предлагаемая лестница блока по классу** — но это НЕ правка json на глаз:

| Класс | Сейчас | Предлагается | Класс | Сейчас | Предлагается |
|---|---|---|---|---|---|
| `sword` | .08/.08/.05 и .02 у архаичного с двуручным (§26) | **.08** | `mace` | .04 у 1 из 5 | **.04** |
| `spear` | .05 у 1 из 5 | **.06** | `axe` | ноль у всех | **.03** |
| `halberd` | ноль у всех | **.05** | `crossbow` | ноль у всех | **.03** |
| `staff` | ноль у всех | **.05** | `wand` | ноль у всех | **.03** |
| `dagger` | .03 у 1 из 5 | **.04** | `bow` | ноль | **0 — лук не парирует** |

⚠ Блок гасит урон **ПОЛНОСТЬЮ** (`resolveAttack`, кап 0.75). Долить 0.03 бойцу с двуручным
топором без щита = **+3.1 % eHP всем сразу**, а со щитом 0.30 → 0.33 это +4.5 %. Это глобальный
бафф выживаемости, и он требует прогона сима, а не одной правки конфига. До него гнездо 4
работает только на восьми базах.

⚠ `interruptResist` не выдаёт сегодня **ни один из 38 аффиксов** — стат приходит только с
пассивок. Чтобы «упор» лука не создавал стата, которого нет в дропе, в `affixes.json` нужен
суффикс: 2 ступени, 0.04–0.08 при ilvl 1 и 0.08–0.15 при ilvl 16, `appliesTo: ["weapon"]`.

## 8. Ловкость или сила — решает ТИП, а не прочие детали

Вес оружия задаёт, от какого атрибута оно кормится. Лестница ровная, от чистой ловкости
к чистой силе, плюс две магические ветки:

| Вес | Ловкость | Сила | Интеллект | Масса | Примеры |
|---|---|---|---|---|---|
| **Сверхлёгкое** | 1.0 | — | — | 3 | кинжалы, короткий лук |
| Лёгкое | 0.65 | 0.35 | — | 6 | короткий меч, гладиус, ручной топор |
| Среднее | 0.5 | 0.5 | — | 12 | длинный меч, боевая секира, копьё |
| Массивное | 0.35 | 0.65 | — | 18 | двуручный меч, алебарда, осадный арбалет |
| **Тяжёлое** | — | 1.0 | — | 25 | боевой топор, молот, длинное копьё |
| Мистическое | 0.4 | — | 0.6 | 6 | жезлы |
| Волшебное | — | — | 1.0 | 8 | посохи |

Вклад в удар при чистом билде (150 основного против 30 второго) и при гибриде (90/90):

| Вес | Чистая сила | Чистая ловкость | Гибрид |
|---|---|---|---|
| Сверхлёгкое | 15 | **75** | 45 |
| Лёгкое | 36 | 54 | 45 |
| Среднее | 45 | 45 | 45 |
| Массивное | 54 | 36 | 45 |
| Тяжёлое | **75** | 15 | 45 |

⭐ **Эту ось нельзя СЛОЖИТЬ из деталей, и это сознательно.** Двигай вес любая деталь — чистый
билд всегда сдвигал бы оружие к своему атрибуту и получал +30…40 % вклада даром. Вес приходит
только пакетом с типом: хочешь меч под ловкача — берёшь короткий или римский клинок, и это
выбор ключевой детали, ровно как раньше выбор чертежа. Выбор при этом честный: гибрид получает
ровно 45 на любом весе, чистый билд — свой край лестницы.

⚠ **Масса остаётся СЛЕДСТВИЕМ модели, а не торгуемой колонкой.** Она лежит в предмете строковым
идентификатором веса (`WeaponWeight = string`), записать в неё «×1.6» физически нечем; в движке
она используется для расталкивания в толпе и для нокдауна, потолок которого — +2.37 % урона.
В подписи гнёзд нокдаун не обещаем вовсе.

## 9. Форма детали: вариантов сколько угодно

⭐ **Вариант — это ТОЧКА на оси своего гнезда плюс имя и меш.** Числа выводятся из поля
`axis` (−1…+1) умножением на шаг гнезда; руками в вариант не пишется ни одно число. Поэтому
вариантов может быть сколько угодно, а балансная поверхность остаётся одной таблицей на
четыре строки. Контент растёт именами и силуэтами, баланс — нет.

**Каталог клинков рыцарского меча** — ключевое гнездо, база «Длинный меч» (числа общие для всех
классов, окно — из каких ступеней материала форма куётся):

| Клинок | τ | Урон | Скорость | Окно | Редкость | Откуда |
|---|---|---|---|---|---|---|
| Широкий с долом, X | +1.0 | +10 п.п. | −8 % | 1–3 | обычный | эпоха викингов и позже |
| Фальшион | +0.6 | +6 п.п. | −5 % | 2–5 | нечастый | однолезвийный, Элмсли 2015 |
| Широкий рубящий, XIII | +0.6 | +6 п.п. | −5 % | 2–4 | обычный | XIII–XIV вв. |
| Ромбический, XVIII | +0.3 | +3 п.п. | −2 % | 3–5 | нечастый | XV в. |
| Классический, XII | 0 | — | — | 1–5 | обычный | эталон |
| Колюще-рубящий, XVI | −0.3 | −3 п.п. | +2 % | 2–4 | обычный | XIV в. |
| Узкий, XI | −0.6 | −6 п.п. | +5 % | 1–3 | обычный | XII в. |
| Саблевидный | −0.8 | −8 п.п. | +6 % | 1–4 | редкий | ранние сабли, Кирпичников 1966 |

| Узкий с рикассо, XIX | −1.0 | −10 п.п. | +8 % | 3–5 | редкий | поздний |

⚠ **Колонка τ этой таблицы — история.** У всех 36 мечевых клинков ось теперь выводится из длины модели
внутри вилки (§26), и у гранёного XV и узкого XIX она сменила знак: они не лёгкие, а длинные для своей вилки.

Ранние формы куются из простого железа, поздние — из хорошей стали, но на ЛЮБОЙ ступени у базы
есть и тяжёлая, и лёгкая форма (сторож): ступень материала не выбирает стиль боя.

Тот же приём на других классах — меняются имя, силуэт, окно и грань, не числа:

| Класс | Ключевое гнездо | Формы (примеры) |
|---|---|---|
| Топор | Полотно | клиновидное · узкое · с выемкой · висячая борода · бородовидное · короткая бородка · широкое · датское · полулунное |
| Булава | Било | шаровая · кубовидная · ребристая · шестопёр · клевец · двенадцатишипная · дубина · люцернский молот · ослоп · гёдендаг |
| Копьё | Перо | ланцетовидное · ромбическое · яйцевидное · лавролистное · рогатинное · шиловидное · четырёхгранное · двушипное · крылатое · трезубое |
| Лук | Рога × тугость | сигмовидные · простые · длинные прямые · рефлексные · длинные рефлексные — по три тугости |
| Посох | Навершие (не ключ) | держава · двузмий · тау · крюк · рогулька · череп |

**Сколько вариантов и чьи это пулы.** Ключевое гнездо класс-специфично (это и есть тип), у
остальных — свои словари по классу: гарды кинжала — не гарды меча. В данных **311 вариантов**
(ключевых около 180) и 132 правила имён. Художественный объём реален, поэтому §18 фазирует:
варианты одной формы разных телосложений делят меш, остальное — параметрический визуал с тинтом.

## 10. Материал детали: свой у каждой, в окне формы

У детали две независимые оси: **форма** (характер) и **материал** (из чего). Материал выбирается
У КАЖДОЙ детали отдельно, но не любой: у формы есть **окно материалов** — из каких ступеней её
делали. Широкое лезвие X — эпоха кричного железа (ступени 1–3), гранёный XV — время позднего доспеха
(3–5), пламенеющий клинок ковал только хороший мастер из хорошей стали (3–5), простая рукоять
делается из чего угодно (1–5). Ступень вещи потом выводится из материалов всех четырёх (§11).

### 10.1 Окно формы вместо полосы вещи

Прежняя «полоса одна на вещь» заменена двумя правилами:

1. **окно на форме** — поля `stepMin…stepMax` варианта (правятся в редакторе, «Ковка → Детали»);
2. **ступень вещи** — средний уровень материала по массе (§11).

| Вещь целиком из ступени | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| Ступень вещи | t0 | t2 | t3 | t5 | t6 |

Промежуточные ступени дают смешанные материалы:

| Клинок | Рукоять, гарда, навершие | Ступень | Что это значит |
|---|---|---|---|
| кричное (2) | болотное / сыромять / чёрное железо (1) | **t1** | дешёвый клинок получше — вещь уже не убогая |
| уклад (3) | кричное, дублёная кожа, бронза (2) | **t2** | |
| дамаск (4) | уклад, варёная кожа, воронёная сталь (3) | **t4** | |
| булат (5) | всё на ступень ниже (4) | **t5** | |
| булат (5) | две детали 5, одна 4 | **t6** | мифику нужен булатный клинок |
| булат (5) | всё болотное (1) | **t2** | дорогой клинок не вытягивает дешёвую вещь |
| болотное (1) | всё лучшее (5) | **t4** | и наоборот |

Сторожа окон: **каждая база куётся в каждой своей ступени** (от `minTier` до `maxTier`), и **на
любой ступени материала у базы есть и тяжёлая, и лёгкая ключевая форма**.

⭐ **Фэнтези на доске ноль ступеней.** История закрывает t0…t6 целиком, включая верх: булат,
золочёный прибор, шёлк, пружинная сталь. «Небесное железо», «Эфирное стекло», «Рог Разлома» и
«Окаменелое древко» с лестниц СНЯТЫ — они уходят в уникумы и дроп с боссов, где им и место.
Один материал не может стоять в двух семьях сразу (формула выдаст два разных id для одной вещи),
а именно это и случилось бы с небесным железом.

### 10.2 Чёрный металл `iron` — кромка и масса

Каркас владельца проверен по источникам и исправлен в одном месте: «низкокачественное» и
«кричное» железо — это одно и то же (кричное и есть низкокачественное). Настоящая разница идёт
по РУДЕ, а между кричным железом и дамаском зияла целая эпоха — туда встала недостающая
ступень «уклад», момент, когда железо впервые начало брать закалку.

| Материал | id | Где живёт | Что это исторически | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Болотное железо** | `iron-1` | t0–t2 | Сыродутный горн, болотная и дерновая руда. Железо в нём не плавится — выходит крица, пористый ком со шлаком. Болотная руда богата фосфором | Руда валяется под ногами | Фосфор даёт хладноломкость — трескается при холодной ковке. Шлаковые включения работают как надрезы. Углерода нет, закалку не держит |
| **Кричное железо** | `iron-2` | t2–t3 | Тот же горн, но нормальная руда и многократная проковка в сварочном жару, выжимающая шлак. | **Булат** | `iron-5` | t5–t6 | Тигельная сталь: индийский вутц, дендритный узор от ликвации. На Ближнем Востоке его клинки и звались «дамасскими». ### 10.3 Древесина `wood` — древко, топорище, ложе, ствол

Самая широкая семья: восемь классов из десяти.

| Материал | id | Где живёт | Что это | Чем лучше | Чем платит |

### 10.4 Плечи и дуги `stave` — пружина, а не кромка

⚠ Посылка «стальных луков история не знает, сталь — ответ только для арбалета» оказалась
неверна и снята проверкой. Поэтому фэнтезийная верхушка плечам не понадобилась, а асимметрия
между луком и арбалетом исчезла сама.

### 10.5 Прибор `trim` — оснастка и противовес

Исторически гарда, навершие, обоймица, ланцеты, подток и замок арбалета — это один «прибор»:
один мастер, один металл, один гарнитур. Поэтому одна семья кормит **два гнезда из четырёх
у девяти классов из десяти** — это самый расходуемый материал в игре, и цену ковки надо
раскладывать по семьям неравномерно (§13).

| Материал | id | Где живёт | Что это | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Чёрное железо** | `trim-1` | t0–t2 | Кованое железо из-под молота, окалина не снята. Вопреки фэнтези-привычке к бронзовым эфесам, железо и было нормой для прибора европейского меча | Есть везде; принимает прямой удар клинка лучше цветного металла | Ржавеет от пота и крови — единственный материал линии, требующий ухода просто чтобы остаться собой |
| **Литая бронза** | `trim-2` | t2–t3 | Прибор, отлитый одним куском: бронза берёт тончайший оттиск формы | Не ржавеет; сложная форма за одну плавку — кольца, дужки, ажур, которые из железа пришлось бы ковать по частям | Мягкая: гарда мнётся от прямого удара, навершие разбивается при расклёпке хвостовика. И тяжелее железа при той же форме |
| **Воронёная сталь** | `trim-3` | t3–t4 | Стальной прибор под управляемым слоем чёрного оксида. Воронили не только доспех — контраст полированного и синего был штатным приёмом отделки эфесов | Сталь держит удар там, где бронза мнётся; воронение снимает ржавчину в массе вещи, а не краской поверх | Плёнка не вечна, а восстанавливать её — снова греть прибор, и перегрев отпускает закалку. Красивый прибор стареет и чинится хуже, чем портится |
| **Серебряный прибор** | `trim-4` | t4–t5 | Серебро с настоящей репутацией: им лечили раны, в фольклоре — металл против нежити | Не ржавеет вовсе, тянется в филигрань — и это портативная цена: деньги, которые носят на рукояти | Мягче стали; дорог |
| **Золочёный прибор** | `trim-5` | t5–t6 | Огневое (ртутное) золочение — господствующий способ от античности до XIX в. | Вечное покрытие, вплавленное в металл, а не нанесённое на него | Ртутные пары. Ремесленное предание говорит, что золотильщики редко доживали до сорока; проверяемые вехи рядом — запрет ртутного золочения во Франции в 1830 г. и переход на гальванику с 1840-х |

### 10.6 Фокус `focus` — сигнатурное гнездо магии

Реальной «магической металлургии» нет, поэтому лестница опирается на материалы, которым
исторически приписывали силу, и на реальные ремёсла. Правдоподобие здесь держится не на
физике, а на том, что люди действительно так считали.

| Материал | id | Где живёт | Что это | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Стеклянная паста** | `focus-1` | t0–t2 | Римляне лили цветные пасты, подделывая изумруд и лазурит; Плиний писал, что нет обмана прибыльнее подделки самоцветов | Льётся в форму, а не режется из камня — дёшев и доступен учеником и в поле | Пузыри и муть внутри, трескается от нагрева, заряд держит слабо. Подделка и есть подделка |
| **Гагат** | `focus-2` | t2–t3 | Gagates по реке Гагас в Ликии. Беда Достопочтенный о британском гагате: «чёрный и искрящийся, горит в огне и нагретый отгоняет змей». **Восемь семей на игру, не больше трёх на любую вещь.** Пять оружейных (`iron`, `wood`, `stave`,
`trim`, `focus`) и три бронных, две из которых получают оружейный сток: `hide` даёт хват меча
и кинжала, `cloth` — тетиву. `plate` остаётся чисто бронной, иначе столкнулась бы с `iron`
в одном гнезде.

Семья — у гнезда, но форма может её сменить (поле `family` варианта): било дубины деревянное.
У ствола жезла и древка посоха порода — это ФОРМА (и ключ типа), поэтому ступень дерева там
читается обработкой, а не сортом: сырой → колотый → в олифе → морёный → клеёный (`stepNames`
гнезда) — иначе вышел бы «тисовый ствол из сырой сосны».

### 10.8 Что уехало в ФОРМЫ, а не в ступени

Половина красивых материалов — это не качество, а характер, и им место на оси формы:

| Было предложено ступенью | Стало |
|---|---|
| Витая латунная и серебряная проволока на рукояти | **форма** оплётки поверх кожи — исторически проволоку мотали ПО коже, а не вместо неё |
| Лещина, тёрн, кладбищенский тис, эбен | **формы** ствола посоха и жезла — и КЛЮЧ типа: порода задаёт стихию (§3.3) |
| Кожа ската (самэгава) | **форма** хвата (в конфиге пока стоит пятой ступенью `hide-5` — бронная кожа, где она и есть предел лестницы) |
| Насечка и таушировка | **форма** прибора — это отделка, а не ступень: проволока в канавках |
| Небесное железо, эфирное стекло, рог Разлома, окаменелое древко | **уникумы и дроп с боссов**, вне лестниц |

### 10.9 Разбор отдаёт то, из чего вещь сделана

⚠ **Сегодня в игре ступень выпавшего сырья задаёт ТОЛЬКО редкость вещи** (обычная → 1, магическая
→ 2, редкая → 3), а тир на разбор не влияет вовсе: мифический обычный топор даёт ровно то же, что
убогий обычный топор. Пяти ступеней из трёх редкостей не выжать — формула обязана смотреть на тир.

⭐ **Решение — ТОЖДЕСТВО по деталям.** У найденной вещи детали и их материалы выводятся из неё
самой (сид от `uid`), причём ступени подбираются так, чтобы из них ковалась РОВНО ступень вещи
(ровные сочетания вероятнее перекошенных), а ключевая форма — из пула её собственной базы. Разбор
отдаёт материал каждой детали её ступени:

| Деталь | Единиц | Надбавка |
|---|---|---|
| ударная часть | 3 | +1 у магической, +2 у редкой |
| держак | 2 | — |
| обвязка | 1 | — |
| оголовье | 1 | — |

Числа — `balance.craft.salvage`. Сторож: на всех 50 базах × 7 уровнях дропа тип найденной вещи
равен её базе, а ступень из её деталей — её ступени. Отсюда: разбор t4-меча отдаёт, например,
уклад клинка и кричное железо рукояти — ровно то, из чего такой меч и куётся; сырьё едет вместе с
игроком по лестнице, и низ её не умирает.

⚠ **У надетой на монстра вещи тира нет вовсе.** Берём тир по уровню монстра из той же лестницы
`item-tiers` (высший, у которого `minItemLevel ≤ уровня`), а редкость — у КОНКРЕТНОЙ надетой
вещи, как сейчас. Новых чисел в баланс не добавляется: обе шкалы уже лежат в конфиге.

**Правки для игры:**

| Где | Было | Стало |
|---|---|---|
| `schemas.ts` | `tier: z.number().int().min(1).max(3)` | `.max(5)` — ✅ сделано |
| `salvage.ts` | ступень сырья из редкости, `shiftTier(id, tier−1)` | звать `craftSalvageYield` ядра: материалы деталей их ступеней |
| `balance.json` | `salvage.rarityTier {normal:1,magic:2,rare:3,unique:0}` | `craft.salvage.units` + `rarityBonus` — ✅ в конфиге; игровой разбор ещё на старом |
| `salvage-rules.json` | 17 правил по старой анатомии | для оружия не нужны: состав даёт анатомия; остаются для брони |
| `monster-gear.json` | 22 записи ссылаются только на `iron-1`, `wood-1`, `cloth-1`, `hide-1`, `plate-1` | ⚠ пока туда не добавлены `stave`, `trim`, `focus`, трёх новых семей в игре не будет ВОВСЕ — ровно та грабля, что уже ловилась коммитом `2fd6d96` |
| `craft-materials.json` | 15 строк | ✅ 40 строк; ids не менялись. Ступени 4–5 и семьи `stave`/`trim`/`focus` выключены до врезки |

### 10.10 Легенды, которые нельзя писать никогда

Красивые, широко повторяемые и неверные. Одна такая строка в тултипе обесценит остальные сорок.

| Не писать | Как правильно |
|---|---|
| «Дамаск резал шёлк, падающий в воздухе» | молва, а не свойство материала |
| «Секрет булата утрачен навсегда» | **производство прервалось, а не тайна исчезла** — тигельную сталь с дендритным узором воспроизвели в 1990-х и воспроизводят сейчас |
| «Викинги закаляли клинки в крови» | нет |
| «Японский меч складывали тысячу раз» | нет |
| «Кольчугу пробивал любой бодкин» | почти все исследованные бодкины оказались незакалёнными |
| «Шёлковая тетива стоила вдвое дороже лука» | на источниках этого нет; корректно — «из-за дороговизны шёлка тетивы из него встречались редко» |

⚠ **Числа без источника из документа сняты сознательно.** Линии чёрного металла и прибора
пришли без единой ссылки, поэтому из них убраны вторые значащие цифры (твёрдость, проценты
фосфора, точное окно ковки, даты Аносова) — правдоподобие держится на МЕХАНИЗМЕ, а не на
цифре, которую нечем подтвердить. Если числа понадобятся — сперва ссылка, потом строка.

## 11. Ступень вещи: средний материал деталей по массе

```
Q     = (2·клинок + держак + обвязка + оголовье) / 5    ← ступени материалов деталей (1…5)
tier  = round(1.5 · (Q − 1))                           ← вещь целиком из ступени k: t0, t2, t3, t5, t6
режут: base.minTier ≤ tier ≤ base.maxTier              ← короткий меч не бывает выше t3
       tier ≤ потолок журнала                           ← t6 — ещё и ворота мификов (§12.4)
ilvl  = minItemLevel(tier)
```

Веса и масштаб — `balance.craft.tierFromParts`. Дальше всё едет по существующему руслу без единой
новой кривой: `statMult` масштабирует урон, `reqMult` — требования, кап `maxTotalRequirement`.

⭐ **Почему среднее по массе, а не минимум и не полоса.** Владелец: «тир сам определяется по общему
уровню частей». Веса совпадают с массой в цене (клинок 16 единиц, остальные по 8, §13), поэтому
один уровень ступени стоит одинаково в любом гнезде: сэкономить на рукояти и вложиться в клинок
законно, но скидки не даёт. Дыра «одна дорогая деталь + три дешёвые = мифик» закрыта весом:
булатный клинок при болотном прочем даёт t2, а мифик требует булатного клинка (Р6).

Окно ступень не спрашивает — показывает её и формулу. Вне пределов базы или журнала ковка
**отказывает с причиной** («короткий меч не бывает выше t3: возьми материалы попроще»), а не
срезает ступень молча: иначе игрок заплатил бы булатом за t3.

⚠ **`ilvl` берётся от ступени, а не от уровня героя.** Замер: `rollSpec` всегда берёт ЛУЧШУЮ
доступную ступень аффикса, а высшая по всем оружейным аффиксам — ilvl 24. Значит от t3 (ilvl 30)
и выше обе формулы дают одинаковые аффиксы, зато «по уровню героя» открывало бы станок: дешёвая
t0-рама на 90-м уровне получала бы топовые аффиксы и продавалась бы с прибылью.

⚠ **Скованную вещь не поднимает `forgeUpgrade`: её ступень — функция материалов.** Поднять её —
значит заменить деталь на деталь из лучшего материала (глагол «заменить деталь», §17.1). И
`retierItem` к скованной применять нельзя: он пересобирает `baseStats` ОТ БАЗЫ и молча сотрёт
запечённый вклад деталей, а поле `parts` переживёт, и вещь будет выглядеть правильной.

## 12. Открытие деталей: журнал кузнеца

**Чертежей как предметов нет.** Разобрал вещь у кузнеца — открылся и её тип (база), и четыре
детали, которые в ней стояли, а историческое имя её сборки легло в кодекс. Один глагол, один поток открытий, и каждый мусорный дроп
становится прогрессом.

### 12.1 Детали есть у каждого оружия, в том числе выпавшего

Чтобы «разобрал меч и открылись части, которые в нём были» не было фикцией, партсет должен
быть у любого оружия. Детали найденной вещи **выводятся детерминированно из неё самой**
(`baseId` + `tier` + сид от `uid`) — не катаются в момент разбора (иначе лотерея, нарушение Р3)
и не требуют миграции старых сейвов.

⚠ Вывод обязан быть СТАБИЛЬНЫМ: если дизайнер добавит вариант в гнездо и веса поменяются,
у всех мечей в сейвах молча переедут детали. Значит либо вывод идёт по замороженной версии
таблицы весов, либо `parts` записываются на предмет при первом же чтении.

### 12.2 Что помнит журнал

Журнал живёт **на аккаунте** (`AccountStash.forgeJournal?`, рядом с `materials?` и по той же
причине) — иначе каждый новый герой перефармливает каталог заново.

| Ось журнала | Что хранит | Как открывается |
|---|---|---|
| **Типы (базы)** | множество открытых баз | первым разбором вещи этой базы |
| **Варианты** | множество открытых форм | первым же разбором вещи, где вариант стоял; ключевую форму можно ковать только при открытом типе |
| **Кодекс** | исторические имена: «видел» и «сковал» | «видел» — разбор вещи, чьи детали дают имя; «сковал» — ковка. Чисел кодекс не даёт — это коллекция и причина вернуться |
| **Потолок ступени** | одно число: высший тир, который игрок когда-либо разбирал | первым разбором вещи этого тира |
| **Счётчик мификов** | сколько вещей `origin ∈ {drop, chest, boss}` тира t6 разобрано | ворота t6 |

⚠ Счётчик по паре «вариант × ступень» рассматривался и отвергнут: он мёртв арифметически —
конкретный t6-вариант конкретного класса требовал бы десятков тысяч убийств.

### 12.3 Сколько это в убийствах

Замер на текущем темпе (443 убийства/ч, 53.2 вещи/ч):

| Редкость варианта | Вес в пуле | Ожидание | В часах | 95-й перцентиль |
|---|---|---|---|---|
| Обычный | 10 | 1 111 убийств | **2.5 ч** | 7.4 ч |
| Нечастый | 4 | 2 778 убийств | 6.3 ч | 18.5 ч |
| Редкий | 1 | 5 556 убийств | 12.5 ч | **36.4 ч** |

⭐ **Хвост распределения делает каталог издевательством, поэтому жалость — часть конструкции,
а не украшение.** Правило: **8 разборов оружия своего класса дают «эскиз»**, открывающий любой
неоткрытый вариант этого класса на выбор игрока — кроме ключевой формы НЕОТКРЫТОГО типа: ключ несёт
тип, и эскиз стал бы чертежом в обход разбора. 2 667 убийств ≈ 6 ч — это потолок ожидания
вместо 36-часового хвоста.

⚠ **Полевой разбор** даёт 30 % сырья, но журналу — ПОЛНЫЙ зачёт: знание не делится пополам,
иначе каталог превращается в обязательную логистику «таскай всё в город». Открытие при этом
остаётся у кузнеца (решение владельца), а полевой разбор обязан **предупреждать**: «в этой
вещи неизвестная деталь». Без предупреждения он становится тихой ловушкой — игрок сжигает
единственный носитель штучной детали ради трети сырья и не узнаёт об этом никогда.

### 12.4 Ворота t6

Ступень t6 открывается после **5 разборов мифических вещей** (счётчик журнала, `balance.craft.journal.mythicSalvages`).

⚠⚠ **И это требование сегодня НЕ выполнимо, потому что магазин — бесконечный кран.**
`regenShop` зовётся на КАЖДЫЙ вход в город и катает 15 оружий; `generateItem` получает
`itemLevel: level + 1` и **не получает `tierLevel`**, поэтому `pickTierClamped` берёт высшую
доступную ступень ДЕТЕРМИНИРОВАННО — тогда как дроп передаёт `rollTierLevel`, бросок в окне
со смещением вниз. На 80-м уровне вся витрина — t6. При этом `shopItemValue` тира не видит
вовсе: `(15 + ilvl × 4 + аффиксы × 12) × priceMult`, то есть обычный t6 ≈ **339 золота ≈ 8
убийств**. Двадцать мификов покупаются за 163 убийства вместо 22 часов фарма.

Лечится двумя правками, обе полезны сами по себе: передать `tierLevel` в `regenShop` (одна
строка) и научить `shopItemValue` видеть тир. Плюс счётчик считает только вещи с полем
`origin ∈ {drop, chest, boss}` — новое поле, ставится в `generateItem`.

## 13. Цена

Две кассы, и они не пересекаются: **сырьё платится за ковку, золото — за зачарование.**

⭐ **Каждая деталь платит СВОИМ материалом, единиц — по её МАССЕ:** клинок 16, держак, обвязка и
оголовье по 8 (у лука тетива — волокном, концы — плечами), всё ×M формы ёмкости из §6.1. Ни
«дешёвой» и «дорогой» ступени вещи больше нет: ступеней столько, сколько деталей, и выбирает их
игрок. Низ лестницы не умирает сам: держак, обвязку и оголовье выгодно ставить на ступень ниже
клинка, и на это уходит ровно то сырьё, что падает на предыдущем тире.

| Действие | Сырьё | Золото |
|---|---|---|
| **Ковка** (4 детали) | клинок **16** · держак **8** · обвязка **8** · оголовье **8** — каждая своим материалом, ×M | `300 × reqMult ступени`, плоско |
| **Зачаровать** до редкого | — | `100 × reqMult × priceMult × M` |
| Замена одной детали | единицы этой детали её новым материалом | `100 × reqMult` |
| **Переплавить** | 60 % каждого материала (с округлением вниз) | — |

Числа — `balance.craft.cost` и `balance.craft.melt`.

**Цены продажи сырья** по пяти ступеням: **1 · 4 · 12 · 36 · 108**. Множитель ×3 не на глаз:
замер прихода за 100 убийств (126 / 21 / 8 по нынешним трём ступеням) при ценах 1/4/12 даёт
126 / 84 / 96 золота — поток от продажи почти ровный, и ×3 его ровным оставляет. Шестой
ступени нет намеренно: 330× вместо 108× превратило бы один стек верхнего сырья в состояние
и сделало бы продажу сырья главным источником золота — ровно против цели «золото остаётся
дефицитным всю игру».

⚠ Перемножать все множители подряд нельзя: вариант «30/10/4 × ёмкость × 1.6 двуручному ×
полосу тира» давал бы на t6 **1 728 ржавого железа и 230 калёной стали** при приходе 8 калёной
за 100 убийств — 2 900 убийств только на сырьё.

**Сторож против прачечной золота:** вещь целиком из ступени 4 стоит 40 × 36 = **1 440** в золотом
эквиваленте (при M = 1), переплавка возвращает 21 единицу — **756**. Денег не печатается, и тест
проверяет это на каждой ступени 1…5.

**Якорь:** `forgeUpgrade` до t6 стоит 2 000 золота. Ковка t6 верхней формы: 3 000 за саму
ковку плюс ≈ 14 400 за зачарование до редкого — около **17 400**, то есть порядка 200 убийств
на 80-м уровне, и сверху ≈ 36 единиц булата и золочёного прибора. «Дорого очень» выполнено.

⚠ **Цену придётся перекалибровать после запуска экономики открытия.** Нынешние числа
откалиброваны на текущий приход (126 / 21 / 8 единиц трёх ступеней за 100 убийств), а
требование «разбирай, чтобы открывать детали» этот поток изменит.

### 13.1 Вилка базы и доводка: у ковки появился смысл «сделать лучше»

**Беда, которую это лечит.** До вилки у меча на каждой ступени был ОДИН урон, и скованный меч
ровно равнялся найденному — ковке нечего было предложить, кроме формы и аффиксов. В D2 каждая
база катала урон в вилке («мин 10–14, макс 30–38»), и две одинаковые на вид вещи были разными.

**Как катается** (`itemgen.ts`, `balance.loot.baseRoll`):

| Стата | Вилка | Как |
|---|---|---|
| мин. урон оружия | ×0.85 … ×1.15 | своя доля броска |
| макс. урон оружия | ×0.85 … ×1.15 | своя доля, отдельно от мина (как в D2); макс не бывает ниже мина |
| броня | ×0.80 … ×1.20 | шире: доля брони в выживаемости меньше, чем доля оружия в ДПС |

Середина вилки — прежнее число ступени. Поэтому вещь без броска (старый сейв, стартовый комплект)
не изменилась ни на единицу, и никакой миграции не нужно.

⭐ **На вещи лежит ДОЛЯ броска `q ∈ [0, 1]`, а не число** (`Item.baseRoll`). Числа при этом лежат в
`baseStats` готовыми — бой их не пересчитывает. Доля нужна кузнице: подъём ступени пересчитывает
статы от базы с ТОЙ ЖЕ долей, и удачный меч остаётся удачным на новой ступени. Так в Last Epoch
(Glyph of Order держит место в вилке), и так не копится ошибка округления.

**Сколько это стоит в силе** (замер: герой 30-го уровня, по 400 найденных обычных на базу и ступень).
±15 % цифр оружия — это заметно меньше в ДПС, потому что вклад атрибутов прибавляется к урону плоско
и размывает оружие: на t3 найденные лежат в −5…−8 % / +3…+8 % от середины, на t6 — в −7…−11 % /
+7…+11 %. Уже всего у кинжала (мелкие числа базы), шире всего у тяжёлых на мифической ступени.

Соседние ступени перекрываются краями там, где шаг множителя ступени не больше ×1.35 (= 1.15 / 0.85):
у длинного меча это t0→t1, t4→t5 и t5→t6 — удачный «Элитный» бьёт как неудачный «Мифический», ровно как
в D2. На t1→t4 шаг крупнее, и там зазор. Вещь с ювелирной доводкой не перекрывается с нижней ступенью
никогда.

| Доводка | ДПС медианы против обычной работы | Цена против обычной (сырьё по цене продажи + золото) |
|---|---|---|
| Тщательная | +2.6 % | ×1.14 |
| Кропотливая | +3.4 % | ×1.28 |
| Ювелирная | +5.1 % | ×1.57 |

Замер длинного меча t3. Почти вся надбавка — золото (240 / 480 / 960 из 288 / 576 / 1 152).

**Доводка при ковке** (`balance.craft.finish`) — единственный рычаг «сделать лучше» у кузнеца:

| Доводка | Пол броска | Сверх цены | Где встаёт скованная среди найденных обычных |
|---|---|---|---|
| Обычная работа | 0 | — | как любая найденная: медиана ~48-й перцентиль |
| Тщательная | 0.35 | +4 материала клинка, золото ×1.25 | ~76-й |
| Кропотливая | 0.60 | +8, ×1.5 | ~90-й |
| Ювелирная | 0.80 | +16, ×2 | ~97-й |

Перцентиль — по ДПС среди 400 найденных той же базы и ступени, 10 проверок: меч, топор, кинжал, лук,
арбалет на t3 и t6. Лучшая скованная РАВНА теоретическому верху найденных и ни разу его не превысила.

Правила, на которых держится:

* **Поднимается только НИЗ вилки.** Верх тот же, что у лучшей найденной вещи этой ступени — правило Р1
  цело: ковка покупает НАДЁЖНОСТЬ, а не силу сверх дропа. Так же устроен «lucky» бросок в PoE:
  шанс сдвигается, потолок нет.
* **Результат — только после ковки.** До неё окно показывает вилку «(11–14)–(20–27)» и сравнение с
  тем, что в руках, «от и до». Мы берём модель New World (диапазон силы виден до крафта, число —
  после), а не превью-число: у ковки появляется маленький момент «что выпало».
* **Платится сырьём клинка**, его же материалом: доводят именно ударную часть, и цена растёт вместе
  со ступенью клинка сама. Золото ×1.25/×1.5/×2 держит доводку золотым стоком.
* **Переплавка доводку НЕ возвращает.** Её сырьё лежит отдельной строкой цены (`cost.finish`), а
  переплавка берёт долю только от строк деталей — иначе «ковать с ювелирной и переплавлять» стало бы
  бесплатным перебором бросков.
* **Бросок тянется ПОСЛЕДНИМ из генератора дропа** — редкость, аффиксы и имя найденной вещи на том
  же сиде не сдвинулись.
* **Скованную не поднимает кузнечный подъём тира** — теперь это запрет в коде (`upgradedItem`,
  `forgeUpgrade`), а не только строка §11. Без него доводка, купленная по цене t0, доехала бы до t6
  (ревью воспроизвело: 600 золота за пол 0.8 на мифическом мече), а `retierItem` стёр бы вклад деталей.
* **Пол — на сетке сотых, вверх** (`snapFloor`): доля хранится до сотых, и пол 0.333 иначе давал бы
  бросок 0.33 — ниже края вилки, показанного игроку.
* **Строка доводки действует своими числами, где бы ни стояла.** «Первая = без доводки» — договорённость
  данных: удали «Обычную работу» в редакторе, и «Тщательная» станет умолчанием, но останется платной.
* **Предпросмотр — середина СВОЕЙ вилки.** При доводке с полом вещь окна стоит на середине [пол, 1],
  иначе она несла бы урон, которого ковка не даст (тест по всем базам, ступеням и доводкам).

⚠ **Более сильный рычаг, который пока НЕ сделан:** пол на ЗНАЧЕНИЯ аффиксов при зачаровании. Доводка
двигает цифры базы (+2.6…+5.1 % ДПС медианы), а разброс значений аффиксов у редкой вещи шире в разы — это
следующий кандидат на «доводку», если этой покажется мало.

## 14. Математика: детали запекаются в предмет

```
ковка:
  база     = тип от ключевой детали (weapon-types.bases → items-base.json)
  имя      = первое сработавшее правило weapon-types.names или шаблон (§3.3) — без чисел
  ступень  = средний материал деталей по массе, в пределах базы и журнала (§11)
  статы    = scaleBaseStats(база, statMult ступени)
  damageMult = 1 ± 0.10 (весь удар) + { attackSpeed flat ∓0.08 }  ← гнездо 1
             + { reachMult, arcMult }                      ← гнездо 2 (ближний бой)
             + { <грань>ChancePct | <грань>PowerPct, blockChance } ← гнездо 4
  affixCap = { prefix, suffix }                            ← гнездо 3
  parts    = четыре ИД формы + ступень материала каждой     ← показ, модель, переплавка
  typeId   = ИД правила имени (если сработало)             ← кодекс, тултип
  аффиксы  = НЕТ. Вещь выходит обычной
```

Детали не создают нового множительного слоя в бою: их вклад записывается в статы самого
предмета — туда же, где живут урон и скорость любой найденной вещи. Почему не «слой поверх»:
любой новый множитель пришлось бы вручную вкрутить в бой, в ИИ, в симулятор и в калькулятор
редактора; пропустишь одно — числа разойдутся молча.

⚠ **Сервер считает сам.** На предмете лежат только ИД деталей; значения выводятся из конфига
при ковке. Предпросмотр редактора и результат сервера считает ОДНА чистая функция
`craftWeapon` в `shared/formulas` — иначе окно обещает не то, за что игрок платит.

⚠ **Предпросмотр показывает ВИЛКУ, а не бросок.** Сервер катает `createRng(Date.now() & 0xffffff)`;
«видно в момент создания» — это видно, какая форма и какие диапазоны, а не что именно выпадет.

## 15. Три сквозных примера

Герой 40 уровня, длинный меч t4 (база 7–13 → 24–44), бонус урона +45 %, скорости +15 %.

### Быстрый меч под статусы
Плоский клинок (τ −1) · короткая рукоять · широкая гарда (1+3) · оголовье в укус

| | Найденный редкий | Скованный | Разница |
|---|---|---|---|
| ДПС | 122 | 121 | −1 % |
| Ударов в секунду | 0.92 | **1.01** | +9 % |
| Стаков кровотечения | 1.38 | **1.79** | **+30 %** |
| Площадь взмаха | ×1.00 | ×1.00 | площадь-нейтрально |
| Дальность / дуга | — | ×0.89 / ×1.26 | ближе, но шире |
| Форма | 2+2 (случайная) | **1+3 (выбрана)** | сопротивления и реген |

### Тяжёлый под один большой удар
Широкий клинок (τ +1) · длинная рукоять · узкая гарда (3+1) · оголовье в упор

| | Найденный редкий | Скованный | Разница |
|---|---|---|---|
| ДПС | 122 | 121 | −1 % |
| Урон одного удара | 133 | **145** | +9 % |
| Дальность / дуга | — | ×1.12 / ×0.797 | достаёт дальше, задевает уже |
| Блок | 0.08 | **0.10** | +2.6 % eHP |
| Форма | 2+2 | **3+1** | урон, крит, стихия |

### Попытка собрать имбу
Всё в урон: широкий клинок · длинная рукоять · узкая гарда · оголовье в укус

| Что игрок хотел | Что вышло |
|---|---|
| Сложить урон клинка и ещё урон рукояти | **Нечем.** Рукоять урона не даёт вовсе, и площадь взмаха у неё постоянна |
| Добрать урон статусом с оголовья | Можно — но оголовье тогда отдаёт блок в пол, и вещь становится стеклянной |
| ДПС | 121 против 122 — **−1 %** |
| Удар | +9 % на удар при −8 % частоты: тот же ДПС, иначе разложенный |
| Форма | 3+1: ни сопротивлений, ни регена |
| Геометрия | дальше, но уже: по пачке из пяти бьёт одного |

⭐ Имба не выходит **по построению**: складывать нечего. Крайняя сборка перекладывает тот же
ДПС в один крупный удар или в частые мелкие и платит за это геометрией, формой слотов и блоком.

## 16. Восемь замков против имбы

| Замок | Как работает | Чем проверяется |
|---|---|---|
| **Каркас — существующая база** | у скованного не может быть статов, которых нет у дропа | тест по всем 50 базам |
| **Одна ось ДПС внутри типа** | `mods` детали выводятся из её `axis` × шага гнезда, руками не пишутся; смена ключа — смена базы | сторож: суммарный сдвиг ДПС от гнёзд 2–4 ≤ 3 % на реальном бою при фиксированной базе |
| **Площадь взмаха постоянна** | `дуга × дальность² = const ± 3 %` | сторож мерит ЧИСЛО задетых целей в симе, а не формулу |
| **Вес не складывается** | ось «ловкость ↔ сила» приходит пакетом с типом | тест «вес вещи = вес базы, урон и требования — базы» |
| **Потолок ёмкости выведен из дропа** | Σ ≤ 5, префиксов ≤ 3, суффиксов ≤ 3 — лимиты редкого | тест «ковка не даёт формы, которой нет у дропа» |
| **Переплавка вместо разбора** | у скованного свой глагол, журналу он не пишет | тест «ковка + переплавка не создаёт ни сырья, ни знаний» |
| **Имя без силы** | у правила имени нет числовых полей | тест «выключение всех правил имён не меняет ни одного числа» |
| **Верх вилки не растёт** | доводка поднимает пол броска базы, потолок — как у найденной; переплавка доводку не возвращает | тесты «доводка поднимает низ, верх не растёт», «найденная и скованная в одной вилке», «переплавка без доводки» |

⚠ Последний замок важнее, чем кажется, и держит сразу две прачечные: сырья («скуй обычную →
разбери как редкую») и знаний («накуй t1 ради журнала»). Плюс переплавка обходит
`rerollLimit: 3` — единственное, что сегодня удерживает аффиксы от бесконечного пережимания;
её цена обязана быть не ниже цены перекатки.

## 17. Экран ковки: от деталей к типу

```
Кузница → вкладка «Ковка»
  1. Семейство:  [Меч] [Одноручное]
  2. ★ Клинок — определяет тип            список по базам: «Длинный меч · 7–13 · режущий · вес среднее»
       [Широкий с долом, X]   ст.1–3   удар крупнее, взмахов меньше            материал: [Уклад]
  3. Рукоять:    [Тесная]     ст.1–3   вплотную, но шире                         [Варёная кожа]
  4. Гарда:      [Короткое перекрестье] 3+1: больше префиксов                   [Воронёная сталь]
  5. Навершие:   [Трёхчастное]  чуть крепче держит удар                        [Воронёная сталь]
     «Вся вещь из…»  [ст.1] [ст.2] [ст.3] [ст.4] [ст.5]   — каждой детали, прижато к окну формы

  Получилось: КАРОЛИНГСКИЙ МЕЧ                                       Ступень из деталей: t3 Отличный
              широкое полотно, короткое перекрестье, делёное навершие · Свод: клинок X · перекрестье 3 · навершие трёхчастное
              механика: Длинный меч · 7–13 · одноручное · режущий · вес среднее · Petersen 1919
     Урон: (11–14)–(20–27) — вилка; что выпадет, видно после ковки
  6. Доводка:  [Обычная работа] [Тщательная] [Кропотливая] [Ювелирная]   — поднимает низ вилки
  7. [Ковать]  уклад 59 · варёная кожа 30 · воронёная сталь 60 (форма 3+1: ×3.68) · 960 золота
```

**Решений пять:** семейство, ключевая деталь и три остальные. Материалы — четыре ряда чипов, но
почти всегда это одна кнопка «вся вещь из…»; тип, имя и ступень окно НЕ спрашивает, а
показывает, и пересчитывает после каждого клика. Ключевая деталь идёт первой, даже если это гнездо
2 (арбалет, магия), и её список сгруппирован по базам: заголовок — тип с уроном, весом и потолком,
строки — формы с окном материала и точкой оси. Отдельного переключателя «телосложение» нет — он
был бы шестым решением.

Правила экрана, купленные чужими ошибками:

* **Подпись говорит СЛЕДСТВИЕ с числом, а не стат.** Не «`+40 % bleedChancePct`», а «кровотечение
  вешается чаще: 1.4 → 1.8 стака». Строка каталога без подписи — незаконченная строка данных,
  и это закон схемы, а не пожелание.
* **Вилка видна до оплаты**, включая диапазоны будущих аффиксов. Цифры базы — тоже вилкой, и
  сравнение с тем, что в руках, идёт «от и до» (края вилки при выбранной доводке), а не по середине.
* **Серая кнопка объясняет себя:** «не хватает 4 калёной стали», «короткий меч не бывает выше t3»,
  «клинок X куётся только из ступеней 1–3», а не просто серый цвет.
* **Материал вне окна формы виден, но не нажимается** — с подсказкой, из чего форма куётся.
* **Одна кнопка «как было».**
* **Разбор и продажа скованного спрашивают дважды.**
* ⚠ **Сервер отказывает ДО списания, если пул аффиксов не наберёт оплаченную форму.**
  `rollAffixes` при пустом пуле делает `break` МОЛЧА: выключил дизайнер полдюжины аффиксов —
  игрок заплатил за пять слотов, получил три, и никто не узнал.

### 17.1 Чего в системе не хватает: момента радости и причины возвращаться

Правило Р3 (детерминизм) вынесло из ковки почти всю эмоцию: платишь и получаешь то, что прочитал.
Вилка базы (§13.1) вернула маленький момент — «что выпало» после удара молота, — но он узкий
(единицы процентов ДПС) и не заменяет церемонию. Это правильно — но у каждой работающей системы есть момент, ради
которого её открывают: слэм в PoE, щелчок рунного слова в D2, крит-ковка в Last Epoch.

Лечение не в возврате азарта в ковку, а в **переносе церемонии на зачарование**, где
случайность уже есть и она законна: удар молота, вспышка, проявление аффиксов по одному.
**Ковка — спокойная, зачарование — громкое.**

И вторая вещь, без которой вкладка мертва между ковками: **страница каталога**. Силуэты
незакрытых деталей, счётчик «6 из 8 клинков меча», всплывашка «открыта новая деталь» прямо
в момент разбора. Главная петля системы — не «сковал оружие раз в двадцать уровней», а
**«разбор хлама кормит каталог»**, то есть каждый мусорный дроп становится прогрессом.

⚠ **И самая крупная дыра в охвате: глагола «заменить деталь в найденной вещи» нет.** Система
обслуживает только тех, кто кует с нуля; игрок с хорошим найденным раром не откроет вкладку
никогда. А детали у найденной вещи уже выводятся детерминированно — значит слоты у неё есть,
и замена клинка в любимом мече использует ту же машинерию. Стоит одного глагола и превращает
ковку из отдельного пути в то, что трогают все.

## 22. Чем проверяем

* **Разброс ДПС ≤ 8 % в объявленном конверте** (бонус урона 0.3…1.5 × бонус скорости
  0.05…0.6), на всех 50 базах, **на реальном бою** через `session/microFight.ts` — не закрытой
  формулой и не `sim/fight.ts` (он сам в шапке пишет, что DoT и статусы игнорирует).
  Сетка обязана шагать **по темпу**, а не только по ДПС: уптайм статуса — ступенька по ударам
  в секунду, и при неизменном ДПС она не видна.
* **Инвариант объявляется на руку**, дуал-вилд мерится отдельным прогоном.
* **Число задетых целей** в симе для гнезда 2 — иначе «площадь-нейтрально» останется формулой.
* **Одна ось:** сторож, что `mods` детали выводятся из `axis`, а не записаны руками.
* **Не прачечная:** «сковать и переплавить» не создаёт ни сырья дороже потраченного, ни меток
  в журнале — ни на одном пути.
* **Мощность в час:** «сковал за N минут фарма» против «нашёл за то же время».
* **Редактор ≡ сервер:** предпросмотр совпадает с расчётом сервера до числа.
* **Телеметрия:** счётчик скованного и разобранного рядом с `killsPerHour` — иначе проверить
  «цена ≈ времени фарма» после запуска будет нечем.
* `npx vitest run` + `tsc` ×4 + сборка клиента и редактора.

У грани один продавец · ↻ **пересмотрено в §26:** клинок и оголовье дают ОДНУ точку баланса вещи с общим клампом ±1 (доли 0.6 / 0.4) — это один продавец, а не два: крайний клинок с крайним оголовьем упираются ровно в прежний потолок одного оголовья, а разнонаправленные гасят друг друга |
| **Масса как торгуемая колонка** | вся лестница весов двигает нокдаун на 0.44 п.п.; потолок всей механики +2.37 % урона · ↻ **§26 это не отменяет:** центр тяжести силуэта — свойство формы, он кормит рычаг баланса; масса вещи по-прежнему не вводится и не торгуется |

| **Шестая ступень материала** | ступень вещи — средний уровень деталей по массе; шестая ступень в одной семье сделала бы её гнездо «весомее» остальных без единой строки баланса |
| **Потолок материала по роли гнезда** | «булава не может быть t5» — это запрет на ковку целого класса. Осталось текстом в тултипе, а не механикой |
| **Ковка брони** | второй заход ⚠ и решить надо СЕЙЧАС: у брони группа `life` общая у префикса `hearty` и суффикса `of-vigor`, оплаченный сплит 3+3 может не набраться |
| **Уникальные свойства с ковки** | они остаются за дропом |

вторая ось двигала бы ДПС и складывалась бы у двух деталей. У §26 ширина ДПС не двигает, а баланс — один

## 25. Полуторный хват: двуручное оружие одной рукой

Полуторный меч (95–105 см) носят и двумя руками, и одной — со щитом, за штраф. Режим нигде не
хранится: **занята вторая рука — значит одноручный хват**.

**Как это было в Diablo II** (сверено по `weapons.txt` 1.13, 18 строк с флагом `1or2handed`, все —
мечи): у оружия ДВА набора урона (`mindam/maxdam` и `2handmindam/2handmaxdam`), скорость и требования
в обоих хватах ОДИНАКОВЫ, режим — по занятости офф-руки, и право так носить было только у варвара.
Одноручный хват давал примерно половину двуручного урона; смысл не в «половине», а в том, что он
выводил двуручник ВРОВЕНЬ с хорошим одноручником той же ступени, а платой было требование силы
примерно в полтора раза выше.

**Что у нас иначе и почему:**

| | Д2 | У нас |
|---|---|---|
| Наборы чисел | два в данных | ОДИН (двуручный), одноручные считаются на лету |
| Скорость | одна на оба хвата | одной рукой ×0.92 — второй довод взять двумя |
| Урон одной рукой | ×0.52 | **×0.88** |
| Требования | одни на оба хвата | так же |
| Кому доступно | только варвару | свойство ВЕЩИ, доступно всем |

⚠ **Один набор чисел — не мелочь.** У вещи катается вилка базы (§13.1) и работает доводка; храни мы
два набора, они разъехались бы между хватами, и подсказка начала бы врать.

⚠ **Множитель Д2 копировать нельзя.** Там двуручники вдвое сильнее одноручных, у нас — в полтора
раза: с ×0.52 одноручный хват стал бы заведомо хуже длинного меча, то есть мёртвой опцией.

⚠ **Числа подобраны ЗАМЕРОМ, а не выведены.** Вклад атрибутов размывает разницу оружия: «на бумаге»
×0.88 урона и ×0.92 темпа дают −19 % ДПС, а в модели героя 30-го уровня — −12 %. Замер (воин 1/30/60
уровня, щит в офф-руке): одноручный хват ≈ 0.99 длинного меча при требовании силы 22 против 15,
двуручный хват выгоднее одноручного в 1.13 раза, и настоящий двуручник остаётся сильнее полуторного.
Все три величины стережёт `versatile.test.ts`.

**Что видит игрок.** В подсказке СРАЗУ обе строки, без переключателей:

```
Урон: 11–19 (физ)
Скорость: ×0.95 · 57 уд/мин
Одной рукой (со щитом): 10–17 · ×0.87 · 52 уд/мин
```

**Где живёт механика:** флаг `versatile` у базы (`items.base`), ручки `balance.versatile`
(редактор, группа «Бой и физика»), расчёт — `formulas/versatile.ts`. Шва ровно два, и через них
проходит всё: `equippedItems` (стат-блок панелей и деривация) и `attackWeaponsOf` (настоящий удар).
Экипировка щита к полуторному разрешена (`townActions.equip`), ключ анимации берётся по фактическому
хвату (`session/weapon3d.ts`) — иначе двуручные взмахи играли бы на мече в одной руке.

⭐ **Задел на дерево навыков** (решение владельца): узел, поднимающий одноручный множитель с 0.88
ближе к 0.95, — тогда игрок ПОКУПАЕТ очками право драться полуторником со щитом почти без потерь.
Ручка для этого уже вынесена в конфиг; узла пока нет.

## 26. Клинок из геометрии модели

До этой правки точку оси клинка (τ, §4) ставили руками: «Широкий с долом, X — +1». Владелец приносит
около сорока настоящих моделей клинков, и число на глаз перестаёт работать: игрок видит длинный узкий
клинок, а подпись обещает «самый быстрый в пуле». Поэтому у мечевого клинка с измеренной моделью статы
**выводятся из самой модели** — из длины, ширины и центра тяжести силуэта. Новых ручек силы нет: все три
рычага едут по уже существующим (§4, §7), и ДПС внутри типа по-прежнему двигает одна ось.

```
ДЛИНА  L   → место в вилке  n_L = clamp((L − (lo+hi)/2) / ((hi−lo)/2), −1, +1)   → ось удара §4: удар ×(1 + 0.10·n_L), скорость flat −0.08·n_L
ШИРИНА W   → разброс урона  s   = clamp(1 − 0.9·ln(W / W0), 0.4, 1.6)             → мин и макс базы = середина ∓ полуразмах × s
ЦТ         → баланс клинка  n_B = clamp((0.45 − ЦТ) / 0.10, −1, +1)
           → баланс ВЕЩИ    n   = clamp(0.6·n_B + 0.4·ось оголовья + сдвиг формы, −1, +1)
                                                                                 → блок +0.02·n, кровотечение −0.25·n
```

| Рычаг | Что меряем | Куда идёт | ДПС | Что чувствует игрок |
|---|---|---|---|---|
| **Длина** | длина клинка, см | место в своей вилке → ось удара (§4) | ×0.972…×1.012 — та же ось, тот же конверт 4.1 % | длинный для вилки — удар крупнее, взмахов меньше; короткий — наоборот |
| **Ширина** | рабочая ширина, см | разброс мин–макс вокруг ТОЙ ЖЕ середины | **×1.000** — среднее не двигается | широкий бьёт ровно, узкий — вразнобой |
| **Баланс** | центр тяжести силуэта | точка баланса вещи вместе с оголовьем (§7) | только через кровотечение, как у оголовья | вес у руки — крепче держит удар; вес к концу — чаще пускает кровь |

Сквозной пример — **Гранёный, XV**, с 25.09 короткий меч: 74 см в классе 45–78 → место +0.76 → удар ×1.076,
скорость ×0.94; рабочая ширина 2.02 см при эталоне 4.7 → разброс упёрся в потолок ×1.6; ЦТ 0.342 → баланс
клинка +1. Широкий XXII (5.79 см) на той же базе бьёт ровнее — разброс ×0.81. Середина чисел у обоих одна.

### 26.1 Длина: место внутри вилки

Вилка берётся по тегу `blade` клинка — те же четыре класса по длине, что выбирают базу (§3.5):

| Тег | Класс | Клинок, см | Место считается по | Середина, см | 1 см длины = шаг оси | Эталон ширины W0, см | Выведенная ось в данных |
|---|---|---|---|---|---|---|---|
| `short` | короткий | до 78 | 45–78 | 61.5 | 0.06 | 4.7 | −1.0…+1.0 |
| `arming` | длинный | 78–90 | 78–90 | 84 | **0.17** | 3.5 | −1.0…+0.83 |
| `great` | полуторный | 90–110 | 90–110 | 100 | 0.1 | 3.9 | **−0.9…+0.4** |
| `huge` | двуручный | от 110 | 110–136 | 123 | 0.08 | 4.6 | **−0.69…+0.54** |

W0 — медиана рабочих ширин клинков класса (пересчитана 25.09 после перекладки). Минус −1.0 у длинного даёт
сабля: её форма добавляет −1 к месту.

⭐ **Длина — не новая ось, а прежняя τ, только измеренная.** ДПС формы = (1 + 0.1·n)(1 − 0.08·n) ∈
[0.972, 1.012], ручки те же — `balance.craft.strike` (0.10 / 0.08). Сторожа §4 и §22 не меняются.

⚠ **Вилки разной ширины — и сантиметр стоит по-разному.** В длинном мече 1 см — 0.17 шага оси, в коротком —
0.06. Поэтому длина замера округляется до 0.1 см, а сторож держит расхождение данных с замером ≤ 0.15 см.

⚠ **Полуторные и двуручные занимают только часть оси:** −0.9…+0.4 и −0.69…+0.54 — исторические длины не
тянутся к краям класса. Это не формула, а длины оригиналов; закрывается моделями владельца (§3.5).

Клинок вне своей вилки упирается в ±1, и окно пишет «Клинок N см вне вилки … ось упёрлась в край»
(`bakeParts`). Клинок без тега `blade` — ось 0, разброс ×1. Сегодня все 36 клинков внутри своих вилок.

✅ **Зазоров больше нет** (решение 8 закрыто 24.09): классы идут встык, границы полуоткрытые, крайние классы
открыты наружу (§3.5). Если ручками редактора развести вилки, `suggestBracket` снова отдаст ближайшую с
пометкой «в зазоре», и редактор покажет это предупреждением, а не отказом.

### 26.2 Ширина: разброс вокруг той же середины

```
s = clamp(1 − 0.9·ln(W / W0), 0.4, 1.6)      мин = середина − полуразмах·s,  макс = середина + полуразмах·s
```

Логарифм — чтобы «вдвое шире» и «вдвое уже» были равными шагами. Края ручки достигаются при ширине ×1.95
от эталона (s = 0.4, почти ровный удар) и ×0.51 (s = 1.6).

* **Разброс ложится в числа БАЗЫ, до тира и броска** (`shapedBaseStats` внутри `scaleBaseStats`): тир
  сохраняет форму от «Сломанного» до «Мифического», а бросок D2 (§13.1) катается уже вокруг неё. Мин не
  опускается ниже 0.5 до тира.
* **Только числа оружия** (решение 3): вклад атрибутов в удар не разводится. Поэтому в ударе ширина
  размыта так же, как бросок базы в §13.1.
* На вещи лежит `Item.spreadMult`: подъём тира (`retierItem`) и вывод тира старых сейвов (`inferTierId`)
  пересчитывают мин и макс с той же формой — узкий «Сломанный» 5–15 не прочтётся чужим тиром.

**Замер при проектировании** (герой 30-го уровня, «Сломанный» длинный меч 9–11 против 5–15): удар узким
гуляет на **±12 %**, широким — на **±2.4 %**, и отношение держится у героя 1, 30 и 60 уровня. По формуле края
ручки дают 4× (1.6 / 0.4); замер показал 5×, потому что 8.8–11.2 округлилось до 9–11. У крайних клинков
данных длинного меча отношение s — 3.4 (1.44 / 0.43).

⚠ **Шум округления.** Мин и макс формы округляются ПОРОЗНЬ, как и без формы: каждый зависит только от своего
броска, и вещь не выкатывается за показанную вилку «от и до». Цена — середина клинка уезжает до полединицы.
На малых числах это видно: у архаичного меча (5–9) герою 1-го уровня разброс ДПС между клинками — до 7 % на
t1–t5, при том что без округления он в коридоре оси длины (≤ 4.1 %). С 40-го уровня и у остальных баз —
в пределах 5 %. Подгонка суммы мин + макс шум убирала, но связывала мин с броском макса — и сторож вилки
`craft.test.ts` ловил выход за «от и до». Сторож ДПС в `bladeStats.test.ts` держит список известных случаев:
новый валит тест.

⚠ **Бросок ±15 % разброс не стирает, но края перекрывает.** Широкий клинок в самом разбросанном углу броска
(мин вниз, макс вверх) не дотягивается до размаха узкого в самом собранном (мин вверх, макс вниз), только
если их s разнятся не меньше чем на 0.3 × середина / полуразмах базы: ≈ 1.0 у длинного меча, 1.15 у двуручного. Края ручки
(0.4 и 1.6) разведены на всех ступенях, кроме трёх ничьих от округления. Крайние клинки данных — нет: у
длинного меча (XIII против XV) впритык — ничья на пяти ступенях из семи, в остальных вилках углы броска
перекрыты. Как ступени в §13.1: края перекрываются, середины — нет.

### 26.3 Баланс: центр тяжести силуэта

```
n_B = clamp((0.45 − ЦТ) / 0.10, −1, +1)      ЦТ 0.5 — лезвия параллельны, 0.33 — треугольник к острию
n   = clamp(0.6·n_B + 0.4·ось оголовья + сдвиг формы, −1, +1)
блок += 0.02·n     кровотечение −= 0.25·n      (у меча статус грани — кровотечение, §7.1)
```

⭐ **Одна точка баланса на вещь, один продавец.** Клинок и оголовье не складывают вклады, а делят один рычаг
с одним клампом (доли 0.6 / 0.4, решение 7): крайний клинок с крайним оголовьем упираются ровно в прежний
потолок одного оголовья (блок ±0.02), разнонаправленные гасят друг друга. Это и снимает запрет §23 «статусный
рычаг в двух гнёздах».

* **Блок платит только кровотечением** (решение 2). Цены «урон за удар» у баланса нет — замок «одна ось ДПС
  внутри типа» цел.
* Клинок без геометрии — точка баланса = ось оголовья, как было.
* Вес у руки — гранёные и узкие: XV, XVa, XVII, XVIII (ЦТ 0.34–0.36, баланс клинка +0.93…+1). Вес к концу —
  фальшионы (ЦТ 0.52–0.54, −0.7…−0.9, и форма сверху −0.4).
* Чтобы рычаг был двусторонним у всех пяти вилок, архаичный и двуручный меч получили базовый блок 0.02 (§7.2).

### 26.4 Формы: фальшион и сабля

| Форма | Длина | Баланс | Детали сейчас |
|---|---|---|---|
| фальшион `falchion` | +1 шаг оси | −0.4 | Фальшион (`sw-a-falchion`), Падающий (`sw-r-falling`, копис), Серповидный, V (`sw-r-sickle`, хопеш) |
| сабля `sabre` | −1 шаг оси | +0.4 | Саблевидный (`sw-a-sabre`) |

Фальшион тяжелее и рубит концом, сабля легче и ходит у руки. Обе поправки зажаты в ±1 — форма не выводит
клинок за потолок оси. **Сабля — зеркало фальшиона** (решение 4): «у нас АРПГ, а не симулятор фехтования».

Подсказка формы по замеру (`suggestForm`, пороги `balance.craft.detect`): однолезвийность по сетке не видна,
поэтому её ставит человек тегом `edge: single`, а замер решает только «какая» — расширение к концу
`flare ≥ 1.15` → фальшион, изгиб спинки `spine ≥ 3 %` → сабля. Решает человек, полем `form` детали.
⚠ Заглушка саблевидного почти прямая (изгиб 0.74 %) — форма у неё поставлена руками.

### 26.5 Замер модели

| Число | Как считается |
|---|---|
| `len` | длина клинка от пяты до острия, см, до 0.1 |
| `width` | рабочая ширина: **медиана** ширины на станциях 25–87 % длины — без усов рикассо и без острия |
| `bal` | ЦТ — центр площади силуэта по профилю ширины: 0 у рукояти, 1 у острия |
| `flare` | наибольшая ширина на 67–87 % длины к медиане на 33–67 % |
| `spine` | изгиб спинки: наибольший снос линии обуха от хорды между второй и двадцать первой станцией, % длины |

Клинок режется **24 плоскостями** поперёк длины (`BLADE_STATIONS`), и в каждой ширина и толщина сечения
берутся по пересечению рёбер ТРЕУГОЛЬНИКОВ с плоскостью, а не по вершинам: у низкополигональной модели
длинный треугольник пересекает полосу, не оставив в ней ни одной вершины, и замер по вершинам читал бы там
ноль. Пустое сечение — предупреждение «клинок с разрывом или сетка не замкнута».

**Договор о модели** — тот же, что у `craftMesh/core.ts`: сантиметры, пята клинка в начале координат, клинок
идёт по −Y, полотно в плоскости XY, лезвие смотрит в +X. Модель не по договору разворачивается (`orient`):
длинная ось — клинок, полотно — более широкая из двух оставшихся осей, а ⭐ **пята и остриё — по ФОРМЕ:**
узкий конец — остриё. Догадка «пята у начала координат» у модели с центром посередине клинка — монетка, и
перевёрнутый клинок молча менял бы блок на кровотечение (ЦТ 0.36 ↔ 0.64). Центр не у пяты — предупреждение;
форма обманула (тупоконечный, тяжёлый конец) — во вкладке редактора есть «перевернуть пяту и остриё»
(`measureBlade(obj, { orient, flip })`). Спинку однолезвийного при развороте не отличить от лезвия — замер
предупреждает, однолезвийность ставит человек.

Единицы модели вкладка угадывает по длинной стороне: меньше 5 — метры (×100), больше 250 — миллиметры
(×0.1): самая длинная вилка — 150 см, а 45-сантиметровый акинак в миллиметрах — 450. Можно задать руками.
`.gltf` с отдельным `.bin` не читается — нужен `.glb` (или `.gltf` со встроенными буферами).

### 26.6 Найденный меч = скованный из тех же деталей

`shapeFoundWeapon(reg, item)` стоит во всех точках дропа: монстр и сундук (`session.ts`), лавка (`room.ts`),
симы (`sim/floor.ts`, `sim/economy.ts`) и генераторы редактора. Вид вещи обязан совпадать с её числами:
широкий клинок бьёт ровно и с пола, и из кузницы.

* **Детали замораживаются в момент выпадения** — `Item.foundParts`, отдельно от `parts` (по `parts` вещь
  считается скованной: переплавка вместо разбора). Дальше подъём тира и новый вариант в пуле клинок не
  подменяют. `partsOf` отдаёт `parts ?? foundParts ?? вывод`.
* **Сид — из содержимого вещи** (база, редкость, уровень, тир, бросок, аффиксы, имя), а не из `uid`: тот
  сделан из времени и `Math.random`, и сим с сидом перестал бы повторяться. И не новым броском `rng` — лишний
  бросок сдвинул бы всю следующую добычу.
* **Берётся** ось длины (множитель удара и плоская скорость), разброс ширины и точка баланса (блок и
  кровотечение). **Не берутся** держак (дальность и дуга) и обвязка (ёмкость) — аффиксы уже выпали.
  Уникальные не трогаются вовсе. Ударная часть без геометрии — вещь возвращается как была.
* Функция идемпотентна: статы пересобираются от базы, повторный вызов не накопит вклад клинка дважды.
* **Подъём тира в кузнице** (`upgradedItem`): `retierItem` пересобирает числа от базы с той же формой, затем
  `restepParts` ставит тем же деталям ступени под новый тир (разбор отдаёт то, из чего вещь сделана, §10.9 —
  а не материалы тира выпадения), и `shapeFoundWeapon` возвращает вклад клинка ОТ ДЕТАЛЕЙ. Вычитание
  «что сверх базы» из текущих статов отвергнуто: правка базы после выпадения застревала бы в вещи навсегда.

Решение 5: сейчас мечи; потом ВСЁ оружие и весь дроп — остальные классы перейдут сами, как только их
ударные части получат модели и `geom`.

### 26.10 Отступление от плана и риски

⚠ **Отступление: заглушки берут ВИД из ручной оси.** Процедурный клинок (`blades.ts`) по-прежнему расширяет
полотно ×0.86…×1.14 по ручной `axis` (`byAxis`), а статы идут только из замера. Отсюда круг: ручная ось →
ширина заглушки → замер → разброс. Правка ручной оси или формы в `blades.ts` без нового замера краснит
сторож `bladeGeom.test.ts`; после перемера меняются и статы. Круг рвётся, когда заглушку заменит модель.

⚠ **Найденная вещь замораживает детали и числа при выпадении.** Правка `balance.craft.blade` или перемер не
перестраивают мечи, уже лежащие в сейвах и сундуках, — как не перекатываются выпавшие аффиксы.
`shapeFoundWeapon` идемпотентна и пересобирает от базы, так что прогнать её при загрузке можно, но это
отдельное решение: оно поменяет вещи, которые игрок уже оценил.

⚠ **Мимо `shapeFoundWeapon` идут:** стартовый набор (`economy/newCharacter.ts`), награды квестов
(`economy/questLogic.ts`) и стартовое оружие бота симулятора (`sim/playerBot.ts`) — они живут на числах базы:
множитель ×1, разброс ×1, блок только базовый.

✅ **Долг §19 для найденных мечей закрыт:** подъём тира возвращает вклад клинка от записанных деталей
(§26.6), ступени деталей встают под новый тир. `retierItem` сам по-прежнему собирает статы от базы (плюс
