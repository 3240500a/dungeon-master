# Ковка оружия из деталей — гейм-дизайн

Документ РЕШЕНИЙ: что игрок делает, из чего это собрано, какими числами держится и почему
отвергнуто другое. Состояние работ живёт во вкладке «📍 Роадмап» конфиг-редактора.
Экономика сырья, разбор и ступени — в [ECONOMY.md](ECONOMY.md).

Все числа в документе ЗАМЕРЕНЫ по коду и конфигу, а не оценены. Где замера нет — написано
«оценка». Где замер противоречит прежней версии документа — старая строка удалена, а не
поправлена: в §0 перечислено, что именно отменено.

## 0. Что отменено из первой версии

Первая версия писалась до замеров. Шесть независимых разборов кода плюс три сверки вскрыли,
что три её опоры держались на числах, которых в игре нет. Отменённое:

| Было | Почему отменено | Стало |
|---|---|---|
| **Навершие торгует «масса ↔ требования»** | Ось мертва с ОБЕИХ сторон. Масса: вся лестница весов (кинжал 3 → молот 25) двигает шанс сбить с ног на **0.44 п.п.** (4.31 % → 4.75 % по цели массой 100), потому что `knockdown.chanceBase` = 0.85 растворяет вклад оружия, а сопротивление `масса_цели × 0.01` упирается в кап 0.95 у 11 монстров из 13. Потолок ВСЕЙ механики нокдауна — +2.37 % урона. Требования: кап `maxTotalRequirement` 190 душит **42 базы из 50 на t6** и 24 на t5, там −15 % двигают ровно ноль; зато на t3–t4 та же колонка стоит 3.5–7.5 % ДПС — перекос 31:1…260:1 | Гнездо 4 торгует **«укус ↔ упор»**: шанс статуса против блока и стойкости (§7) |
| **Р5: «ковка до t5, t6 только с дропа»** | Решение владельца: t6 куётся, но через счётчик разобранных мифических вещей и по цене ×6 сырьём | t6 куётся (§12) |
| **Чертежи падают с монстров, из сундуков и с боссов** | Решение владельца: чертежей как предметов нет | Разбор вещи у кузнеца открывает и базу, и её четыре детали (§12) |
| **Лезвие ±15 п.п. урона / ∓12 % скорости, «разброс ≤ 6 %»** | Замер на сетке из самого документа (бонусы урона 0…0.9 × скорости 0…0.9): пара 15/12 даёт **19.2 %** разброса, а не 6 %. И сам документ спорил с собой: §14 обещал 6 %, фаза К5 — 8 % | Пара **±10 / ∓8** и один объявленный конверт (§4) |
| **Рукоять: «+20 % дальности ↔ −20 % дуги, ни одна сторона не ДПС»** | `meleeSwing` бьёт ВСЕХ в секторе, площадь сектора = `дуга × дальность²`. Длинная рукоять давала **+27.6 % сметаемой площади** — то есть гнездо, объявленное «ДПС не трогает», было почти втрое сильнее единственной разрешённой оси ДПС | Площадь-нейтральная пара: `дуга × дальность² = const ± 3 %` (§5) |
| **«У лука и арбалета рукоять торгует дальностью против разброса»** | Дальность снаряда — константа `440 × 2.5 = 1100 px` при зрении монстра 240–320 px: стрелять дальше, чем видишь, можно уже вчетверо. Поля «разброс» у оружия не существует вовсе — `spread` принадлежит СКИЛЛУ | Пробой с затуханием, и он требует правки кода (§5) |
| **«Новых семейств сырья не вводим»** | Решение владельца: у деталей свои тиры по материалам. Трёх ступеней железа под лестницу «болотное → кричное → уклад → дамаск → булат» не хватает | Восемь семей по пять ступеней, ровно три на вещь (§10) |
| **«Скованное РАВНО найденному по силе»** | Замер по весам аффиксов: скованная форма 3+2 несёт **2.78** полезных билду аффикса против **2.22** у среднего найденного редкого (+25 %). Правило Р1 не нарушено — такая вещь выпадает у 16.7 % редких, — но формулировка была неверна буквально | «Равно ВЕРХНИМ 17 % найденных редких и платит за это шестикратно» (§2) |
| **«Три клика»** | После всех решений честный флоу — 8 действий при 5 решениях | Пишем 8 и не врём (§17) |

## 1. Рамка: решения владельца

| Ось | Решение |
|---|---|
| Что делает крафт | **Создаёт вещь с нуля** из деталей, а не только улучшает найденное |
| Визуал | **Модель собирается из частей** |
| Охват | **Все 10 классов оружия** равным числом деталей — четыре гнезда у каждого |
| Откуда детали | **Разобрал вещь у кузнеца — открылись части, из которых она состояла.** Чертежей как предметов нет |
| Редкость деталей | Прямая гарда часто, изогнутая реже, фигурная ещё реже |
| Тиры деталей | **Материал задаёт полосу ступеней**: низкокачественное железо t0–2, кричное t2–3, дамаск t3–5, булат t5–7. По магическим, рукоятям и остальному — так же. **Правдоподобно, по историческим источникам** |
| Уровень вещи | **Вычисляется из уровня частей** |
| Аффиксы | Сперва куётся **база**, потом отдельно поднимается до магической/редкой. В ковке заложено, **сколько каких аффиксов** база примет, и это **видно в момент создания** |
| Цена | Чем лучше база — тем дороже по ресурсам |
| t6 | **Куётся**, но разобрав некоторое количество t6 предметов, и стоит очень дорого |
| Варианты деталей | **Не по три.** Лезвий много — плоское, широкое, фальшион, узкое, изогнутое; у каждого свои показатели |
| Статусы | Можно сделать **шанс наложения эффекта** от детали, и в противовес что-то поставить |
| Блок | У оружия есть свой небольшой шанс блока — **обыграть его** |
| Сила | Равна найденному, но специализирована под билд |
| ⭐ Главное | **Приятное дополнение, а не вторая работа.** Не ломать флоу D2/PoE 2: можно бегать с тем, что нашёл, и вкладку не открывать |
| Материалы | Не пятнадцать материалов ради одного меча |

## 2. Шесть правил, которые нельзя нарушать

**Р1. Крафт не создаёт мощности, которой нет в дропе.** Каркас скованного — та же база из
`items-base.json` и та же ступень. Ковка меняет не силу, а **её форму**. Точная формулировка
после замера: скованная вещь равна **верхним 17 % найденных редких** и платит за это
шестикратной ценой; больше лучшего дропа она не даёт ни на единицу.

**Р2. У каждой детали заполнены обе колонки — «дал» и «забрал».** Ни одной детали, которая
просто лучше другой. Урок Warframe (Zaw/Kitgun) и Destiny 2: там части давали чистый плюс,
и через месяц все играли двумя-тремя мета-сборками.

**Р3. Случайность — только в ЗНАЧЕНИИ, никогда в том, что выпадет.** Детали выбираются
осознанно, вилка видна заранее; катаются только аффиксы, ровно как у найденной вещи.
Отсюда же: детали найденной вещи **выводятся детерминированно из неё самой**, а не катаются
в момент разбора — иначе разбор становится лотереей.

**Р4. Провал не «кирпичит» вещь.** Любую сборку можно переплавить и вернуть часть вложенного.
Главная жалоба на Last Epoch (`Forging Potential = 0` — предмет закрыт навсегда) и на темперинг
Diablo 4 — именно про это.

**Р5. Редкость варианта детали — это ЧАСТОТА, а не сила.** Фигурная гарда не лучше прямой,
она реже. Все варианты одного гнезда сидят на ОДНОЙ его оси, просто в разных её точках.
Сторож обязан группировать замер ДПС по редкости детали и краснеть при расхождении.

**Р6. Ступень вещи задают детали, а не кошелёк.** Материал детали несёт ПОЛОСУ ступеней;
ступень вещи зажата снизу материалами, сверху — журналом кузнеца. Дешёвой t6-детали не
существует как объекта, поэтому «три дешёвые + одна дорогая» невозможно по построению,
а не по проверке.

## 3. Конструкция: чертёж → четыре гнезда → аффиксы

```
ЧЕРТЁЖ                  ЧЕТЫРЕ ГНЕЗДА                       АФФИКСЫ
(какая база)            (какой характер)                    (потом, отдельным глаголом)

«Длинный меч»           1 ударная часть  урон ↔ скорость     форма объявлена при ковке,
урон 7–13, треб. 25     2 держак         дальше ↔ шире       значения катаются как у дропа
грань: режущий          3 обвязка        префиксы ↔ суффиксы
вес: среднее            4 оголовье       укус ↔ упор

у каждого гнезда: ФОРМА (точка на оси) × МАТЕРИАЛ (полоса ступеней)
```

Чертёж не описывает новое оружие. Он даёт право ковать **одну из 50 баз, которые уже есть
в игре**: урон, скорость, требования, класс, грань удара и сигнатурные поля (`stunChance`,
`armorPenPct`, `arcMult`, `reachMult`) приходят готовыми. Правило Р1 держится не подбором
чисел, а по построению: скованный длинный меч — это длинный меч.

### 3.1 Гнездо × класс: как деталь называется у каждого из десяти

Гнездо несёт РОЛЬ, класс даёт ИМЯ и МЕШ. Анатомии хватило у всех десяти — ни одну деталь
не пришлось нагружать двумя показателями.

| Класс | 1 · УДАРНАЯ ЧАСТЬ<br>урон ↔ скорость | 2 · ДЕРЖАК<br>дальше ↔ шире | 3 · ОБВЯЗКА<br>префиксы ↔ суффиксы | 4 · ОГОЛОВЬЕ<br>укус ↔ упор |
|---|---|---|---|---|
| Меч `sword` | Клинок | Рукоять | Гарда | Навершие |
| Кинжал `dagger` | Клинок | Черен | Крестовина | Оголовок |
| Топор `axe` | Полотно | Топорище | Проушина (всад) | Подток топорища |
| Булава `mace` | Било (головка) | Рукоять | Шейка (обоймица) | Противовес |
| Копьё `spear` | Наконечник (перо) | Древко | Тулея (втулка) | Подток |
| Алебарда `halberd` | Полотно с крюком | Древко | Обоймица (ланцеты) | Подток |
| Лук `bow` | Плечи (рога) | Рукоять-райзер | Накладки и оплётка | Тетива |
| Арбалет `crossbow` | Дуга (лучище) | Ложе | Оковка и стремя | Замок (орех и спуск) |
| Жезл `wand` | Фокус (навершие-камень) | Рукоять | Оправа | Сердечник |
| Посох `staff` | Навершие-фокус | Древко | Оковка | Пята |

Проверка «хватает ли анатомии» простая: гнездо 1 — что входит в цель; гнездо 2 — за что
держат (задаёт дистанцию); гнездо 3 — где детали сходятся (туда и садятся чары); гнездо 4 —
противоположный ударной части конец. У лука и арбалета порядок читается вдоль выстрела:
плечи бросают, райзер целит, тетива задаёт резкость спуска.

### 3.2 Четыре роли в одной таблице

| Гнездо | Ось | Ближний бой (30 баз) | Стрелковое (10 баз) | Магическое (10 баз) |
|---|---|---|---|---|
| **1 · Ударная часть** | единственная ось ДПС, зеркальная | `damagePct ±0.10` ↔ `attackSpeed ∓0.08` | то же: туже натянуто = урон, мягче = темп | то же: болт идёт через тот же `attackCd` |
| **2 · Держак** | дальше по одному ↔ шире по многим | `reachMult` ↔ `arcMult`, площадь-нейтрально | пробой с затуханием ↔ одна цель (**нужна правка кода**) | то же, что у стрелкового |
| **3 · Обвязка** | форма ёмкости аффиксов | узкая 3+1 · равная 2+2 · широкая 1+3 | то же | то же |
| **4 · Оголовье** | укус ↔ упор | шанс статуса своей грани ↔ блок `+0.02` | лук: ↔ `interruptResist`; арбалет: ↔ блок ложа | шанс статуса своей стихии ↔ блок |

⭐ **ДПС двигает ровно одно гнездо.** Замок: `mods` детали **выводятся** из её поля `axis`
(−1…+1) умножением на шаг гнезда, а не пишутся руками. Тогда «деталь написала в чужой стат»
физически невозможно, а не запрещено правилом.

⚠ Но одного этого мало: гнездо 4 через шанс статуса всё равно сдвигает ДПС. Поэтому сторож
формулируется не как «гнёзда 2–4 не пишут в `damagePct`/`attackSpeed`», а как
**«суммарный сдвиг ДПС от гнёзд 2–4 на сетке сборок ≤ 3 %»**, и мерится он на реальном бою
(`session/microFight.ts`), а не закрытой формулой.

## 4. Гнездо 1 — ударная часть: урон ↔ скорость

Одна зеркальная пара, **±10 п.п. множителя урона против ∓8 % скорости атаки**.

| Точка оси | Множитель урона | Скорость | Кому |
|---|---|---|---|
| **τ = +1** тяжёлая | **+10 п.п.** | **−8 %** | крит-билды, кровотечение (оно считается от РАЗМЕРА удара), редкие крупные удары |
| **τ = 0** ровная | — | — | дефолт |
| **τ = −1** лёгкая | **−10 п.п.** | **+8 %** | статусы и проки за удар, вампиризм, серии ударов, вставки «при касте» |

**Почему проценты, а не плоский урон.** Удар = `(урон вещи + вклад атрибутов) × (1 + бонусы)`.
Доля самой вещи гуляет втрое: у длинного меча на 10-м уровне 0.40, на 80-м 0.31, у кинжала
0.13. Торгуй лезвие плоским уроном — скорость выигрывала бы всегда и у всех.

**Замер разброса** на сетке «бонус урона 0…0.9 × бонус скорости 0…0.9»:

| Пара | Худший угол сетки | В объявленном конверте | На типовых сборках |
|---|---|---|---|
| ±15 / ∓12 (прежняя) | **19.2 %** | 12.5 % | 7.8 % |
| **±10 / ∓8 (принята)** | 12.3 % | **7.5 %** | **4.4 %** |
| ±7 / ∓6 | 8.6 % | 5.2 % | 3.1 % |

Конверт объявляется явно: **разброс ДПС ≤ 8 % при бонусе урона D ∈ [0.3, 1.5] и бонусе
скорости S ∈ [0.05, 0.6]**. Без объявленного конверта фраза «разброс ≤ N %» бессмысленна:
у любой аддитивной пары есть угол, где она врёт. Пара ±7/∓6 дала бы буквальные 6 %, но там
ось перестаёт читаться в тултипе.

⭐ **Статусы едут на этой оси сами, и это ответ на просьбу «шанс эффекта с противовесом».**
Статусы катаются ЗА УДАР, значит темп ими уже торгует: замер ступеньки 1.00 → 1.05 удара/с
даёт **+62 % стаков раны и +41 % кровотечения при НЕИЗМЕННОМ ДПС**. Подпись так и пишется:

> **Лёгкий клинок** — взмахов больше: статусы, вампиризм и проки срабатывают чаще. Каждый удар мельче.
> **Тяжёлый клинок** — удар крупнее: крит и кровотечение считаются от его размера. Взмахов меньше.

⚠ **Второй оси у этой детали нет.** Отдельная ось «заточка» (статус против крита и блока)
рассматривалась и отвергнута: 5 × 5 = 25 ячеек вместо 5, три числа в тултипе вместо одного,
и главное — замер показал, что при дуал-вилде два «зазубренных» клинка складывают вклады и
дают +5.8 % вместо обещанных +3.4 %. Замок «одна ось ДПС» ломается не чужой деталью, а второй
осью на той же самой.

⚠ **Дуал-вилд удваивает всё, что деталь запекает.** `combatStatsOf` собирает ОДИН стат-блок
из обеих рук, одноручных баз 22 из 50. Зеркальная пара 10/8 в двух руках становится 20/16 и
даёт разброс 15.8 % вместо 7.5 %. Значит инвариант объявляется **на руку**, а дуал мерится
отдельным прогоном. Форма слотов и блок считаются по ГЛАВНОЙ руке — иначе четыре слота
становятся восемью.

## 5. Гнездо 2 — держак: дальше по одному ↔ шире по многим

### 5.1 Ближний бой: площадь-нейтральная пара

`meleeSwing` бьёт **всех** монстров в секторе. Площадь сектора = `дуга × дальность²`. Значит
честная пара обязана держать произведение постоянным:

| Точка оси | Дальность | Дуга | Площадь | Кому |
|---|---|---|---|---|
| **+1** длинный | **×1.12** | **×0.797** | 1.000 | достать первым, бить из второй линии, одиночные цели |
| **0** обычный | — | — | 1.000 | дефолт |
| **−1** короткий | **×0.89** | **×1.26** | 0.998 | толпы: задеть троих одним взмахом |

⚠ **Прежние числа были дырой.** «+20 % дальности ↔ −20 % дуги» даёт `0.8 × 1.2² = 1.152`
против `1.25 × 0.85² = 0.903` у короткой — то есть длинная сметала на **27.6 % больше
площади**. При пачках по 3–6 монстров это прямой ДПС, почти втрое сильнее всей оси лезвия.

⚠ **Один и тот же рычаг стоит разного на разных классах.** У топоров `arcMult` уже 1.5–2.0
(полудуга до 1.6 рад ≈ 183° полного сектора) — там прибавка дуги почти ничего не даёт, а у
мечей даёт много. Поэтому итоговая полудуга клампится, а сторож мерит **число задетых целей
в симе**, а не формулу.

### 5.2 Стрелковое и магическое: честного рычага сегодня нет

Замер: снаряд живёт `PLAYER_PROJ_SPEED 440 × PROJ_TTL 2.5 = 1100 px` (магический болт 1150)
при зрении монстра 240–320 px. Стрелять дальше, чем видишь, можно уже вчетверо — **+20 %
дальности не покупают ничего**. Поля «разброс» у оружия нет вовсе. А `projectileHit`
сравнивает расстояние ТОЛЬКО с `proj.radius` (16 px) и радиус цели игнорирует, то есть
радиус — это ВЕСЬ коридор попадания, и «радиус ×1.25» было бы второй осью ДПС под видом
геометрии.

Рабочий кандидат уже лежит в коде: **`proj.pierce`** — снаряд летит сквозь цель, `hitIds`
не даёт бить дважды. Сегодня это поле СКИЛЛА. Чтобы оно стало честной осью держака, нужен
один добавок: **затухание урона по числу пройденных целей**.

| Точка оси | Что делает | Цена |
|---|---|---|
| **+1** одна цель | снаряд встаёт в первой цели, урон полный | по толпе бьёт одного |
| **−1** пробойный | летит сквозь, **урон × 0.65 за каждую пройденную цель** | одиночной цели — как обычный |

Это точный аналог дуги: больше целей — меньше на каждую, суммарная «площадь» постоянна.
Стоит примерно десяти строк в `session.ts` (`damage × 0.65 ** hitIds.length`), и до этой
правки гнездо 2 у 20 баз из 50 честно объявляется **косметическим** — меш и имя, без обещаний.

## 6. Гнездо 3 — обвязка: форма ёмкости аффиксов

Ковка выдаёт **обычную вещь** (0 аффиксов) с записанной на ней ЁМКОСТЬЮ — парой «сколько
префиксов, сколько суффиксов». Редкость поднимается отдельным глаголом (§6.3).

### 6.1 Потолок выводится из дропа, а не калибруется

Найденный редкий: 3–5 аффиксов, максимум 3 префикса и 3 суффикса (`rarities.json`). Прогон
самого `rollAffixes` даёт частоты форм у найденных редких:

| Форма | Встречается у редких | Множитель цены M = 1/частота |
|---|---|---|
| 1+1 | 91.7 % | 1.09 |
| 2+1 | 68.8 % | 1.45 |
| **2+2** | **45.8 %** | **2.18** |
| 3+0 | 31.2 % | 3.21 |
| **3+1** | **27.1 %** | **3.69** |
| **3+2** | **16.7 %** | **5.99** |
| 3+3 | **0 %** | — (невозможна) |

⭐ **Отсюда всё и выводится.** Потолок ковки — (3,2) и (2,3), потому что 3+3 дроп не даёт
вовсе. Цена формы — во сколько раз реже дроп даёт такую же или лучшую. Перекошенная форма
дороже сбалансированной при том же числе слотов, и «заплатил больше» перестаёт быть просто
«купил ещё слот».

### 6.2 Потолок ёмкости растёт со ступенью вещи

| Ступень вещи | Потолок Σ | Доступные формы |
|---|---|---|
| t0–t1 | 2 | 2+0 · 1+1 · 0+2 |
| t2 | 3 | 3+0 · 2+1 · 1+2 · 0+3 |
| t3–t4 | 4 | 3+1 · **2+2** · 1+3 |
| t5–t6 | 5 | **3+2** · 2+3 |

⚠ На полной ёмкости форм всего ДВЕ: «равная» схлопывается, потому что 3+3 невозможна.
Обвязка интереснее всего на Σ=3 и Σ=4. Это ограничение данных, а не схемы, и в интерфейсе
ковки «равную» на Σ=5 рисовать нельзя.

**Что игрок реально получает** (замер по весам аффиксов, полезность «билду», 200 000 бросков):

| Что | Полезных аффиксов | Против среднего дропа |
|---|---|---|
| Средний найденный редкий | **2.22** | — |
| Скованная 2+2 | **2.21** | −0.5 % |
| Скованная 3+1 | 2.24 | +1 % |
| Скованная 3+2 | **2.78** | **+25 %**, цена ×6 |

⚠ 3+1 почти не отличается от 2+2, потому что `cruel`, `merciless` и `warlords` лежат в одной
группе `ed` — второй множитель урона взять негде. Это баг данных, и он в списке долгов (§20).

### 6.3 Новый глагол «зачаровать»

Глаголов кузницы сегодня четыре (`forgeUpgrade`, `forgeReroll`, `forgeSalvage`, `forgeRepair`),
и глагола «поднять редкость» среди них нет. Вводим **один**: `forgeEnchant` с целевой
редкостью сразу.

* Лестницу из двух покупок (normal→magic, потом magic→rare) не делаем: она даёт два действия
  и ноль решений — никто не остановится на magic, имея золото на rare.
* Движок не меняется ни на строку: `rollAffixes` (`itemgen.ts:479`) **уже** принимает `slots`
  отдельным аргументом. При `{ minAffixes = maxAffixes = P+S, maxPrefix = P, maxSuffix = S }`
  цикл физически не может лечь другим сплитом.
* Глагол сезона 2 («улучшение аффиксов») он не съедает: зачарование катает всё заново,
  улучшение двигает ЗНАЧЕНИЕ внутри уже сохранённого аффикса.
* ⚠ **В том же коммите обязаны поехать две правки.** `forgeReroll` берёт `minAffixes`/
  `maxAffixes` прямо из `rarities` и снесёт купленную форму первым же нажатием (шанс вернуть
  ровно 3+2 — 16.7 %). `forgeGold` читает ТЕКУЩУЮ редкость и даст скидку ×2.4 ровно на самом
  дорогом действии.

## 7. Гнездо 4 — оголовье: укус ↔ упор

Здесь живут обе просьбы владельца — «шанс наложения эффекта с противовесом» и «обыграть
блок». Ось одна: **чаще вешаешь статус ↔ крепче держишь удар**.

### 7.1 Укус — рычаг по грани, а не одно число

Грань принадлежит ОРУЖИЮ (кинжал колет, меч режет, топор рубит, булава дробит) — на ней висят
анимация, звук и ветки пассивок, деталь её не меняет. Оголовье двигает ШАНС или СИЛУ статуса
этой грани. Магнитуда **пер-грань**, потому что одна общая ручка стоит разного:

| Грань / стихия | Статус | База | Стаков при 1 уд/с | Рычаг «укуса» | Чем это является |
|---|---|---|---|---|---|
| Режущий (мечи, глефа) | кровотечение | 0.25 | 1.51 из 5 | `bleedChancePct` **+0.25** | ДПС во времени |
| Рубящий (топоры, алебарды) | увечье | 0.50 | **3.65 из 5** | `sunderPowerPct` **+0.15** | +получаемый урон |
| Дробящий (булавы) | ошеломление | 0.60 | **6.25 из 8** | `dazePowerPct` **≤ +0.06** | контроль + броня |
| Колющий (кинжалы, копья) | рана | 0.20 | 0.77 из 4 | `woundChancePct` **+0.50** | чистая оборона, ДПС не двигает |
| Огонь | поджиг | 0.10 | 0.30 из 3 | `burnChancePct` **+0.50** | ДПС во времени |
| Яд | отравление | 0.10 | 0.40 из 5 | `poisonChancePct` **+0.60** | ДПС во времени |
| Молния | шок | 0.12 | 0.36 из 2 | `shockChancePct` **+0.60** | +получаемый урон |
| Холод | заморозка | 0.15 | 0.30 из 1 | `freezeChancePct` **+0.50** | контроль |

⚠ **Магнитуды посчитаны по РЕАЛЬНОЙ механике стаков, и это важно.** `addDebuffStack` обновляет
ОБЩИЙ таймер всего стака, а не таймер на стак — поэтому стаки копятся почти до капа и
сбрасываются целиком только при паузе длиннее `durationMs`. Наивная модель «шанс × темп ×
длительность» даёт увечью 2.0 стака вместо реальных 3.65, ошеломлению 2.4 вместо 6.25 — и все
магнитуды, посчитанные по ней, завышены в 1.5–2 раза.

⚠ **У рубящего рычаг РАЗВОРАЧИВАЕТСЯ с темпом:** шанс ×1.5 стоит +4.8 % ДПС при 1.0 уд/с и
всего +1.5 % при 1.4 уд/с, потому что стаки уже у потолка. Значит гнёзда 1 и 4 взаимодействуют,
и сторож обязан мерить ДПС **с включёнными статусами** на реальном бою, а не по формуле.

⚠ **Статус у 20 баз из 50 не накладывается вовсе:** у луков, арбалетов, жезлов и посохов нет
поля `physSub`. Магическим грань заменяет стихия (`damageType`), а стрелковым — нечем; у них
«укус» работает только если оружие несёт стихию с аффикса.

### 7.2 Упор — блок, и он требует правки данных

| Точка оси | Ближний бой | Лук | Арбалет | Магическое |
|---|---|---|---|---|
| **+1** упор | `blockChance` **+0.02** | `interruptResist` **+0.12** | блок ложа **+0.02** | `blockChance` **+0.02** |
| **−1** укус | блок **−0.02**, рычаг статуса на полную | стойкость 0 | блок −0.02 | блок −0.02 |

Цена стороны: **+2.7…3.3 % эффективного HP** против **∓1…2 п.п. ДПС**. Настоящая, но не
решающая развилка — ровно то, что нужно.

⚠⚠ **«У оружия есть свой небольшой шанс блока» — сегодня неверно для 44 баз из 50.** Замер:
блок стоит ровно на шести — short-sword .08, long-sword .08, greatsword .06, short-spear .05,
mace .04, dagger .03. У ВСЕХ топоров, алебард, луков, арбалетов, жезлов, посохов и у гладиуса
с клеймором блока нет вовсе. Пока это так, «упор» у 44 баз платит нулём: `blockChance`
клампится снизу нулём (`stats.ts:150`), то есть отрицательный мод съедается молча и деталь
получает выгоду бесплатно.

**Предлагаемая лестница блока по классу** — но это НЕ правка json на глаз:

| Класс | Сейчас | Предлагается | Класс | Сейчас | Предлагается |
|---|---|---|---|---|---|
| `sword` | .08/.08/.06, у 2 из 5 — ноль | **.08** | `mace` | .04 у 1 из 5 | **.04** |
| `spear` | .05 у 1 из 5 | **.06** | `axe` | ноль у всех | **.03** |
| `halberd` | ноль у всех | **.05** | `crossbow` | ноль у всех | **.03** |
| `staff` | ноль у всех | **.05** | `wand` | ноль у всех | **.03** |
| `dagger` | .03 у 1 из 5 | **.04** | `bow` | ноль | **0 — лук не парирует** |

⚠ Блок гасит урон **ПОЛНОСТЬЮ** (`resolveAttack`, кап 0.75). Долить 0.03 бойцу с двуручным
топором без щита = **+3.1 % eHP всем сразу**, а со щитом 0.30 → 0.33 это +4.5 %. Это глобальный
бафф выживаемости, и он требует прогона сима, а не одной правки конфига. До него гнездо 4
работает только на шести базах.

⚠ `interruptResist` не выдаёт сегодня **ни один из 38 аффиксов** — стат приходит только с
пассивок. Чтобы «упор» лука не создавал стата, которого нет в дропе, в `affixes.json` нужен
суффикс: 2 ступени, 0.04–0.08 при ilvl 1 и 0.08–0.15 при ilvl 16, `appliesTo: ["weapon"]`.

## 8. Ловкость или сила — решает ЧЕРТЁЖ, а не деталь

Вес оружия задаёт, от какого атрибута оно кормится. Лестница ровная, от чистой ловкости
к чистой силе, плюс две магические ветки:

| Вес | Ловкость | Сила | Интеллект | Масса | Примеры |
|---|---|---|---|---|---|
| **Сверхлёгкое** | 1.0 | — | — | 3 | кинжалы, короткий лук |
| Лёгкое | 0.65 | 0.35 | — | 6 | короткий меч, гладиус, ручной топор |
| Среднее | 0.5 | 0.5 | — | 12 | длинный меч, боевая секира, копьё |
| Массивное | 0.35 | 0.65 | — | 18 | двуручный меч, алебарда, осадный арбалет |
| **Тяжёлое** | — | 1.0 | — | 25 | боевой топор, молот, длинное копьё |
| Мистическое | 0.4 | — | 0.6 | 6 | жезлы |
| Волшебное | — | — | 1.0 | 8 | посохи |

Вклад в удар при чистом билде (150 основного против 30 второго) и при гибриде (90/90):

| Вес | Чистая сила | Чистая ловкость | Гибрид |
|---|---|---|---|
| Сверхлёгкое | 15 | **75** | 45 |
| Лёгкое | 36 | 54 | 45 |
| Среднее | 45 | 45 | 45 |
| Массивное | 54 | 36 | 45 |
| Тяжёлое | **75** | 15 | 45 |

⭐ **Эту ось нельзя купить деталью, и это сознательно.** Двигай вес деталь — чистый билд
всегда сдвигал бы оружие к своему атрибуту и получал +30…40 % вклада даром. Хочешь меч под
ловкача — куёшь короткий меч, а не длинный. Выбор при этом честный: гибрид получает ровно 45
на любом весе, чистый билд — свой край лестницы.

⚠ **Масса остаётся СЛЕДСТВИЕМ модели, а не торгуемой колонкой.** Она лежит в предмете строковым
идентификатором веса (`WeaponWeight = string`), записать в неё «×1.6» физически нечем; в движке
она используется для расталкивания в толпе и для нокдауна, потолок которого — +2.37 % урона.
В подписи гнёзд нокдаун не обещаем вовсе.

## 9. Форма детали: вариантов сколько угодно

⭐ **Вариант — это ТОЧКА на оси своего гнезда плюс имя и меш.** Числа выводятся из поля
`axis` (−1…+1) умножением на шаг гнезда; руками в вариант не пишется ни одно число. Поэтому
вариантов может быть сколько угодно, а балансная поверхность остаётся одной таблицей на
четыре строки. Контент растёт именами и силуэтами, баланс — нет.

**Каталог ударного гнезда меча** (грань «режущий», числа общие для всех классов):

| Вариант | τ | Урон | Скорость | Редкость | Подпись в UI |
|---|---|---|---|---|---|
| Широкое | +1.0 | +10 п.п. | −8 % | обычный | удар крупнее, взмахов меньше |
| Фальшион | +0.6 | +6 п.п. | −5 % | нечастый | тяжёлая кромка: рубит глубже, ведётся медленнее |
| Ромбическое | +0.3 | +3 п.п. | −2 % | обычный | чуть тяжелее в кисти |
| Прямое | 0 | — | — | обычный | эталон |
| Ложчатое | −0.3 | −3 п.п. | +2 % | нечастый | долы снимают вес, темп чуть выше |
| Узкое | −0.6 | −6 п.п. | +5 % | обычный | взмахов больше, каждый мельче |
| Изогнутое (ятаган) | −0.8 | −8 п.п. | +6 % | нечастый | тянет рез: серии ударов и статусы чаще |
| Плоское | −1.0 | −10 п.п. | +8 % | редкий | самый быстрый клинок в пуле |

Тот же приём на других классах — меняются имя, силуэт и грань, не числа:

| Класс | Гнездо 1 зовётся | Варианты (примеры) |
|---|---|---|
| Топор | Полотно | бородовидное · клиновое · широкое · чекан · двулезвийное |
| Булава | Било | шестопёр · гранёное · шаровое · клевец · ребристое |
| Копьё | Перо | листовое · гранёное · крылатое · иглоподобное · трёхгранное |
| Лук | Плечи | прямые · рекурсивные · короткие · длинные · усиленные |
| Посох | Навершие-фокус | шар · кристалл · череп · кольцо · венец |

**Сколько вариантов и чьи это пулы.** Гнездо 1 класс-специфично (силуэт — это и есть класс),
остальные три группируются по родству: рукоять общая у меча, кинжала, булавы и жезла; древко —
у копья, алебарды и посоха. При 5–8 вариантах на гнездо выходит порядка 100 записей и столько
же мешей. Художественный объём реален, поэтому §18 фазирует: сперва гнездо 1, остальные —
общим мешем с тинтом.

## 10. Материал детали: полоса ступеней

У детали две независимые оси: **форма** (характер) и **материал** (какой ступени вещь из неё
можно собрать). Полосы ступеней **перекрываются** — на каждом шве доступны два материала:
дешёвый на своём потолке и дорогой на своём полу.

⭐ **И перекрытие — это настоящий выбор, а не текстура.** Материал задаёт не только пол, но и
ПОТОЛОК вещи: сковав t3 из уклада (его потолок), ты получаешь дешёвую вещь, которую уже никогда
не поднять; сковав t3 из дамаска (его пол), платишь дороже, но оставляешь запас — эту вещь
потом поднимет `forgeUpgrade` до t4 и t5.

### 10.1 Полоса одна и та же у всех семей

Ступень `k` строит вещи тиров `t(k) … t(k+1)`; первая дотягивается вниз до t0. Больше конфигу
о диапазонах знать нечего — полоса выводится из номера ступени, полей `minItemTier`/`maxItemTier`
заводить не надо.

| Ступень предмета | ст. 1 | ст. 2 | ст. 3 | ст. 4 | ст. 5 | На выбор |
|---|---|---|---|---|---|---|
| **t0** Убогий | ✔ | — | — | — | — | один |
| **t1** Старый | ✔ | — | — | — | — | один |
| **t2** Крепкий | ✔ потолок | ✔ пол | — | — | — | **два** |
| **t3** Отличный | — | ✔ потолок | ✔ пол | — | — | **два** |
| **t4** Мастерский | — | — | ✔ потолок | ✔ пол | — | **два** |
| **t5** Элитный | — | — | — | ✔ потолок | ✔ пол | **два** |
| **t6** Мифический | — | — | — | — | ✔ | один |

⭐ Отсюда бесплатно следует согласованность гнёзд: «сталь уже дамасская, а древко ещё
трухлявое» невозможно **по построению**, а не по присмотру — полоса общая, рассинхрон нечем
создать. Что игрок видит на t3 сразу по всем гнёздам:

| Гнездо | Дешёвый (на своём потолке) | Дорогой (на своём полу) |
|---|---|---|
| Лезвие · `iron` | Кричное железо | **Уклад** |
| Древко · `wood` | Колотый ясень | **Граб в олифе** |
| Плечи · `stave` | Тисовый стан | **Рог и жила** |
| Прибор · `trim` | Литая бронза | **Воронёная сталь** |
| Фокус · `focus` | Гагат | **Обсидиан** |
| Хват · `hide` | Дублёная кожа | **Варёная кожа** |
| Тетива · `cloth` | Сырая жила | **Льняное полотно** |

⭐ **Фэнтези на доске ноль ступеней.** История закрывает t0…t6 целиком, включая верх: булат,
золочёный прибор, шёлк, пружинная сталь. «Небесное железо», «Эфирное стекло», «Рог Разлома» и
«Окаменелое древко» с лестниц СНЯТЫ — они уходят в уникумы и дроп с боссов, где им и место.
Один материал не может стоять в двух семьях сразу (формула выдаст два разных id для одной вещи),
а именно это и случилось бы с небесным железом.

### 10.2 Чёрный металл `iron` — кромка и масса

Каркас владельца проверен по источникам и исправлен в одном месте: «низкокачественное» и
«кричное» железо — это одно и то же (кричное и есть низкокачественное). Настоящая разница идёт
по РУДЕ, а между кричным железом и дамаском зияла целая эпоха — туда встала недостающая
ступень «уклад», момент, когда железо впервые начало брать закалку.

| Материал | id | Полоса | Что это исторически | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Болотное железо** | `iron-1` | t0–t2 | Сыродутный горн, болотная и дерновая руда. Железо в нём не плавится — выходит крица, пористый ком со шлаком. Болотная руда богата фосфором | Руда валяется под ногами | Фосфор даёт хладноломкость — трескается при холодной ковке. Шлаковые включения работают как надрезы. Углерода нет, закалку не держит |
| **Кричное железо** | `iron-2` | t2–t3 | Тот же горн, но нормальная руда и многократная проковка в сварочном жару, выжимающая шлак. Волокнистая структура, «древесный» излом | Шлак выжат: металл вязкий — гнётся, но не колется | Углерода всё ещё нет: кромка мнётся, а не режет. Десятки проковок на брусок |
| **Уклад** | `iron-3` | t3–t4 | Русская сырцовая сталь: цементация кричного железа в горне (европейский аналог — «пузырчатая» сталь) | **Впервые берёт закалку** — кромка держит остроту | Углерод сидит только в корке и набрался неровно; закалённый слой выкрашивается. Монолитом не ковали, наваривали на железо |
| **Сварочный дамаск** | `iron-4` | t4–t5 | Узорчатая сварка, Европа сер. I тыс. — XI в. Пакет из полос разного сорта, скрученный и сваренный, с наварными кромками; японский родственник — кобусэ | Выигрыш КОНСТРУКТИВНЫЙ: вязкий сердечник не даёт переломиться, твёрдая кромка режет. И это ответ на непостоянное сырьё: перемешивая сорта, кузнец усредняет что досталось | По металлографическим обзорам ранних клинков сам узор прочности не добавляет — то же даёт простая наварка без витья. Десятки швов — десятки мест расслоения |
| **Булат** | `iron-5` | t5–t6 | Тигельная сталь: индийский вутц, дендритный узор от ликвации. На Ближнем Востоке его клинки и звались «дамасскими». Аносов повторил технологию в Златоусте в XIX в. | Ни шлака, ни швов — монолит, которому нечему расслаиваться. Карбидные полосы работают как микропила: кромка режет дольше при той же заточке | Узкое окно ковки: перегрел — узор пропал навсегда, недогрел — высокоуглеродистый брусок трескается под молотом. Карбиды твёрдые, но хрупкие. И слиток мал — вутц-лепёшка весила порядка килограмма, то есть **один слиток — один клинок** |

### 10.3 Древесина `wood` — древко, топорище, ложе, ствол

Самая широкая семья: восемь классов из десяти.

| Материал | id | Полоса | Что это | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Сырая сосна** | `wood-1` | t0–t2 | Мягкая хвоя, не просушенная | Растёт везде, стоит ноль | Вминается под ударом, колется вдоль, при высыхании даёт усадку — голова расшатывается |
| **Колотый ясень** | `wood-2` | t2–t3 | Канонический черенковый сорт. Ключ не в породе, а в РАСКОЛЕ: колотая заготовка идёт по волокну, пилёная режет годовые кольца поперёк | Не разлетается от удара, а пружинит | Колоть можно только прямослойный ствол без сучьев — бо́льшая часть бревна в отход |
| **Граб в олифе** | `wood-3` | t3–t4 | Плотная древесина, пропитанная олифой: варёное льняное масло полимеризуется ВНУТРИ волокон и запечатывает дерево от влаги | Держит тяжёлую голову; пропитка снимает главную беду дерева в подземелье — сырость | Плотнее и тяжелее ясеня; масло надо сушить сезон, готовых заготовок мало |
| **Морёный дуб** | `wood-4` | t4–t5 | Дуб, пролежавший в болоте сотни и тысячи лет: танины реагируют с железом грунта, дерево чернеет и частично минерализуется | Плотность и стойкость, каких не даёт живое дерево. И он ЧЁРНЫЙ — читается на модели без единого слова | Его не растят, его находят; сушить надо крайне осторожно, брака много |
| **Клееное древко** | `wood-5` | t5–t6 | Не порода, а технология: для длинных японских яри древки клеили из полос дерева и бамбука и стягивали кольцами | Лучшее отношение прочности к весу на всей лестнице: слабое место одной планки перекрыто соседней | Неделя работы против дня; клеевой шов расслаивается от сырости и жара |

⚠ «Ведьмины» породы магической линии — лещина, тёрн, кладбищенский тис, эбен — становятся
**формами** ствола посоха, а не отдельной лестницей. Дерево есть дерево; двух семей под одну
роль быть не должно.

### 10.4 Плечи и дуги `stave` — пружина, а не кромка

Отдельная семья, потому что от древка и от плеча просят ПРОТИВОПОЛОЖНОГО: древку нужна ударная
вязкость вдоль волокна, плечу — упругий возврат энергии. Тис как топорище так же плох, как
граб в качестве лука.

| Материал | id | Полоса | Что это | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Вязовое плечо** | `stave-1` | t0–t2 | Лучшее европейское дерево для лука ПОСЛЕ тиса; мезолитические луки хольмегордского типа сделаны из него | Доступен, прощает ошибки мастера | Слабее тиса при той же длине, набирает влагу |
| **Тисовый стан** | `stave-2` | t2–t3 | Тис — природный слоёный материал: заболонь на спинке работает на растяжение, ядро на животе — на сжатие | Сама природа сделала композит | Тис редок и капризен; сучок в заготовке — брак |
| **Рог и жила** | `stave-3` | t3–t4 | Составной лук: деревянное ядро, роговая пластина на животе, сухожилие на спинке, рыбий клей. В некоторых дугах вместо рога — китовый ус | Мощнее при вдвое меньшей длине — можно стрелять с коня | Сырость расклеивает; изготовление занимает год |
| **Варёный рог** | `stave-4` | t4–t5 | Тот же композит, но с отобранным и проваренным рогом и многослойной обмоткой | Ровнее по силе и стабильнее к погоде | Ещё дольше и ещё дороже; сушка годами |
| **Пружинная сталь** | `stave-5` | t5–t6 | Стальная дуга арбалета к XV в. — и **стальной лук тоже существовал**: индо-персидский каман из кованых стальных плеч, соединённых в рукояти, лежит в музейных собраниях и применялся в бою | Сила натяжения, недостижимая органике; не боится сырости | Руками уже не взвести — нужен ворот или козья нога. Ломается сразу и насовсем, а не расслаивается постепенно |

⚠ Посылка «стальных луков история не знает, сталь — ответ только для арбалета» оказалась
неверна и снята проверкой. Поэтому фэнтезийная верхушка плечам не понадобилась, а асимметрия
между луком и арбалетом исчезла сама.

### 10.5 Прибор `trim` — оснастка и противовес

Исторически гарда, навершие, обоймица, ланцеты, подток и замок арбалета — это один «прибор»:
один мастер, один металл, один гарнитур. Поэтому одна семья кормит **два гнезда из четырёх
у девяти классов из десяти** — это самый расходуемый материал в игре, и цену ковки надо
раскладывать по семьям неравномерно (§13).

| Материал | id | Полоса | Что это | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Чёрное железо** | `trim-1` | t0–t2 | Кованое железо из-под молота, окалина не снята. Вопреки фэнтези-привычке к бронзовым эфесам, железо и было нормой для прибора европейского меча | Есть везде; принимает прямой удар клинка лучше цветного металла | Ржавеет от пота и крови — единственный материал линии, требующий ухода просто чтобы остаться собой |
| **Литая бронза** | `trim-2` | t2–t3 | Прибор, отлитый одним куском: бронза берёт тончайший оттиск формы | Не ржавеет; сложная форма за одну плавку — кольца, дужки, ажур, которые из железа пришлось бы ковать по частям | Мягкая: гарда мнётся от прямого удара, навершие разбивается при расклёпке хвостовика. И тяжелее железа при той же форме |
| **Воронёная сталь** | `trim-3` | t3–t4 | Стальной прибор под управляемым слоем чёрного оксида. Воронили не только доспех — контраст полированного и синего был штатным приёмом отделки эфесов | Сталь держит удар там, где бронза мнётся; воронение снимает ржавчину в массе вещи, а не краской поверх | Плёнка не вечна, а восстанавливать её — снова греть прибор, и перегрев отпускает закалку. Красивый прибор стареет и чинится хуже, чем портится |
| **Насечной прибор** | `trim-4` | t4–t5 | Золотая или серебряная проволока, вбитая в насечённую воронёную сталь: на Востоке koftgari, у нас насечка или таушировка | Основа остаётся сталью — прочность не потеряна ни на грамм; вбитое золото не окисляется, рисунок переживает вещь. И это ПОРТАТИВНАЯ ЦЕНА: прибор с серебром — деньги, которые носят на рукояти | Дорога не проволока, а работа: рисунок режется и набивается вручную. «Ложная» насечка сидит в канавках глубиной в доли миллиметра и вытирается ладонью за годы |
| **Золочёный прибор** | `trim-5` | t5–t6 | Огневое (ртутное) золочение — господствующий способ от античности до XIX в. | Вечное покрытие, вплавленное в металл, а не нанесённое на него | Ртутные пары. Ремесленное предание говорит, что золотильщики редко доживали до сорока; проверяемые вехи рядом — запрет ртутного золочения во Франции в 1830 г. и переход на гальванику с 1840-х |

### 10.6 Фокус `focus` — сигнатурное гнездо магии

Реальной «магической металлургии» нет, поэтому лестница опирается на материалы, которым
исторически приписывали силу, и на реальные ремёсла. Правдоподобие здесь держится не на
физике, а на том, что люди действительно так считали.

| Материал | id | Полоса | Что это | Чем лучше | Чем платит |
|---|---|---|---|---|---|
| **Стеклянная паста** | `focus-1` | t0–t2 | Римляне лили цветные пасты, подделывая изумруд и лазурит; Плиний писал, что нет обмана прибыльнее подделки самоцветов | Льётся в форму, а не режется из камня — дёшев и доступен учеником и в поле | Пузыри и муть внутри, трескается от нагрева, заряд держит слабо. Подделка и есть подделка |
| **Гагат** | `focus-2` | t2–t3 | Gagates по реке Гагас в Ликии. Беда Достопочтенный о британском гагате: «чёрный и искрящийся, горит в огне и нагретый отгоняет змей». Уитби — центр промысла и камень траура | Настоящий амулетный материал: электризуется от трения, лёгок и тёпл на ощупь. пятнадцати далеки.

### 10.8 Что уехало в ФОРМЫ, а не в ступени

Половина красивых материалов — это не качество, а характер, и им место на оси формы:

| Было предложено ступенью | Стало |
|---|---|
| Витая латунная и серебряная проволока на рукояти | **форма** оплётки поверх кожи — исторически проволоку мотали ПО коже, а не вместо неё |
| Лещина, тёрн, кладбищенский тис, эбен | **формы** ствола посоха и жезла |
| Кожа ската (самэгава) | **форма** хвата |
| Небесное железо, эфирное стекло, рог Разлома, окаменелое древко | **уникумы и дроп с боссов**, вне лестниц |

### 10.9 Разбор наконец видит ТИР

⚠ **Сегодня ступень выпавшего сырья задаёт ТОЛЬКО редкость вещи** (обычная → 1, магическая → 2,
редкая → 3), а тир на разбор не влияет вовсе: мифический обычный топор даёт ровно то же, что
убогий обычный топор. Пяти ступеней из трёх редкостей не выжать — формула обязана смотреть на тир.

⭐ **Решение не надбавкой, а ТОЖДЕСТВОМ: ступень сырья равна той, из которой эта вещь и была бы
собрана.** Полоса из §10.1 работает в обе стороны — два материала строят вещь тира X, те же
два из неё и выходят.

```
ступень = пол_полосы(тир вещи) + надбавка(редкость)
  пол_полосы:  t0,t1,t2 → 1 · t3 → 2 · t4 → 3 · t5 → 4 · t6 → 5
  надбавка:    обычная +0 · магическая +0.5 · редкая +1 · уникальная — не разбирается
  зажим:       потолком полосы (t0,t1 → 1 · t2 → 2 · t3 → 3 · t4 → 4 · t5,t6 → 5) и длиной семьи
  дробь 0.5 округляется ВЕРОЯТНОСТНО — тем же rng.chance, что уже стоит в salvageFromItem
```

| Тир вещи \ редкость | обычная | магическая | редкая |
|---|---|---|---|
| **t0–t1** | 1 | 1 | 1 *(зажато потолком)* |
| **t2** | 1 | 1 или **2** (монета) | **2** |
| **t3** | 2 | 2 или **3** | **3** |
| **t4** | 3 | 3 или **4** | **4** |
| **t5** | 4 | 4 или **5** | **5** Булат |
| **t6** | 5 | 5 | 5 |

Что эта формула даёт: булат физически недостижим ниже t5; низ лестницы не умирает, потому что
лестница сырья едет вместе с игроком, а цена ковки ОТНОСИТЕЛЬНАЯ (§13) — вещь тира X всегда
куётся из ступеней X−1 и X, то есть ровно из того, что на этом тире и падает; три редкости
остаются различимы внутри окна из двух ступеней (обычная — нижняя, редкая — верхняя,
магическая — монета).

⚠ **У надетой на монстра вещи тира нет вовсе.** Берём тир по уровню монстра из той же лестницы
`item-tiers` (высший, у которого `minItemLevel ≤ уровня`), а редкость — у КОНКРЕТНОЙ надетой
вещи, как сейчас. Новых чисел в баланс не добавляется: обе шкалы уже лежат в конфиге.

**Правки, все мелкие:**

| Где | Было | Стало |
|---|---|---|
| `schemas.ts` | `tier: z.number().int().min(1).max(3)` | `.max(5)` — **первым делом**: пока стоит 3, строки ступеней 4 и 5 конфиг молча теряет при загрузке |
| `salvage.ts` | `shiftTier(id, tier−1)` — сдвиг прибавкой | `setStep(id, ступень)` — абсолютный номер, с той же защитой «нет такой ступени — спускаемся до ближайшей» |
| `salvage.ts` | `tierOfRarity` → ступень 1/2/3 | `rarityStep` → надбавка 0 / 0.5 / 1; «уникальные не разбираются» читается из отдельного списка, а не из `<= 0` |
| `balance.json` | `salvage.rarityTier {normal:1,magic:2,rare:3,unique:0}` | `salvage.rarityStep {normal:0,magic:0.5,rare:1}` + `salvage.noSalvage: ["unique"]` |
| `salvage-rules.json` | 17 правил по старой анатомии | переписать по гнёздам §10.7 ⚠ и решить ЯВНО: номер в `materialId` больше не читается (его считает формула) — либо игнорировать цифру, либо завести поле `family` |
| `monster-gear.json` | 22 записи ссылаются только на `iron-1`, `wood-1`, `cloth-1`, `hide-1`, `plate-1` | ⚠ пока туда не добавлены `stave`, `trim`, `focus`, трёх новых семей в игре не будет ВОВСЕ — ровно та грабля, что уже ловилась коммитом `2fd6d96` |
| `craft-materials.json` | 15 строк | 40: ids не меняются нигде (кошельки в сейвах переживут), 11 переименований, 25 новых строк. Единственный сдвиг смысла — «Морёный дуб» уезжает с `wood-3` на `wood-4` |
| `craft-materials.json` | `usedFor` у `cloth`/`hide` = `armor` | `any`. В игровом коде поле не читается ни одной строкой — только фильтрами редактора, но их надо перепроверить |

### 10.10 Легенды, которые нельзя писать никогда

Красивые, широко повторяемые и неверные. Одна такая строка в тултипе обесценит остальные сорок.

| Не писать | Как правильно |
|---|---|
| «Дамаск резал шёлк, падающий в воздухе» | молва, а не свойство материала |
| «Секрет булата утрачен навсегда» | **производство прервалось, а не тайна исчезла** — тигельную сталь с дендритным узором воспроизвели в 1990-х и воспроизводят сейчас |
| «Викинги закаляли клинки в крови» | нет |
| «Японский меч складывали тысячу раз» | нет |
| «Кольчугу пробивал любой бодкин» | почти все исследованные бодкины оказались незакалёнными |
| «Шёлковая тетива стоила вдвое дороже лука» | на источниках этого нет; корректно — «из-за дороговизны шёлка тетивы из него встречались редко» |

⚠ **Числа без источника из документа сняты сознательно.** Линии чёрного металла и прибора
пришли без единой ссылки, поэтому из них убраны вторые значащие цифры (твёрдость, проценты
фосфора, точное окно ковки, даты Аносова) — правдоподобие держится на МЕХАНИЗМЕ, а не на
цифре, которую нечем подтвердить. Если числа понадобятся — сперва ссылка, потом строка.

## 11. Ступень вещи: из деталей и журнала

```
tierLo  = max(нижняя граница полос четырёх материалов)   ← ниже не собрать
tierHi  = min(верхняя граница полос, потолок журнала, base.maxTier)
tier    = выбор игрока в [tierLo, tierHi]
ilvl    = minItemLevel(tier)
```

Дальше всё едет по существующему руслу без единой новой кривой: `pickTierClamped` →
`statMult` масштабирует урон, `reqMult` — требования, кап `maxTotalRequirement`.

⭐ **Почему деталь носит ПОРОГ, а не собственную ступень.** Если бы у детали была своя ступень,
сборку «три дешёвые + одна t6» пришлось бы запрещать отдельным правилом. А так все четыре
детали куются НА СТУПЕНИ ВЕЩИ и по её цене — дешёвой t6-детали не существует как объекта.
Дыра закрыта по построению (Р6).

⚠ **`ilvl` берётся от ступени, а не от уровня героя.** Замер: `rollSpec` всегда берёт ЛУЧШУЮ
доступную ступень аффикса, а высшая по всем оружейным аффиксам — ilvl 24. Значит от t3 (ilvl 30)
и выше обе формулы дают одинаковые аффиксы, зато «по уровню героя» открывало бы станок: дешёвая
t0-рама на 90-м уровне получала бы топовые аффиксы и продавалась бы с прибылью.

⚠ **`retierItem` обязан заново применить детали.** Он пересобирает `baseStats` и `requirements`
ОТ БАЗЫ (`itemgen.ts:355`), то есть подъём ступени молча сотрёт запечённый вклад деталей —
причём поле `parts` при этом переживёт, и вещь будет выглядеть правильной.

## 12. Открытие деталей: журнал кузнеца

**Чертежей как предметов нет.** Разобрал вещь у кузнеца — открылась и её база, и четыре
детали, которые в ней стояли. Один глагол, один поток открытий, и каждый мусорный дроп
становится прогрессом.

### 12.1 Детали есть у каждого оружия, в том числе выпавшего

Чтобы «разобрал меч и открылись части, которые в нём были» не было фикцией, партсет должен
быть у любого оружия. Детали найденной вещи **выводятся детерминированно из неё самой**
(`baseId` + `tier` + сид от `uid`) — не катаются в момент разбора (иначе лотерея, нарушение Р3)
и не требуют миграции старых сейвов.

⚠ Вывод обязан быть СТАБИЛЬНЫМ: если дизайнер добавит вариант в гнездо и веса поменяются,
у всех мечей в сейвах молча переедут детали. Значит либо вывод идёт по замороженной версии
таблицы весов, либо `parts` записываются на предмет при первом же чтении.

### 12.2 Что помнит журнал

Журнал живёт **на аккаунте** (`AccountStash.forgeJournal?`, рядом с `materials?` и по той же
причине) — иначе каждый новый герой перефармливает каталог заново.

| Ось журнала | Что хранит | Как открывается |
|---|---|---|
| **Варианты** | множество открытых форм | первым же разбором вещи, где вариант стоял |
| **Потолок ступени** | одно число: высший тир, который игрок когда-либо разбирал | первым разбором вещи этого тира |
| **Счётчик мификов** | сколько вещей `origin ∈ {drop, chest, boss}` тира t6 разобрано | ворота t6 |

⚠ Счётчик по паре «вариант × ступень» рассматривался и отвергнут: он мёртв арифметически —
конкретный t6-вариант конкретного класса требовал бы десятков тысяч убийств.

### 12.3 Сколько это в убийствах

Замер на текущем темпе (443 убийства/ч, 53.2 вещи/ч):

| Редкость варианта | Вес в пуле | Ожидание | В часах | 95-й перцентиль |
|---|---|---|---|---|
| Обычный | 10 | 1 111 убийств | **2.5 ч** | 7.4 ч |
| Нечастый | 4 | 2 778 убийств | 6.3 ч | 18.5 ч |
| Редкий | 1 | 5 556 убийств | 12.5 ч | **36.4 ч** |

⭐ **Хвост распределения делает каталог издевательством, поэтому жалость — часть конструкции,
а не украшение.** Правило: **8 разборов оружия своего класса дают «эскиз»**, открывающий любой
неоткрытый вариант этого класса на выбор игрока. 2 667 убийств ≈ 6 ч — это потолок ожидания
вместо 36-часового хвоста.

⚠ **Полевой разбор** даёт 30 % сырья, но журналу — ПОЛНЫЙ зачёт: знание не делится пополам,
иначе каталог превращается в обязательную логистику «таскай всё в город». Открытие при этом
остаётся у кузнеца (решение владельца), а полевой разбор обязан **предупреждать**: «в этой
вещи неизвестная деталь». Без предупреждения он становится тихой ловушкой — игрок сжигает
единственный носитель штучной детали ради трети сырья и не узнаёт об этом никогда.

### 12.4 Ворота t6

Полоса t6 каждого гнезда открывается после **5 разборов мифических вещей в это гнездо** —
20 вещей на полный набор.

⚠⚠ **И это требование сегодня НЕ выполнимо, потому что магазин — бесконечный кран.**
`regenShop` зовётся на КАЖДЫЙ вход в город и катает 15 оружий; `generateItem` получает
`itemLevel: level + 1` и **не получает `tierLevel`**, поэтому `pickTierClamped` берёт высшую
доступную ступень ДЕТЕРМИНИРОВАННО — тогда как дроп передаёт `rollTierLevel`, бросок в окне
со смещением вниз. На 80-м уровне вся витрина — t6. При этом `shopItemValue` тира не видит
вовсе: `(15 + ilvl × 4 + аффиксы × 12) × priceMult`, то есть обычный t6 ≈ **339 золота ≈ 8
убийств**. Двадцать мификов покупаются за 163 убийства вместо 22 часов фарма.

Лечится двумя правками, обе полезны сами по себе: передать `tierLevel` в `regenShop` (одна
строка) и научить `shopItemValue` видеть тир. Плюс счётчик считает только вещи с полем
`origin ∈ {drop, chest, boss}` — новое поле, ставится в `generateItem`.

## 13. Цена

Две кассы, и они не пересекаются: **сырьё платится за ковку, золото — за зачарование.**

⭐ **Цена ковки ОТНОСИТЕЛЬНАЯ, а не абсолютная** — иначе низ лестницы умирает. У тира X
доступны ровно две ступени материала, X−1 и X, и платится вещь именно ими:

| Действие | Сырьё | Золото |
|---|---|---|
| **Ковка вещи тира X** (4 детали) | **30 единиц ступени X−1 + 10 единиц ступени X**, всё ×M (множитель формы из §6.1) | `300 × reqMult ступени`, плоско |
| Разложение по семьям — не поровну | сигнатурное гнездо **12 + 4** · геометрия **8 + 3** · прибор (два гнезда) **10 + 3** | — |
| **Зачаровать** до редкого | — | `100 × reqMult × priceMult × M` |
| Замена одной детали | 10 дешёвой + 3 дорогой | `100 × reqMult` |
| **Переплавить** | возврат 50 % дешёвой и 100 % дорогой | — |

**Цены продажи сырья** по пяти ступеням: **1 · 4 · 12 · 36 · 108**. Множитель ×3 не на глаз:
замер прихода за 100 убийств (126 / 21 / 8 по нынешним трём ступеням) при ценах 1/4/12 даёт
126 / 84 / 96 золота — поток от продажи почти ровный, и ×3 его ровным оставляет. Шестой
ступени нет намеренно: 330× вместо 108× превратило бы один стек верхнего сырья в состояние
и сделало бы продажу сырья главным источником золота — ровно против цели «золото остаётся
дефицитным всю игру».

⚠ Перемножать все множители подряд нельзя: вариант «30/10/4 × ёмкость × 1.6 двуручному ×
полосу тира» давал бы на t6 **1 728 ржавого железа и 230 калёной стали** при приходе 8 калёной
за 100 убийств — 2 900 убийств только на сырьё.

**Сторож против прачечной золота:** ковка t5 стоит 30×36 + 10×108 = **2 160** в золотом
эквиваленте, переплавка возвращает 15×36 + 10×108 = **1 620**. Денег не печатается — и это
надо проверять тестом на КАЖДОЙ паре соседних ступеней, а не только на верхней.

**Якорь:** `forgeUpgrade` до t6 стоит 2 000 золота. Ковка t6 верхней формы: 3 000 за саму
ковку плюс ≈ 14 400 за зачарование до редкого — около **17 400**, то есть порядка 200 убийств
на 80-м уровне. «Дорого очень» выполнено.

⚠ **Цену придётся перекалибровать после запуска экономики открытия.** Нынешние числа
откалиброваны на текущий приход (126 / 21 / 8 единиц трёх ступеней за 100 убийств), а
требование «разбирай, чтобы открывать детали» этот поток изменит.

## 14. Математика: детали запекаются в предмет

```
ковка:
  база     = чертёж (items-base.json)
  ступень  = из материалов и журнала (§11)
  статы    = scaleBaseStats(база, statMult ступени)
             + { damagePct: ±0.10, attackSpeed: ∓0.08 }   ← гнездо 1
             + { reachMult, arcMult }                      ← гнездо 2 (ближний бой)
             + { <грань>ChancePct | <грань>PowerPct, blockChance } ← гнездо 4
  affixCap = { prefix, suffix }                            ← гнездо 3
  parts    = четыре ИД (форма + материал)                  ← показ, модель, переплавка
  аффиксы  = НЕТ. Вещь выходит обычной
```

Детали не создают нового множительного слоя в бою: их вклад записывается в статы самого
предмета — туда же, где живут урон и скорость любой найденной вещи. Почему не «слой поверх»:
любой новый множитель пришлось бы вручную вкрутить в бой, в ИИ, в симулятор и в калькулятор
редактора; пропустишь одно — числа разойдутся молча.

⚠ **Сервер считает сам.** На предмете лежат только ИД деталей; значения выводятся из конфига
при ковке. Предпросмотр редактора и результат сервера считает ОДНА чистая функция
`craftWeapon` в `shared/formulas` — иначе окно обещает не то, за что игрок платит.

⚠ **Предпросмотр показывает ВИЛКУ, а не бросок.** Сервер катает `createRng(Date.now() & 0xffffff)`;
«видно в момент создания» — это видно, какая форма и какие диапазоны, а не что именно выпадет.

## 15. Три сквозных примера

Герой 40 уровня, длинный меч t4 (база 7–13 → 24–44), бонус урона +45 %, скорости +15 %.

### Быстрый меч под статусы
Плоский клинок (τ −1) · короткая рукоять · широкая гарда (1+3) · оголовье в укус

| | Найденный редкий | Скованный | Разница |
|---|---|---|---|
| ДПС | 122 | 121 | −1 % |
| Ударов в секунду | 0.92 | **1.01** | +9 % |
| Стаков кровотечения | 1.38 | **1.79** | **+30 %** |
| Площадь взмаха | ×1.00 | ×1.00 | площадь-нейтрально |
| Дальность / дуга | — | ×0.89 / ×1.26 | ближе, но шире |
| Форма | 2+2 (случайная) | **1+3 (выбрана)** | сопротивления и реген |

### Тяжёлый под один большой удар
Широкий клинок (τ +1) · длинная рукоять · узкая гарда (3+1) · оголовье в упор

| | Найденный редкий | Скованный | Разница |
|---|---|---|---|
| ДПС | 122 | 121 | −1 % |
| Урон одного удара | 133 | **145** | +9 % |
| Дальность / дуга | — | ×1.12 / ×0.797 | достаёт дальше, задевает уже |
| Блок | 0.08 | **0.10** | +2.6 % eHP |
| Форма | 2+2 | **3+1** | урон, крит, стихия |

### Попытка собрать имбу
Всё в урон: широкий клинок · длинная рукоять · узкая гарда · оголовье в укус

| Что игрок хотел | Что вышло |
|---|---|
| Сложить урон клинка и ещё урон рукояти | **Нечем.** Рукоять урона не даёт вовсе, и площадь взмаха у неё постоянна |
| Добрать урон статусом с оголовья | Можно — но оголовье тогда отдаёт блок в пол, и вещь становится стеклянной |
| ДПС | 121 против 122 — **−1 %** |
| Удар | +9 % на удар при −8 % частоты: тот же ДПС, иначе разложенный |
| Форма | 3+1: ни сопротивлений, ни регена |
| Геометрия | дальше, но уже: по пачке из пяти бьёт одного |

⭐ Имба не выходит **по построению**: складывать нечего. Крайняя сборка перекладывает тот же
ДПС в один крупный удар или в частые мелкие и платит за это геометрией, формой слотов и блоком.

## 16. Шесть замков против имбы

| Замок | Как работает | Чем проверяется |
|---|---|---|
| **Каркас — существующая база** | у скованного не может быть статов, которых нет у дропа | тест по всем 50 базам |
| **Одна ось ДПС** | `mods` детали выводятся из её `axis` × шага гнезда, руками не пишутся | сторож: суммарный сдвиг ДПС от гнёзд 2–4 ≤ 3 % на реальном бою |
| **Площадь взмаха постоянна** | `дуга × дальность² = const ± 3 %` | сторож мерит ЧИСЛО задетых целей в симе, а не формулу |
| **Вес не покупается** | ось «ловкость ↔ сила» живёт в чертеже | тест «детали не пишут в доли атрибутов» |
| **Потолок ёмкости выведен из дропа** | Σ ≤ 5, префиксов ≤ 3, суффиксов ≤ 3 — лимиты редкого | тест «ковка не даёт формы, которой нет у дропа» |
| **Переплавка вместо разбора** | у скованного свой глагол, журналу он не пишет | тест «ковка + переплавка не создаёт ни сырья, ни знаний» |

⚠ Последний замок важнее, чем кажется, и держит сразу две прачечные: сырья («скуй обычную →
разбери как редкую») и знаний («накуй t1 ради журнала»). Плюс переплавка обходит
`rerollLimit: 3` — единственное, что сегодня удерживает аффиксы от бесконечного пережимания;
её цена обязана быть не ниже цены перекатки.

## 17. Экран ковки: восемь действий, пять решений

```
Кузница → вкладка «Ковка»
  1. Чертёж:   [Длинный меч ▾]      открытые · режет · средний вес: сила и ловкость поровну
  2. Ступень:  [t4 Мастерский ▾]    доступно до t5 (журнал) · выше — разбери мифическую вещь
  3. Материал: [Уклад ▾]            ст. 3 · t3–t4 · дешевле · ⚠ потолок вещи t4
               [Сварочный дамаск]   ст. 4 · t4–t5 · дороже · вещь поднимется до t5
  4. Клинок:   [Широкое ▾]          удар крупнее, взмахов меньше
  5. Рукоять:  [Длинная ▾]          достаёт дальше, задевает уже
  6. Гарда:    [Узкая 3+1 ▾]        три префикса — урон, крит, стихия
  7. Оголовье: [Тяжёлое ▾]          держит удар крепче: блок 8 % → 10 %
  8. [Ковать]  24–44 урона · 1.24 уд/с · требования 115 · сырьё 45/15/8 · 1 380 золота
```

Полей восемь, но **осмысленных решений пять**: ступень и материал почти всегда берутся
лучшие доступные, а четыре гнезда предзаполнены прошлым выбором и меняются редко.

Правила экрана, купленные чужими ошибками:

* **Подпись говорит СЛЕДСТВИЕ с числом, а не стат.** Не «`+40 % bleedChancePct`», а «кровотечение
  вешается чаще: 1.4 → 1.8 стака». Строка каталога без подписи — незаконченная строка данных,
  и это закон схемы, а не пожелание.
* **Вилка видна до оплаты**, включая диапазоны будущих аффиксов.
* **Серая кнопка объясняет себя:** «не хватает 4 калёной стали», а не просто серый цвет.
* **Потолок материала предупреждает заранее** — иначе игрок узнает о нём через десять уровней.
* **Одна кнопка «как было».**
* **Разбор и продажа скованного спрашивают дважды.**
* ⚠ **Сервер отказывает ДО списания, если пул аффиксов не наберёт оплаченную форму.**
  `rollAffixes` при пустом пуле делает `break` МОЛЧА: выключил дизайнер полдюжины аффиксов —
  игрок заплатил за пять слотов, получил три, и никто не узнал.

### 17.1 Чего в системе не хватает: момента радости и причины возвращаться

Правило Р3 (детерминизм) вынесло из ковки всю эмоцию: превью ЕСТЬ предмет, платишь и получаешь
ровно то, что прочитал. Это правильно — но у каждой работающей системы есть момент, ради
которого её открывают: слэм в PoE, щелчок рунного слова в D2, крит-ковка в Last Epoch.

Лечение не в возврате азарта в ковку, а в **переносе церемонии на зачарование**, где
случайность уже есть и она законна: удар молота, вспышка, проявление аффиксов по одному.
**Ковка — спокойная, зачарование — громкое.**

И вторая вещь, без которой вкладка мертва между ковками: **страница каталога**. Силуэты
незакрытых деталей, счётчик «6 из 8 клинков меча», всплывашка «открыта новая деталь» прямо
в момент разбора. Главная петля системы — не «сковал оружие раз в двадцать уровней», а
**«разбор хлама кормит каталог»**, то есть каждый мусорный дроп становится прогрессом.

⚠ **И самая крупная дыра в охвате: глагола «заменить деталь в найденной вещи» нет.** Система
обслуживает только тех, кто кует с нуля; игрок с хорошим найденным раром не откроет вкладку
никогда. А детали у найденной вещи уже выводятся детерминированно — значит слоты у неё есть,
и замена клинка в любимом мече использует ту же машинерию. Стоит одного глагола и превращает
ковку из отдельного пути в то, что трогают все.

## 22. Чем проверяем

* **Разброс ДПС ≤ 8 % в объявленном конверте** (бонус урона 0.3…1.5 × бонус скорости
  0.05…0.6), на всех 50 базах, **на реальном бою** через `session/microFight.ts` — не закрытой
  формулой и не `sim/fight.ts` (он сам в шапке пишет, что DoT и статусы игнорирует).
  Сетка обязана шагать **по темпу**, а не только по ДПС: уптайм статуса — ступенька по ударам
  в секунду, и при неизменном ДПС она не видна.
* **Инвариант объявляется на руку**, дуал-вилд мерится отдельным прогоном.
* **Число задетых целей** в симе для гнезда 2 — иначе «площадь-нейтрально» останется формулой.
* **Одна ось:** сторож, что `mods` детали выводятся из `axis`, а не записаны руками.
* **Не прачечная:** «сковать и переплавить» не создаёт ни сырья дороже потраченного, ни меток
  в журнале — ни на одном пути.
* **Мощность в час:** «сковал за N минут фарма» против «нашёл за то же время».
* **Редактор ≡ сервер:** предпросмотр совпадает с расчётом сервера до числа.
* **Телеметрия:** счётчик скованного и разобранного рядом с `killsPerHour` — иначе проверить
  «цена ≈ времени фарма» после запуска будет нечем.
* `npx vitest run` + `tsc` ×4 + сборка клиента и редактора.

## 23. Что сознательно НЕ делаем

| Отвергнуто | Почему |
|---|---|
| **Вторая ось у ударной части** («заточка») | 25 ячеек вместо 5, три числа в тултипе; при дуал-вилде складывается и даёт +5.8 % вместо +3.4 % |
| **Статусный рычаг в двух гнёздах сразу** | статусные статы складываются аддитивно в одном пуле — это та же «сумма вкладов», ради запрета которой заведено правило Р2. У грани один продавец |
| **Масса как торгуемая колонка** | вся лестница весов двигает нокдаун на 0.44 п.п.; потолок всей механики +2.37 % урона |
| **Дальность и разброс у стрелкового** | дальность — константа 1100 px при зрении 240–320; поля разброса у оружия нет вовсе |
| **`projRadiusMult` как «геометрия»** | радиус снаряда — весь коридор попадания, это вторая ось ДПС под другим именем |
| **Покупка числа слотов** | полезность слота почти линейна (0.62 / 0.60 / 0.57 / 0.54) — это ценник, а не выбор. Число слотов даёт ступень, выбор даёт форма |
| **Лестница редкости в два платежа** | два действия, ноль решений |
| **+1 к ёмкости двуручному** | компенсация, которой нет у дропа, и двуручное она всё равно не спасает |
| **Форма «равная» на Σ=5** | её не существует: 3+3 у редкого невозможна |
| **Семь порогов журнала по ступеням** | таблица ради монотонности, которая получается сама. Счёт нужен ровно там, где его просил владелец, — на t6 |
| **Ролл качества у детали** | случайность в том, ЧТО дала система, ломает Р3 |
| **Отдельная семья `argent` под магию** | исторически прибор — один гарнитур; две семьи под одну роль удвоили бы пул и сделали бы жезл четырёхсемейным |
| **Отдельная семья `wrap` под оплётку** | оплётка уехала в бронную `hide` (которая получила оружейный сток), а витая проволока стала ФОРМОЙ поверх кожи — так и историчнее |
| **Шестая ступень материала** | требование «на t3 сопоставимый выбор во ВСЕХ гнёздах» выполнимо только при одинаковой полосе; шестая ступень в одной семье ломает согласование во всех |
| **Потолок материала по роли гнезда** | «булава не может быть t5» — это запрет на ковку целого класса. Осталось текстом в тултипе, а не механикой |
| **Ковка брони** | второй заход ⚠ и решить надо СЕЙЧАС: у брони группа `life` общая у префикса `hearty` и суффикса `of-vigor`, оплаченный сплит 3+3 может не набраться |
| **Уникальные свойства с ковки** | они остаются за дропом |
