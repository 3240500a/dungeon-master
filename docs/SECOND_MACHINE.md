# SECOND_MACHINE.md — вторая машина: от чистой Windows до работы по всем направлениям

Мощная машина (Ryzen 9950X, 32 ГБ, GTX 1070) — основное рабочее место: там игра, поз-редактор,
редактор конфигов, нагрузочный стенд и ИИ-генератор анимаций. Ноутбук остаётся для настройки
и проверок.

Этот документ — про **рабочее место**. Боевой деплой (Linux + Caddy + HTTPS) — [DEPLOY.md](DEPLOY.md),
нагрузочный стенд — [tools/deploy/STAND.md](../tools/deploy/STAND.md).

---

## 1. Что поставить руками

Скрипт ничего не ставит молча — он называет недостающее и даёт команду. Заранее нужны:

| Что | Команда | Зачем |
|---|---|---|
| **Node 24** (ровно 24, см. `.nvmrc`) | `winget install OpenJS.NodeJS.LTS` | всё остальное |
| **PostgreSQL 17** | `winget install PostgreSQL.PostgreSQL.17` | аккаунты, персонажи, конфиги, контент редактора. Запомни пароль `postgres` — он спросится один раз |
| **git** | `winget install Git.Git` | код и `uWebSockets.js` (ставится прямо с GitHub) |

Под ИИ-генератор дополнительно (ключ `-Ai` их проверит): **Vulkan SDK**, **CMake 3.25+**, **Ninja**,
опционально **Python 3.12** для запасного пути на PyTorch.

## 2. Две команды

```powershell
git clone <адрес> dungeon_master
cd dungeon_master
powershell -ExecutionPolicy Bypass -File tools\deploy\setup-workstation.ps1 -Admin <твой_ник> -Ai
```

Скрипт проверит окружение, заведёт роль `dm` и базы `dungeon`/`dungeon_test`, поставит зависимости,
**создаст ключ доступа** (`tools/deploy/local.env.ps1`, в git не попадает), выдаст роль `admin`
и откроет порты в фаерволе для частной сети.

Ключ `-Admin` выдаёт роль **существующему** аккаунту (пароль чужого аккаунта установочный
скрипт знать не должен). Аккаунта ещё нет — завести одной командой:
`npm run create-admin -- <ник>` (пароль спросится отдельно и не будет виден).

## 3. Запуск по направлениям

```powershell
. .\tools\deploy\local.env.ps1     # подключить ключ (в каждой новой консоли)

npm run dev                        # игра + поз-редактор
#   игра:          http://localhost:5173/game3d.html
#   поз-редактор:  http://localhost:5173/pose-editor.html
npm run editor                     # редактор конфигов: http://localhost:5174
npm run anim-ai:stub               # шим генерации анимаций (заглушка, движок не нужен)
npm test                           # тесты
```

Стенд — по [STAND.md](../tools/deploy/STAND.md) (`run-stand.ps1 -Mode single|cluster`).

## 4. Доступ: логин или ключ

Инструментальные роуты (`/api/dev/*`: правка конфигов, заливка моделей, публикация контента
редактора) закрыты **ролью**, а не адресом. Пускает:

* **логин/пароль** с ролью `admin` — для людей;
* **`DM_ADMIN_KEY`** — для процессов (скрипты, шим генерации). Тот же ключ шим принимает как `ANIM_KEY`,
  и его же можно вставить в поле «или ключ» формы входа — удобно, пока аккаунта нет.

**Вход спрашивается НА ВХОДЕ.** Оба редактора не показывают ничего, пока не вошёл админ:
за формой пустая страница, кнопки «отмена» нет. Токен ПРОВЕРЯЕТСЯ у сервера (`GET /api/me`),
а не просто берётся из localStorage: роль могли снять, сессию отозвать, ключ сменить.
Вошёл обычным игроком — форма скажет это по имени, а не отдаст безликий отказ.
Сервер не поднят — редактор ВСЁ РАВНО откроется на локальной рабочей копии: падение сервера
не должно отнимать инструмент, а опубликовать без него всё равно не выйдет.

⚠ Сам экран входа — НЕ ЗАЩИТА: страница это код в браузере, его можно обойти. Защищает
СЕРВЕР — он требует роли на КАЖДОМ запросе. Экран убирает другое: инструмент больше не
выглядит открытым для всех, и правка не упирается в отказ после часа работы.

### Аккаунты

```powershell
npm run create-admin -- <ник>            # завести админа (пароль спросится, не виден)
npm run create-admin -- <ник> --reset    # сменить пароль (гасит все сессии)
npm run grant-admin  -- <ник>            # выдать роль уже существующему аккаунту
npm run revoke-admin -- <ник>            # снять роль (действует сразу)
npm run admins                             # кто сейчас админ
```

Пароль НИКОГДА не передаётся аргументом: аргументы оседают в истории консоли и видны
в списке процессов. Смены пароля в самой игре пока нет, поэтому `--reset` — единственный способ.

Роль читается на **каждом** запросе, поэтому снятие действует сразу. Ключ гасится сменой
переменной, сессии человека — `POST /api/logout-all` или сменой пароля.
**Почему так, а не «только с локальной машины».** Прежний гейт проверял адрес сокета. Это не пропуск,
а его видимость: браузер разработчика тоже ходит с `127.0.0.1`, значит проверку проходила ЛЮБАЯ
открытая в нём страница — и могла переписать баланс игры и файлы `data/*.json`. Подробности —
в [DEPLOY.md](DEPLOY.md).

## 5. Работа с ДРУГОЙ машины

Редактор на ноутбуке против сервера на десктопе:

```powershell
$env:DM_API = 'http://192.168.1.69:3001'   # адрес десктопа
$env:DM_LAN = '1'                          # Vite слушает не только петлю
npm run dev
```

На стороне сервера добавь источник редактора в `DM_ORIGINS`
(например `http://192.168.1.50:5173`), иначе браузер отобьёт запросы по CORS.

Префикс `DM_`, а не `VITE_`, намеренно: переменные с `VITE_` Vite впечатывает в собранный бандл,
и внутренний адрес машины уехал бы в продакшен-сборку.

## 6. Переезд содержимого редактора — сам

Ничего экспортировать не надо. При первом открытии на новой машине рабочая копия пуста, и
`poseServer` тянет всё с сервера: клипы, риг, суставы, физ-тела, походки, персонажей, карты костей —
все двадцать ключей `POSE_KEYS`. GLB-модели лежат на сервере (`/assets/<id>.glb`), IndexedDB — только кэш.

Правило хранения: **локальное — истина, на сервер уходит по кнопке «Опубликовать»**. Сервер никогда
не затирает рабочую копию сам; если на сервере оказалось новее, публикация отклоняется целиком (409),
а не теряет чужую правку молча.

Адрес шима генерации приезжает вместе с контентом (он в `pe_ai`), а **ключ — нет**: он в личных
`pe_prefs`, которые на сервер не уходят вовсе. Ключ вводится на каждой машине один раз.

## 7. ИИ-генератор анимаций

Движок живёт на **отдельной ветке** `ai-engines` — общего кода с игрой у него нет, тулчейн другой,
а веса больше десяти гигабайт и в git им нельзя:

```powershell
git worktree add ..\ai-engines ai-engines
```

Порядок: сперва проверить канал заглушкой (`npm run anim-ai:stub` → вкладка «ИИ» в поз-редакторе →
«проверить связь» → «сгенерировать»), и только потом ставить движок. Что ставить и почему именно
Vulkan, а не CUDA — [ANIM_AI_RESEARCH.md, ЧАСТЬ III](ANIM_AI_RESEARCH.md); настройка шима —
[tools/anim-ai/README.md](../tools/anim-ai/README.md).

## 8. Что живёт в git, а что нет

| В git | Не в git |
|---|---|
| весь код, конфиги `data/*.json`, ассеты игры (репозиторий целиком ~20 МБ) | `node_modules/` |
| ветка `ai-engines`: скрипты сборки и скачивания весов | **веса моделей** (>10 ГБ) |
| — | база Postgres (контент редактора живёт в ней; бэкап — `pg_dump`) |
| — | `tools/deploy/local.env.ps1` — ключи этой машины |

## 9. Грабли, которые ловятся заранее

* **Node ровно 24.** На 22 и 25 часть пакетов не соберётся; версия зафиксирована в `.nvmrc`.
* **`uWebSockets.js` ставится с GitHub** и на Windows умеет падать. Сервер работает и без него
  (на `ws`), но замеры стенда будут не те — тогда `DM_WS=ws`.
* **Postgres нужен серверу.** Для быстрой проверки без базы у тестов есть `DM_SKIP_PG=1`.
* **Правило фаервола обязательно.** Без него сетевой адрес молчит, даже когда сервер работает.
* **Два стенда разом запускать нельзя** — оба зовут себя `node-0` и перетирают регистрацию.
