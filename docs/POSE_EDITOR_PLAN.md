# План: Гуманоид-скелет + Pose-editor (мини-Каскадёр)

Цель: (1) авторить позы/анимации на манекене визуально (FK+IK), экспорт углов → аниматор их вшивает в
рэгдолл; (2) скелет = аналог **общего гуманоида Unity** (~21 кость) для беспроблемного ретаргета зариганых
glTF-моделей позже.

## Зафиксированные решения
- **Последовательность:** гуманоид-скелет ПЕРВЫМ, редактор строим на нём (позы 1:1 лягут на модели).
- **Глубина редактора:** FK + IK сразу.
- **Поза покоя:** **T-поза** (стандарт Mixamo/Unity для ретаргета).
- **Размещение:** отдельная страница `pose-editor.html` (без игры/физики).
- **L/R:** строим ПРАВИЛЬНО с нуля (стандарт Mixamo: лицом +Z, Left = +X). Никакого зеркала как в рэгдолле.
- **Физику не раздуваем:** рэгдолл остаётся 15 костей; гуманоид (эдит/рендер-скелет) → рэгдолл маппим
  подмножеством. Гуманоид с 21 костью — для редактора и будущих моделей.

## Кости (общий гуманоид Unity; пальцы +30 — потом)  ✅ СДЕЛАНО (`humanoid.ts`)
Иерархия (имена Unity-конвенции). Male = 22 кости, Female = 24 (+грудь):
```
Hips
 ├ Spine → Chest → UpperChest → Neck → Head
 │                     ├ LeftShoulder → LeftUpperArm → LeftLowerArm → LeftHand
 │                     ├ RightShoulder → RightUpperArm → RightLowerArm → RightHand
 │                     └ [female] LeftBreast, RightBreast   ← вторичные (jiggle), вне humanoid Unity
 ├ LeftUpperLeg → LeftLowerLeg → LeftFoot → LeftToes
 └ RightUpperLeg → RightLowerLeg → RightFoot → RightToes
```
- **UpperChest** (Unity-опция) добавлен — лучше изгиб корпуса; плечи/шея/грудь на нём.
- **Гендер:** `buildHumanoid({ gender:'male'|'female' })` — female добавляет 2 breast-кости.
- **Грудь — ВТОРИЧНЫЕ (jiggle) кости, НЕ humanoid Unity.** Сейчас только структура+rest-форма. Позже:
  (a) spring-bone колыхание от движения Chest; (b) карта ретаргета под breast-кости конкретной модели
  (VRoid `J_Sec_L_Bust…` и пр.) ИЛИ отдать spring-bone'ам самой модели. Rest-позиция груди — подкрутить.

### Ф B2 — Доработка: full-body IK + библиотека клипов  ✅ СДЕЛАНО (`pose-editor.ts`)
Проверено: FABRIK тянет кисть → Chest сдвигается на ~19, Hips-якорь 0 (гнётся вся цепочка до таза);
глубина=3 → только рука (Chest 0); клипы записываются, экспорт JSON, localStorage переживает перезагрузку.
Ниже — исходный план (реализован).
Запрошено: (1) IK на все кости, не только кисти; (2) тянешь за руку — гнётся вся цепочка ДО ТАЗА;
(3) библиотека именованных клипов с настраиваемым числом ключевых кадров, сохранением/редактированием.

**1. Full-body IK (FABRIK) + IK на любой кости.**
- Заменить 2-костный аналит. солвер на **FABRIK** (N-костная итеративная IK): грабишь ЛЮБУЮ кость → тянешь
  translate-гизмо → цепочка от ЯКОРЯ (таз) до этой кости изгибается, длины костей сохраняются.
- **Алгоритм:** цепочка мир-позиций суставов `P0(таз)…Pn(эффектор)` + длины из rest. Итерации:
  backward (Pn=цель, вверх подтягиваем сохраняя длины) → forward (P0=якорь, вниз) ×~10. Затем
  **реконструкция поворотов**: каждую кость наводим `aimBoneAt` на следующий сустав (обновляя матрицы).
- **Глубина IK** (ползунок): сколько родителей вверх тянется — локально (2 кости) … до таза (full-body).
  По умолчанию — до таза (как просил). Таз = якорь (не двигается; позже опц. «открепить таз»).
- **Полюс/изгиб:** после FABRIK лёгкий нудж средних суставов к полюсу (локоть вниз/колено вперёд), чтобы
  не выворачивало. Пины (закрепить стопу/кисть) — позже.
- **Эффекторы на всех костях:** в IK-режиме клик по любой кости → она tip, translate-гизмо на её конце.
  (Отдельные 4 цели-сферы больше не нужны — грабим кость напрямую.)

**2. Библиотека клипов анимаций (localStorage + экспорт).**
- Модель: `Clip { name, keys: PoseData[] }` (keys.length = число ключевых кадров, равномерно 0..1);
  `Library: Clip[]` в `localStorage` (переживает перезагрузку) + экспорт/импорт JSON.
- UI-панель «АНИМАЦИИ»:
  - список клипов: **+ создать / удалить / переименовать / дублировать**; выбор активного клипа.
  - активный клип: **число кадров** (спиннер N), выбор кадра (кнопки 1..N), **«записать кадр = тек. поза»**,
    **«перейти к кадру»** (применить его позу для правки).
  - **плей/скраб** по клипу (ползунок/кнопка Play — интерполяция между кадрами), скорость.
  - **сохранить** (в localStorage), **экспорт JSON** (весь клип / вся библиотека), **импорт**.
- Рабочий цикл: создал «idle» → N=3 кадра → на каждом позирую → сохранил; создал «удар мечом» → N=5 →
  позирую кадры → сохранил; и т.д. Экспорт → мне → вшиваю в игру.
- Старые слоты start/mid/end убираем (их роль берут кадры клипа).

**Оценка:** FABRIK+IK-на-всех ~1 заход; библиотека клипов ~1 заход. Делаю по порядку с проверкой кадрами.

### Ф B3 — IK-риг в стиле Cascadeur (эффекторы + пины + свободный таз + планта стоп)  ✅ СДЕЛАНО
Проверено численно: таз вниз на 12 (32→20) — стопа [4,1,0] стоит НЕИЗМЕННО (дрейф 0), колени согнулись
(присед); тяну кисть — таз наклонился к цели (тело за рукой), стопа стоит (дрейф 0), кисть в цели точно.
Кадрами: чистый присед с плантой стоп + reach с наклоном тела. FABRIK-grab заменён на эффектор-риг.

**Фикс (per-limb IK/FK):** баг — FK-правка сустава руки/ноги сбрасывалась при возврате в IK (solveRig решал ВСЕ
конечности). Решение (Maya HumanIK-модель): флаг `ik` на конечность; `solveRig` решает только IK-конечности, у FK
углы не трогает (цель следит за концом). FK-поворот сустава руки/ноги → авто-FK (сохраняется); тянешь эффектор →
авто-IK; тумблеры IK/FK на конечность в панели. Проверено: FK-локоть после solveRig = −1.2 (сохранён), IK-локоть = солвер.
Проблема B2: FABRIK делал таз ЯКОРЕМ и крутил его; стопы летали. Правильная модель (Cascadeur / Maya HumanIK /
UE Control Rig) — **контрол-риг**: свободный корень-таз + эффекторы конечностей с ПИНАМИ; тянешь что-то — конечности
решаются к своим целям, запиненные стопы/кисти стоят в мире.

**Модель (реализую):**
- **Таз (Hips)** — свободный корень: хэндл двигать (translate) / вращать (rotate, тумблер). Двигает весь скелет.
- **4 эффектора**: LeftHand, RightHand, LeftFoot, RightFoot — мировые цели-хэндлы. **2-костная IK** к каждой
  (плечо+локоть / бедро+колено, полюс: локоть вниз-назад, колено вперёд). Каждый кадр (в IK-режиме) — пересчёт.
- **Стопы — плантованы**: цель стопы фикс в мире + стопа держится плоско (ориентация фикс). Двигаешь таз → ноги
  пересчитываются, стопы СТОЯТ где поставил. ← фикс главной претензии.
- **Пины**: чекбокс на эффекторе. Пин/стопа = цель фикс. Не-пин рука = едет вместе с тазом (рука при движении
  таза не растягивается). Двигаешь таз на Δ: стопы/пины стоят, не-пин руки += Δ.
- **«Тело за рукой»** (ползунок 0..1): тянешь кисть → таз частично едет к цели (Cascadeur-reach), стопы держат
  → тело плавно наклоняется за рукой. При 0 — только рука.
- **FK-режим** остаётся: клик по кости → вращение (спина/голова/скрутки/пальцы — тонкая правка).
- **Захват состояния:** вход в IK-режим = снимок текущей позы в риг (цели = мир-позиции кистей/стоп, таз = тек.).
  Экспорт/клипы читают итог как углы костей (readPose) — формат данных прежний.

**UI:** хэндлы (таз — жёлтый куб, руки — синие, стопы — зелёные сферы), чекбоксы пинов у 4 эффекторов, тумблер
«таз: двигать/вращать», ползунок «тело за рукой». Клипы/гендер/экспорт/FK — как есть.

**Проверка (кадрами+числами):** двигаю таз вниз — стопы Y не меняются (планта); тяну кисть — таз наклоняется,
стопы стоят; стопа перетаскивается; таз не крутится сам.

# СИСТЕМА ФИЗИЧЕСКОЙ АНИМАЦИИ (Exanima-модель) — план 2026-07-18

Редактор перерастает из «редактора поз» в **систему физической анимации**. Суть инструмента: автор делает
ключевые + промежуточные позы, а **физика игры превращает их в физически-корректные анимации, стремящиеся к
этим позам** (как Exanima). Референсы:
- **Cascadeur** (offline): кейфреймишь позы, физика ПОМОГАЕТ («зелёный призрак» = физкорректная версия рядом,
  «Snap to Physics», корректор центра масс). Выход — ЗАПЕЧЁННЫЙ клип кадров.
- **Exanima / active ragdoll** (runtime): запечёнок нет; физика получает ЦЕЛЕВУЮ позу и моторами-«мышцами»
  тянет тело к ней; сила мышц = точность; столкновения/инерция ломают реалистично. **У нас это УЖЕ есть**
  (Jolt `DriveToPoseUsingMotors`, таз кинематик-авторитет) — сейчас цели даёт процедурный `pose.ts`.

## Зафиксированные решения (ответы юзера 2026-07-18)
1. **Унифицировать скелет.** Игровой рэгдолл пересобрать на ГУМАНОИД-скелете (позы 1:1, без ретаргет-конверсии,
   без зеркального L/R). Делаем в редакторе (он уже на гуманоиде) — там же рождается единый риг.
2. **Локомоция = процедурная СТРУКТУРА + авторская СТИЛИЗАЦИЯ.** Оставляем расстановку стоп/фазы по миру
   (реактив), НО целевые ПОЗЫ на фазах (нога спереди Л → нога спереди П → промежуточные) автор задаёт per
   персонаж → у каждого свой бег/ходьба. Моторы тянут к этим позам, физбаза корректна. Для ВСЕХ действий та же
   схема (удар/гард/…): целевые кадры + физкорректная база.
3. **Два рантайм-режима на персонажа:** (а) чистый активный рэгдолл (физика каждый кадр); (б) кукла с
   ЗАПЕЧЁННОЙ анимацией (дёшево) + рэгдолл включается ТОЛЬКО на урон/смерть. Физрезультат из редактора
   **запекаем в обычную покадровую анимацию** → 20+ монстров играют запечёнку, рэгдолл лишь на хит/смерть.
4. **Сначала всё вылизать в РЕДАКТОРЕ, потом проводить в игру.**
