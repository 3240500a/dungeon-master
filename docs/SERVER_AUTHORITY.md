# SERVER_AUTHORITY.md — что авторитетно на сервере (реестр портов client→server)

**Зачем этот файл.** Игра стала полностью серверно-авторитетной (см. [MULTIPLAYER.md](MULTIPLAYER.md)).
При переносе механик с клиента на сервер НЕСКОЛЬКО РАЗ терялась логика (награды, квесты, **смерть**,
кузница). Этот файл — единый реестр: что где живёт, что уже авторитетно, что ещё нет. **Правило:
портируешь клиентскую механику на сервер — обнови строку здесь и пройди чек-лист внизу.**

Принцип: **клиент = вью+ввод**. Любое изменение `SaveState`/мира считает СЕРВЕР (`GameSession` в
`packages/shared/src/session` + `packages/server/src/net/room.ts`), клиент только шлёт ввод/команды и
рисует снапшоты. Чистая логика — в `packages/shared` (переиспользуют сервер и сим).

Задаются `flat`-долей (0.05 = +5%), в UI — как проценты (`PERCENT_STATS`). 15. **Кластер: комната может исчезнуть без похорон (фаззер кластера B1, проход правок 1: K1, K2, K3, ENV1, ENV2; проход 2: K3 целиком).**

   открыт», а свод ждал чекпойнта — падение процесса между ними давало продолжению другого участника закрытый сундук и опыт второй раз.

   запись могла не лечь вовсе: пауза C-07 после сбоя её не ставила, упавшая не повторялась до автосейва, исход неизвестен — копия ждала
   дописки, процесс умирал на ней самой, аренда кончалась в простое базы (и своё выброшенное — так же). Вещь, уже ушедшая из строки
   выбросившего, жила в сумке без строки — падение уносило записанное. Теперь подъём вещи с `owner` (`Room.pickThrown`) — в очереди записей
   поднимающего: вещь лежит на земле под замком (`carrying`: ни соседу, ни второму подъёму), запись несёт её снимком (`Client.carry` →

   как всякая вещь на земле). Строки одной транзакцией писать не пришлось: земля и есть место вещи между двумя записями.

## Чек-лист: как портировать клиентскую механику на сервер (чтобы НЕ потерять логику)

1. Найти клиентскую реализацию (обычно `client/src/modules/<x>` или контроллер сцены). **Прочитать
   ВСЮ логику**, включая побочные эффекты (потеря лута, сброс глубины, экраны, звук).
2. Вынести ЧИСТУЮ логику в `packages/shared` (над `SaveState`/миром, без Phaser/DOM), с тестом.
3. Оркестрация на сервере: `Room` (команда/событие tick) применяет её и шлёт `saveUpdate`/кадр.
4. Протокол: добавить `ClientFrame`/`ServerFrame`/`TownCommand` в `shared/session/netTypes.ts`. Новую команду — ещё и в строгую схему `townCommandSchema` (`netSchemas.ts`; забудешь — упадёт `tsc`) и в карту мест `SCOPE` (`server/net/guard.ts`; тоже `tsc`). id и размеры из конфига на проводе — только через потолки `shared/session/wireLimits.ts`: те же числа держит схема конфига, и редактор не примет id, который сервер молча отвергнет (R2-27). Сервер ответит на неё `cmdResult` сам; действие, трогающее сундук аккаунта, — только через `withAccount`, и все отказы — ДО траты.
5. Клиент: заменить локальную мутацию на `app.sendCmd(...)`/`net.send(...)`; UI рисует ответ сервера.
6. **Удалить** мёртвую клиентскую копию (модуль/контроллер), обновить строку в этом файле + README модуля.
7. Verify: typecheck×4 + vitest + build; ручной кросс-тест в 2 вкладках.
