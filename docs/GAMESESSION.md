# GAMESESSION.md — план: единое безголовое игровое ядро

**Цель:** один авторитетный игровой цикл в `shared` (без Phaser/DOM), который:
- **клиент** рисует (Phaser = только вью),
- **симулятор** гоняет ботом (тот же код → сим = буквально игра без картинки),
- (позже) **кооп-сервер** шарит между игроками.

Это финал начатого выноса боя в `shared` (уже там: `world/debuffs`, `world/combat`,
`resolveWeapon`, `resolveArmor`, `power`). Текущий упрощённый `src/sim` — приближение;
после выноса он заменяется ботом поверх настоящей сессии.

---

## Что сейчас завязано на Phaser (это и переезжает)
| Механика | Где сейчас | Зависимость |
|---|---|---|
| Движение + коллизии | `player.ts`, Arcade-физика | физика Phaser об стены |
| ИИ монстров | `monster.ts` | спрайт/тело/дистанции Phaser |
| Тайминги | сцены | `scene.time`, delta |
| Ввод | `player.ts`, `combatController` | клавиатура/мышь |
| Бой/скиллы/лут-оркестрация | `combatController`, `lootController`, `DungeonScene` | сцены/спрайты |
| Генерация этажа | `dungeon-gen/generate.ts` | почти чистая (сид-rng) |

Чистое уже: формулы боя/статов/лута/монстрогена/скилл-модов/дебаффов — в `shared`.

## Целевая архитектура — `shared/src/session/`

### Данные мира (сериализуемо — годится для сети)
```
WorldState {
  seed, depth, difficultyId, timeMs, tick
  grid                      // сетка этажа (чистые данные)
  players: Record<id, PlayerEntity>   // кооп; одиночка = 1
  monsters: MonsterEntity[]           // id, pos, vel, facing, hp, def, debuffs, cooldowns, aiState
  drops: DropEntity[]                 // id, pos, item
  projectiles: ProjectileEntity[]     // id, pos, vel, owner, packet, attacker, debuffs, ttl
  doors/keys/stairs/portal            // как данные
}
PlayerEntity { id, pos, vel, facing, hp, mana, debuffs, hotbarCd[], attackCd, stunTimer, save: SaveState }
```

### Ввод — абстракция «контроллер» (ключ к «игрок = бот = сеть»)
```
PlayerInput { move:{x,y}, facing:number, attack:boolean, cast:0..3|null, interact:boolean }
interface Controller { input(world, playerId): PlayerInput }
```
- `PlayerController` (клиент) — из клавы/мыши.
- `BotController` (сим) — ИИ-мозг (см. ниже).
- `NetworkController` (кооп, позже) — из сети.

### Сессия — единственный авторитет
```
class GameSession {
  constructor(reg: ConfigRegistry, seed, difficultyId, saves: SaveState[])
  enterFloor(depth)                       // generateDungeon + спавн пачек + расстановка
  tick(dtSec, inputs): WorldEvent[]       // один фикс-шаг всего мира
}
```
`tick` за шаг: движение+коллизии игроков → атаки/касты → ИИ+атаки монстров → снаряды →
тик дебаффов/реген → подбор лута → XP/левелап → смерти → переход этажа. Возвращает
события (числа урона, киллы, дроп, левелапы, смерти, floor:entered) — для вью и статов.

### Phaser-free подсистемы (новое чистое)
1. **Сеточное движение/коллизии** — `moveWithCollision(pos, vel, radius, grid, dt)`: круг vs
   проходимость клеток, скольжение вдоль оси. Заменяет Arcade-физику. **Самый крупный
   новый кусок.**
2. **LoS/восприятие** — `lineOfSight` уже почти чистый; переносим в session; конус
   зрения+слух — чистая математика.
3. **Бой/дебаффы** — уже в `shared` (`resolvePlayerHit` и т.п.); интегрируем в tick.
4. **Скиллы** — `executeAbility` (AoE/снаряды) переносим из клиента в session (чисто:
   урон по радиусу / спавн снарядов).
5. **Лут/XP/прокачка/смерть** — `generateItem`/`addToInventory`/`levelForXp`/штраф — уже в
   shared; оркестрация в session.

## Бот-мозг (BotController) — «ведёт себя как игрок»
Переиспользует логику текущего эконом-бота, но подаёт **реальные вводы в реальном времени**:
- **Цель:** ближайший агрящий монстр → иначе ближайший дроп → иначе лестница (если этаж
  зачищен) / исследование.
- **Движение:** к цели; кайт для дальнего/на низком HP.
- **Атака:** монстр в дальности/дуге → attack; лучший скилл вне КД → cast.
- **Лут:** дойти, подобрать, надеть лучшее (скоринг из `economy`).
- **Выживание:** отступать на низком HP (зелий нет).
- **Прокачка:** левелап → распределить атрибуты/скиллы/пассивы (аллокаторы из `economy`).
- **Поток:** нырять при зачистке+выживаемости; город на «городском» этаже (магазин);
  смерть → штраф.

## Статистика (приоритет: билд + статы забегов + кривые)
Сессия эмитит события → `StatsCollector` копит. Вывод — как d2planner.

**1. Финальный билд (снимок в конце):**
- уровень, распределённые атрибуты (+ эффективные с гиром);
- **надетые предметы по слотам с аффиксами и тирами**;
- активные скиллы (ветка + ранги) и пассивы;
- производные: DPS (по типам), эффективное HP, броня/резисты, скор. атаки/бега, крит;
- Мощь / эфф. уровень.

**2. Статы забегов:**
- на забег: этаж, время, убито мобов, смертей, золото, дроп, XP;
- итого: забегов, мобов, смертей, часов, самый глубокий этаж, лут/час, XP/час.

**3. Кривые:**
- часы→уровень; рост Мощи/гира во времени; где «стены» сложности; смертность по этажам.

**Вывод:** JSON-снимок + карточка (вкладка редактора: «Отчёт по забегу» + «Просмотрщик
билда»), и `npm run sim` печатает сводку.

## Этапы миграции (на каждом игра остаётся рабочей)
1. **Модель мира + чистое движение/коллизии + сетка в `shared`.** Юнит-тесты. Клиент не
   трогаем.
2. **Порт боя/ИИ/скиллов/лута в `session.tick`** (переиспользуя формулы shared). Тесты на
   инварианты (спавн, килл, дроп, левелап, переход этажа).
3. **Перевод клиента (одиночка):** `DungeonScene` создаёт локальную `GameSession`, подаёт
   `PlayerController`, рисует по `WorldState`; авторитетную логику из
   `combatController`/`monster`/`lootController` убираем (становятся вью/удаляются). ←
   рискованный крупный шаг (движение/фидбэк надо сверить вживую).
4. **BotController + StatsCollector = новый сим.** Заменяет упрощённый `src/sim`.
5. **UI статов:** «Отчёт по забегу» + «Просмотрщик билда» в редакторе; CLI-экспорт JSON.
6. **(Позже) Кооп:** сервер хостит session + WebSocket + клиент-предикшн.

## Риски и как снижаем
- **Ощущение движения:** сеточная коллизия должна ощущаться как Arcade (не застревать,
  скользить). Требует тюнинга; шаг 3 без превью рискован → делаем аккуратно, просим тебя
  протестить.
- **Детерминизм:** сид-rng везде (`mulberry32` уже). Для воспроизводимости сима.
- **Производительность:** реальный тик медленнее абстрактного сима. Митигация: headless
  без Phaser всё равно быстр; для макро-прокачки можно «перемотку» (крупный dt), для боёв —
  точный dt.
- **Объём:** большой майлстоун. Разбит на шаги, игра шиппабельна на каждом.
