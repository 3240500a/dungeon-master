# План этапа: баланс HP/урона + калькулятор + редкости монстров + гир в генераторе

## 1. Замеры (что есть сейчас)

**Монстры — hp (урон) по уровню** (деривация из атрибутов+гира):
| тип | L1 | L10 | L30 | L60 | L90 |
|---|---|---|---|---|---|
| зомби-скаут (weak) | 18 (3-5) | 38 (3-6) | 80 (4-8) | 145 (6-12) | 209 (8-15) |
| зомби-охранник (medium) | 39 (6-13) | 78 (7-15) | 163 (10-20) | 290 (14-28) | 418 (18-36) |
| зомби-главарь (boss) | 60 (18-33) | 118 (23-42) | 244 (34-63) | 435 (52-95) | 625 (69-127) |

**Игрок (воин, база+гир, без скиллов) по уровню:**
| | L1 | L10 | L30 | L60 | L90 |
|---|---|---|---|---|---|
| hp | 30 | 103 | 279 | 511 | 763 |
| удар~ | 13 | 19 | 30 | 49 | 67 |

**Проблемы:**
- HP монстра растёт ~×11 за 90 ур (почти ЛИНЕЙНО от атрибутов) — слишком плоско. HP игрока ~×25, урон ~×5 (без скиллов/гира). Кривые расходятся, абсолютные числа малы.
- Разные оси растут по-разному → баланс TTK «плывёт» по уровням.

## 2. Референс D2 / PoE
- **D2**: hp монстра зависит от area level (табличный per-type base × уровень). Чемпион ≈ ×2 life; unique/rare-пак ≈ ×3 life + случайные моды + миньоны; SuperUnique — именной. К Hell — тысячи hp у танков.
- **PoE**: hp монстра растёт **мультипликативно** по уровню × редкость (почти экспонента). magic — выше базы, rare — сильно выше + больше модов. Эндгейм — десятки тысяч.
- **Вывод**: наш HP-скейл (и урон игрока) надо сделать **компаундным** (growth^level), а сверять по **TTK**, а не по абсолюту.

## 3. Часть A — параметризация деривации КАК У ИГРОКА (решено)
Не фиксированная формула, а полностью настраиваемая (как `deriveStats` игрока):
- У монстра стартовые STR/DEX/INT/VIT (уже есть) + **редактируемые коэффициенты** деривации: hp за VIT,
  урон за ведущий атрибут, меткость/уворот за DEX, армор за STR, и т.д. (сейчас захардкожены в
  `DEFAULT_MDERIVE` → вынести в конфиг `monster-derive` или `balance`).
- **Прирост атрибутов за уровень** — редактируемый (сколько статов даётся за уровень). Монстр «левелится»
  по тем же правилам, что игрок → кривые перестают расходиться.
- Крутизну HP-кривой задаём через прирост-за-уровень + коэффициенты, тюним в калькуляторе по TTK.

## 4. Часть B — редкость монстра = редкость ЕГО ШМОТА (решено)
- Лестница **normal / magic / rare** (+ unique позже) — но БЕЗ отдельных множителей: **сила берётся из гира**.
  Обычный моб = обычный шмот; magic-моб = magic-шмот (гир с magic-афиксами); rare-моб = rare-шмот. Всё
  настраивается **афиксами монстро-гира** (тот же item-афикс-движок катает афиксы на гире → это и есть
  сила/редкость моба). Сводит блок «гир-афиксы» и редкость воедино.
- `champion` — ОРТОГОНАЛЬНЫЙ элит-флаг (жир hp/реген), комбинируется с любой редкостью (D2: rare-пак может
  быть чемпионским).
- Настройка в **паках**: галки редкости у ролей + комбинируемость (какая роль какой редкости может катнуться).
- Генератор мобов: селектор редкости (переключает надетый гир), цвет рамки по редкости.

## 5. Часть C — планировщик персонажа (à la maxroll d2planner) + монстр + TTK
Полноценный планировщик, как d2planner — НЕ только базовые атрибуты. Вкладка «Калькулятор» из трёх зон:

**Зона 1 — планировщик персонажа (левая, главная):**
- Выбор **класса** + **уровня** → авто-подсчёт **очков атрибутов и скиллов** по уровню (из progression-конфига,
  как в игре).
- **Распределение атрибутов** STR/DEX/INT/VIT (поля/ползунки, остаток очков) — как окно прокачки.
- **Скилл-деревья** (мастерства + скилы) — раскладка очков скиллов (реюз данных дерева; влияет на урон/статы).
- **Инвентарь/экипировка** — слоты (шлем/броня/оружие/офф-рука/перчатки/боты/пояс/кольца/амулет), **создание
  предметов** (реюз генератора предметов) и **надевание**; требования по уровню/атрибутам как в игре.
- **Полный стат-блок** — точь-в-точь окно статистики персонажа в игре: hp/мана/выносливость, урон min–max + DPS,
  меткость/уворот, армор/блок/крит, резисты, скорость, скор.атаки/каста (брейкпоинты). Реюз `makePlayerModel`/
  `deriveStats`/`estimateAttack`/`buildSkills` (те же формулы, что в игре — правдоподобно).

**Зона 2 — монстр (правая):** уровень + редкость (= его гир) + чемпион → деривнутый стат-блок + надетый гир/афиксы.

**Зона 3 — сведение (низ):** игрок (из планировщика) ↔ монстр → **TTK в обе стороны**, шанс попадания, вердикт/запас.
Это инструмент калибровки Части A (крутим уровень/гир/скиллы — смотрим TTK).

Плюс: **генератор мобов** дополняется надетым гиром + селектором редкости (мини-версия зоны 2).

## 6. Порядок
Калькулятор (C, показывает обе кривые) → рескейл HP/урона (A, тюним по TTK в калькуляторе) → редкости монстров (B) → гир+редкость в генераторе (C-доп).

## 7. Решения (зафиксированы)
- **Кривая HP** → параметризация деривации как у игрока (стартовые статы + коэффициенты + прирост/уровень, всё в редакторе). Не фикс. growth^level.
- **Редкость** → редкость гира монстра (magic-моб = magic-гир с афиксами); настройка в афиксах монстро-гира; `champion` — ортогональный флаг; редкость — галки у ролей в паках + комбинируемость.
- **Калькулятор** → отдельная вкладка «Калькулятор»: игрок ↔ монстр рядом + TTK в обе стороны (макет показан юзеру).
- **Целевой TTK** — уточнить в процессе (крутим в калькуляторе).

## 8. Порядок реализации (обновлён)
1. **Параметризация деривации** (§3): вынести `DEFAULT_MDERIVE` + прирост-атрибутов-за-уровень в конфиг, editor-вкладка. (движок + тесты)
2. **Планировщик персонажа** (§5, вкладка «Калькулятор») — по под-шагам:
   - 2a. Каркас вкладки + класс/уровень → очки атрибутов/скиллов (progression) + распределение атрибутов + полный стат-блок (реюз `makePlayerModel`/`deriveStats`).
   - 2b. Инвентарь/экипировка: слоты + создание предметов (реюз генератора) + надевание → статы обновляются.
   - 2c. Скилл-деревья: раскладка очков скиллов (мастерства+скилы) → влияние на статы/урон.
   - 2d. Зона монстра (ур/редкость/гир) + зона TTK (игрок↔монстр, обе стороны).
3. **Гир-афиксы = редкость** (§4): item-афикс-движок катает magic/rare афиксы на монстро-гир; редкость в генераторе мобов + паках (галки у ролей). Депрекейт `monster-affixes`.
4. Калибровка кривых по TTK в калькуляторе.
