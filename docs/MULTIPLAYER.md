# MULTIPLAYER.md — дорожная карта кооператива

**Цель:** несколько игроков в одном забеге. Опирается на уже готовое авторитетное ядро
`GameSession` (см. [GAMESESSION.md](GAMESESSION.md)). Это **план**, не реализация.

Модель: **комната = один `GameSession` на сервере**. Клиенты шлют ввод (`PlayerInput`),
получают снапшоты `WorldState`. Тот же код ядра, что гоняет сим-бота и рисует клиент.

---

## Что уже готово (фундамент)
- **Авторитетное ядро** `shared/session/GameSession` — headless, детерминированное
  (сид-RNG, доказано `runner.test`/`sim`), сериализуемое (`WorldState` — чистые данные).
- **Мультиигрок по API:** `addPlayer(id, save)`, `players: Record<id, PlayerEntity>`,
  `tick(dt, inputs: Record<id, PlayerInput>)` — уже принимает ввод нескольких игроков.
- **Ввод сериализуем:** `PlayerInput { move, facing, attack, cast, interact }`.
- **Клиент — вью:** движение/бой/реген игрока уже идут через сессию и в городе, и в
  подземелье (`SessionController` = драйвер; игрок — чистый вид). Локальный игрок уже
  авторитетен.
- **Сервер:** есть Express + Postgres, REST `/api/auth|save|load`, zod-валидация
  сейвов (база анти-чита). charId независим — сейвы по игрокам уже разведены.

## Что осталось (фазы MP)

### MP-1. Rewards в авторитетное ядро
Сейчас лут/XP/золото/квесты считает КЛИЕНТ по шине (`GameSession(rewards:false)` → событие
`monster-died` разбирают LootController/Progression/quests). Для MP это рассинхронит игроков.
- Перенести начисление наград в `tick` (режим `rewards:true` уже есть — killMonster даёт
  золото/дроп/XP) или на хост; клиент только отражает.
- Дроп на землю — уже сущность `WorldState.drops`; подбор сделать через `input.interact`
  (в ядре есть `tryPickup`), а не клиентским LootController.
- Квесты слушают события сессии на хосте.

### Транспорт: задержка/пинг — ✅ (июль 2026)
Тюнинг латентности WS (не меняет авторитет; особенно помогает на узком/VPN-канале):
- **`TCP_NODELAY`** ([index.ts](../packages/server/src/index.ts) `server.on('connection', s => s.setNoDelay(true))`):
  выключен алгоритм Нейгла — мелкие реалтайм-кадры (ввод/снапшоты) не ждут склейки до ~40мс.
- **Сжатие WS** ([wsServer.ts](../packages/server/src/net/wsServer.ts) `perMessageDeflate {threshold:1024}`):
  крупные снапшоты 30 Гц жмутся (мелочь <1КБ — нет), снимает забитость полосы (bufferbloat-лаг) на VPN.
- **Индикатор пинга + keepalive**: кадры `ping`/`pong` (id-эхо), клиент раз в 1с меряет RTT
  (`NetClient.rtt`) и рисует его в левом-верхнем углу (`OnlineScene.updatePing`, цвет по порогам).
  Заодно keepalive — не даёт прокси уронить простаивающее соединение.
- Про VPN: основной лаг — это крюк через exit-node (география + возможный TCP-over-TCP). Лечится на
  стороне игрока: VPN-локация рядом с сервером, WireGuard/UDP вместо OpenVPN-TCP, либо без VPN.

## Порядок и оценка
1. **MP-1 (rewards в ядро)** — средне; развязывает клиент от логики наград (нужно и для соло-чистоты).
2. **MP-2 (WS-транспорт + комната)** — крупно; ядро уже принимает мульти-ввод.
3. **MP-5 (рендер ремоутов)** — мелко после MP-2.
4. **MP-3 (предсказание/интерполяция)** — средне; без него будет «резина» на пинге.
5. **MP-4 (серверная floor-gen)** — средне.
6. **MP-6 (лобби/реконнект)** — средне.

Пререквизит «локальный игрок авторитетен» — **уже выполнен** (перенос движения в сессию).
Ближайший осмысленный первый шаг — **MP-1** (rewards в ядро), т.к. он полезен и вне сети.
