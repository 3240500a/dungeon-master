# @dm/editor — HTML-редактор

Отдельная Vite-страница для правки всех игровых конфигов + инструменты + документация. Формы авто-генерируются из zod-схем `@dm/shared`, поэтому новое поле схемы сразу появляется в редакторе. Запуск: `npm run editor` (порт 5174). Прод: собранный клиент и редактор на одном origin.

## Верхние секции (таб-бар в шапке, `main.ts` → `section`, персист в localStorage)

- **🎮 Игра** — левый nav (свёртываемые группы конфигов) + инструменты-вкладки (🧪 Симулятор, 🗺 Забеги v2, 🎲 Генератор предметов, 👹 Генератор мобов, 🧮 Калькулятор, 🔥 Свипы, 🔨 Ковка); справа — авто-форма страницы (`renderPage`) или инструмент. Мостик `editorNav` (напр. Симулятор → Калькулятор).
- **🧍 3D-эдитор** — поз-редактор во всю панель через `iframe` (`pose-editor.html` клиента; dev кросс-ориджин 5173, prod относительный). Авторинг поз/анимаций/походки/поворотов/внешности/3D-моделей; сохранения — общий серверный `pose_store` (`/api/pose`).
- **📍 Роадмап** (`roadmap.ts` и `roadmapModel/Seed/Calendar/Replan/Public*.ts`) — вехи до релиза с галками и автосчётчиками; второй вид — роадмап для игроков (см. `docs/MODULE_MAP.md`, строка «редактор: роадмап»).
- ⭐ **📦 Выпуски** (08.10, Д3 плана «Обновление контента без пересборки клиента»; `releases.ts` — DOM, `releasesModel.ts` — чистое ядро) — релизы контента и каналы
  dev / beta / live через ручки администратора сервера `/api/admin/content/*` (`devFetch`: токен админа, на 401 — вход и повтор; ручки открыты и на
  проде). Карточки каналов: текущий и прежний релиз, раскатка, `minClient`/`latestClient`, кто менял; список релизов (номер, дата, хэш, метки
  каналов с процентом, перевыпуск). Кнопки «⇢ В бету», «🚀 Выпустить» (процент 1..100), «⬆ Поднять раскатку», «↩ Откатить» (к прежнему или к
  выбранному), «Сохранить версии клиента» — каждая через `window.confirm` с текстом «что будет» из ПЛАНА (`planPromote`/`planRollback`/`planClients`):
  план повторяет правила сервера (первый выпуск — 100%, процент только вверх, посреди раскатки другой релиз нельзя, старый — перевыпуском), поэтому
  заведомый отказ показывается сразу, без окна. `dev` — только просмотр (он сам). Ошибки сервера — текстом (`errorText`: вход, роль, сервер до Д3,
  отказ правилом с недостающими файлами, 5xx). Тесты: `releasesModel.test.ts` (разбор, модель, планы, тексты) и `releasesServer.test.ts` — план ≡
  настоящий сервер (ручки `releaseRoutes.ts` за express + `releaseDb.ts` на `dungeon_test`): сценарий владельца и фаззер (`DM_FUZZ_SEEDS`,
  `DM_FUZZ_OPS`): «можно» — принято с предсказанным итогом, «так уже есть» — «без изменений», «нельзя» — отказ и ничего не поменялось. Справка —
  `docs/vypuski-kontenta.md` (раздел «Unity: контент и доставка»).
- **📖 Документация** (`docs.ts`, ядро — `docsCatalog.ts`) — РАЗДЕЛЫ по механикам. Слева разделы; раздел из одного документа — одна кнопка, из нескольких — раскрывается (▸/▾) и открывает страницу раздела с карточками документов. Каталог — `docs/sections.json`: порядок разделов, их документы, у снимков — `title`, `date`, `source` (оригинал), `aliases` (другие адреса того же оригинала), `about`.
  - **Справки механик** — `docs/NN-slug.md` (eager, `marked`). Формат: **Что это → Как работает → Ключевые рычаги → Где в конфиге**. Deep-link на конфиг: `[текст](config:<key>)` / `[текст](config:balance/<группа>)` → секция «Игра» (`gotoConfig`); на другой документ — `[текст](doc:library/<файл>)` или `(doc:section:<id>)`; якоря `#заголовок` листают внутри справки. Стиль — `.doc-body` в `index.html`.
  - **Библиотека** — `docs/library/*.html|md`: снимки проектных документов (артефактов), которые мы готовили: ГДД ковки, серия о сервере, решения по анимации, экономика, звук, роадмап. Грузятся ЛЕНИВО (свой чанк на документ). HTML — как есть в `iframe srcdoc` с песочницей `allow-scripts allow-popups allow-popups-to-escape-sandbox` и `allow="clipboard-write"` (без `allow-same-origin`: скрипты страницы работают, до редактора не дотягиваются; `localStorage` внутри бросает — страницы это переживают в `try`). Окно, открытое из документа (оригинал на claude.ai), уже без песочницы — поэтому внешние ссылки уходят через редактор сообщением `{dmDocLink}`, а не открываются самой страницей. Якоря `#…` скрипт рамки листает сам: у `srcdoc` они резолвятся от адреса редактора и грузили бы в рамку редактор. Тема тёмная/светлая — `data-theme` на `<html>`, переключатель меняет её сообщением `{dmDocTheme}` без пересоздания рамки. Над документом — дата снимка и «оригинал ↗»: живая версия могла уйти вперёд.
  - **Добавить документ:** положить файл в `docs/library/` (HTML артефакта — тот, что отдаёт `Artifact read` с `path: "index.html"`; служебный блок `<!-- frame-runtime -->` вырезать) и строку в `docs/sections.json`. Сторож `docsCatalog.test.ts` краснеет на файл без строки, строку без файла, снимок без даты или оригинала и на ссылку `claude.ai/…artifact/…`, которой нет в каталоге.

## Секция «Игра» — возможности редактора конфигов

- **Страницы по механикам:** Баланс, Классы, Предметы, Аффиксы, Уники, Монстры, Подземелья, Скиллы (активные/пассивные), Квесты (основные/случайные) — навигация слева.
- **Полный CRUD** для конфигов-массивов: список записей + форма; «Новая», «Дублировать», «Удалить». Узлы деревьев скиллов редактируются как записи (поля `requires`, `x`, `y` — связи/позиции).
- **Авто-формы** из схем: `src/form.ts` рекурсивно строит контролы под тип поля (object/array/tuple/record/enum/number/string/boolean). Скаляры пакуются в адаптивную сетку `minmax(200px,1fr)`, вложенные объекты/массивы/union — на всю ширину.
  ⭐ 08.10: `fieldLabels` (по имени ключа) — русская подпись над полем «подпись · ключ» (только уникальные ключи: «Оформление» биома `dressing`, его `torch`/`statues`/`firePits`, `spacing`, `cornerGap`…); `objectId`/`objectIds` — выпадашки из «Объектов»; `modelId` объекта и проверка ссылок принимают ключи окружения каталога Unity (`art`, kind env) — факел, статуи, костры без GLB не «битые».
  ⭐ 08.10: огонь объекта `objects[].fx` («Огонь (Unity)») — свой рендер `fieldCustomRenderers.fx` в `main.ts`: вид выпадашкой из `OBJECT_FX_KINDS`, «— нет огня —» снимает поле целиком (общий рендер необязательного объекта оставил бы `{ scale }` без вида — схема не прошла бы), размер и сдвиг от маркера — при выбранном виде. Читает только Unity (частицы и звук огня), документ — «Подземелье», раздел «Огонь объекта».
- **Компоновка на один экран:** страница фикс-высоты (flex-колонка); слева скроллится навигация, справа — форма; тулбар «Применить/Экспорт/…» липкий сверху.
- **Валидация** при «Применить»/импорте — сломанный конфиг не пройдёт.
- ⭐ **Запертый тир сложности (R8-13):** «Сложности» и «Шаблоны забега» сохраняются (оба «Применить») только через подтверждение,
  если после правки включённый тир не откроется никогда — порог `unlockFloor` глубже самого длинного включённого забега
  (`runMaxDepth` = `length.max` + финал) или предыдущий тир выключен (`lockedDifficulties` из `@dm/shared`). «🔎 Проверить конфиг»
  показывает то же ошибкой. Данные в репозитории стережёт `shared/src/config/difficultyReach.test.ts`.
- **Live-apply в игру:** «Применить» пишет оверрайд в `localStorage` (`dm:configOverride`) + шлёт `BroadcastChannel('dm-config')`; клиент применяет через `ConfigRegistry.reload`. «Применить везде (в файл)» / актуальный конфиг — через сервер `/api/config`.
- ⭐ **Запись — только поверх загруженного конфига сервера (C-09, `src/liveConfig.ts`).** Пока `/api/config` не загружен (сервер лежал на
  открытии: перезапуск `tsx watch`, недоступная машина), рабочая копия — встроенные дефолты, и записи нет вовсе («Применить», «в файл»,
  инструменты «Ковки», «Убрать битые») — таблица из дефолтов целиком затёрла бы правки на сервере; загрузка повторяется с паузой
  (`LOAD_RETRY_MS`). Загружен — тело записи несёт `__baseRev` (ревизии загруженных таблиц, `configRev` из `@dm/shared`), и сервер
  отказывает **409**, если таблица на нём уже другая (сохранили в другой вкладке, инструментом, с другой машины): статус просит обновить
  страницу. Принятая запись сдвигает базу ревизиями из ответа (`rev`); вкладкам игры (`BroadcastChannel`) правка уходит только ПОСЛЕ
  ответа сервера. Тест — `src/liveConfig.test.ts` (+ сервер `configWrites.test.ts`, общая ревизия — `shared/config/configRev.test.ts`).
- ⭐ **Запись и её проверка — канал `src/configChannel.ts` (R22-08).** «Применить», «в файл», инструменты «Ковки», «Убрать битые» и «Сбросить»
  идут через `ConfigChannel` (`main.ts` даёт ему `devFetch`, `BroadcastChannel` и строку статуса). Рабочая копия, база записи и вкладки игры
  двигаются только с ответом сервера. **«Сбросить»** шлёт DELETE ПЕРВЫМ: отказ (422 — без оверрайда связанная таблица нарушит правило поверх
  таблиц, R21-01; 409; нет связи) не трогает ничего, принятый — перечитывает таблицу у сервера (`GET /api/config`: файл на диске, а не бандл
  редактора) и только её кладёт в форму, базу и вкладки; не вышло перечитать — база прежняя, правка поверх старой копии получит 409. Раньше
  форма и вкладки получали встроенные дефолты до ответа, отказ оставлял их такими, и следующее «Применить» одного поля заменяло весь баланс
  хозяина дефолтами. **Правило поверх таблиц (D4)** проверяется над ЖИВЫМИ прочими таблицами (`LiveConfigBase.value`: загруженное и принятое),
  как у сервера, а не над неприменёнными таблицами рабочей копии. Тесты — `src/configChannel.test.ts` (настоящие ручки сервера, `configChannel.fuzzKit.ts`)
  и фаззер «редактор ≡ сервер» `src/configChannel.fuzz.test.ts` (`DM_FUZZ_SEEDS`, `DM_FUZZ_OPS`, `DM_FUZZ_TRACE`; самопроверки — прежний сброс и
  прежняя проверка правила ловятся).
- ⭐ **Встроенные файлы и инструменты — читателем (R22-01).** Рабочая копия до ответа сервера — `bundledWorkingCopy()` (схема каждой таблицы,
  без правила поверх таблиц), и реестры инструментов «что, если» (калькулятор, симулятор, ковка, генераторы) — `loadAll(data, { cross: false })`:
  файлы данных, вместе нарушающие D4 (сервер их приводит с инцидентом «поправить в редакторе»), раньше роняли редактор на старте модуля. Правило
  судит запись (канал выше) и сервер.
- **Экспорт/импорт** JSON по конфигу; «Сбросить» — снять оверрайд таблицы на сервере (к файлу данных), форма — таблица, которую собрал сервер.

## 🔨 Ковка — прототип ковки оружия из деталей

ГДД — `docs/CRAFT_WEAPONS.md`. Четыре вкладки:

- **⚒ Ковка** — в центре ИГРОВАЯ панель `client/src/modules/town/craftPanel.ts` (та же стоит во вкладке
  «⚒ Ковка» кузницы города — там её хозяин шлёт команды серверу): семейство → ключевая деталь (она определяет тип) → детали, у каждой свой материал; тип,
  историческое имя и ступень окно выводит само. Вокруг песочница (`craft.ts`): герой (класс, уровень, пресет атрибутов, бонусы урона/скорости
  для проверки конверта билдов), сырьё и журнал (бесконечные / реальные), материалы, которых ещё нет в
  игре, и **песочные правки данных** (лестница блока по классам, грань «колющий» стрелковому) — живут
  только в копии конфига вкладки. Под окном: настоящий бой (`simulateMicroFight`, бот только базовыми
  ударами, пачка ×1/×3/×5) и сравнение с 200 найденными той же базы и ступени (перцентиль; найденные
  теперь разные — урон катается в вилке ступени). Ковка в песочнице катает бросок базы (`rng` от сида
  песочницы), окно до ковки показывает вилку и ряд «Доводка» (`balance.craft.finish`). Ковка и зачарование
  песочницы — ТЕ ЖЕ `craftAction` / `enchantAction` (`@dm/shared`, `economy/townActions.ts`), что исполняет сервер,
  над копиями её сумки и сундука (ключ заявки `sandbox-<сид>`): своего списания во вкладке нет, отказы и цены
  совпадают с игрой. Отличия — только галки стенда: «Журнал: всё открыто» (`fullJournal`) и «Материалы, выключенные
  в конфиге» (`allowDisabledMaterials` — сервер его не передаёт никогда; с врезки все 40 материалов включены,
  так что галка нужна лишь для выключенного дизайнером — подсказка галки говорит ровно это); флагу `balance.craft.live` песочница
  не подчиняется. ⚠ Повторное зачарование уже зачарованной вещи песочница теперь отклоняет — как сервер. ⚠ Надетую
  скованную — тоже (R1-26): хозяин песочницы (`craftSandboxHost.ts`, без DOM — проверяется в node,
  `craftSandbox.test.ts`) отвечает окну `find`, как игра, и после «Надеть» зачарование гаснет с причиной «Надетую не
  зачаровать» — иначе зачаровывалась копия, а бой и сравнение «в руках» брали прежнюю. Справа —
  3D-превью (`client/src/modules/town/craftPreview3d.ts`, переехал из редактора — тот же стенд стоит в кузнице
  города): модель из тех же деталей (`client/modules/town/craftMesh`) — свой силуэт
  у каждого варианта, цвет по материалу каждой детали. Обновляется сразу на любой выбор в окне (колбэк
  `onChange` у `craftWindow`), тянуть мышью — повернуть, колесо — приблизить, двойной клик — крутить.
- **▦ Сетка баланса** (`craftGrid.ts`) — лампочки инвариантов ГДД на текущих данных (разброс ДПС в
  конверте ≤ 8 %, площадь держака, «неключевые гнёзда не двигают ДПС», форма ≤ дропа, переплавка в минус,
  затенённые правила имён). Замеры — при ФИКСИРОВАННОЙ базе и ступени (`craftWeapon(..., { atTier })`),
  тепловая карта «ударная часть × конверт», держак в бою по пачке, оголовье, замер частот форм аффиксов
  против `balance.craft.formMult`. ⚠ R17-03: строку цены формы, которую даёт ёмкость (`capacityByTier`), ✕ не убрать, а ключ —
  только «P+S»: «Применить» отвечает ошибкой валидации с именем формы (раньше форма без строки молча шла по ×1).
- **📖 Каталог и разбор** (`craftCatalog.ts`) — петля открытия: нарезать дроп реальным генератором →
  разобрать → журнал, эскизы, сырьё по деталям; **кодекс типов** (видел / сковал / можно / чего не
  хватает) и каталог деталей по классам.
- **🗡 Клинки** (`craftBlades.ts`, ГДД §26) — статы клинка из геометрии модели. Ручки `balance.craft.blade`
  (вилки по длине, разброс от ширины, баланс от центра тяжести, формы фальшиона и сабли) и величины
  `strike` / `headBlock` правятся прямо здесь, таблица всех мечевых клинков пересчитывается сразу — через

⭐ **R7-15: мост — `App` БЕЗ СЕРВЕРА (`new App({ offline: true })`).** Конфиг моста — ровно данные инструмента
(песочница ковки — со своими оверрайдами: «Лестница блока», «Грань дальнего боя»; калькулятор — рабочая копия редактора,
с «Применить» или без). Раньше конструктор `App` тянул `/api/config` и через миллисекунды клал серверный конфиг поверх:
первый кадр считал по песочнице, следующий клик — по серверу, а галочка оставалась включённой; ещё и каждый мост держал
свой канал «Применить» (`BroadcastChannel`) навсегда. Правка в редакторе доходит до моста из тех же данных —
`followHarness(app, data)` на каждой перерисовке (перечитывает, только если данные изменились; сейв и панели моста целы).
Тест — `gameHarness.test.ts` (корневой `vitest.config.ts` знает псевдоним `@dm/client`, как `vite.config.ts` редактора).

## Инструментальные роуты — только через `devFetch`

Все обращения к `/api/dev/*` идут через `devFetch` (`@dm/client/devAuth.js`): он подставляет токен админа и
переспрашивает вход при 401 (запись конфига — канал `configChannel.ts`, его `send` в `main.ts` — `devFetch`). ⚠ 15.09.2026 нашёлся
ЕДИНСТВЕННЫЙ вызов в обход — кнопка «Сбросить к дефолту» (тогда `resetOnServer`) ходила голым `fetch`, всегда получала 401 и **не работала никогда**, причём сообщение об
ошибке списывало это на недоступный сервер. Если добавляешь новый инструментальный роут — проверь grep-ом,
что он не мимо: `grep -rn "fetch('/api/dev/" --include=*.ts packages/ | grep -v devFetch` обязан быть пуст.

Отдельная грабля со стороны сервера: `/api/config` отдаёт слабый ETag, и он обязан считаться по ВСЕМУ телу
(`server/src/configEtag.ts`). Была выборка каждого 64-го символа — правка числа той же длины давала тот же
ETag, редактор получал 304 и показывал старое.

## Ключевые файлы

- `main.ts` — оболочка (таб-бар) + `renderGame` (nav+страница) + `gotoConfig`; состояние `section`/`view`/`current`.
- `docs.ts` — секция документации (разделы, рамка для HTML-снимков, ленивая загрузка, deep-link); `docsCatalog.ts` — её чистое ядро (каталог, сторож, подготовка снимка). Контент: `docs/NN-*.md` — справки, `docs/library/*` — снимки документов, `docs/sections.json` — каталог разделов.
- `form.ts` — авто-формы из zod; `sim.ts`/`calc.ts`/`sweep.ts`/`itemGen.ts`/`monsterGen.ts`/`runGen.ts` — инструменты; `passiveGraph.ts`/`skillGraph.ts` — граф-редакторы; `gameHarness.ts` — мост к реальным панелям игры.
