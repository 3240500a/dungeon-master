# @dm/editor — HTML-редактор

Отдельная Vite-страница для правки всех игровых конфигов + инструменты + документация. Формы авто-генерируются из zod-схем `@dm/shared`, поэтому новое поле схемы сразу появляется в редакторе. Запуск: `npm run editor` (порт 5174). Прод: собранный клиент и редактор на одном origin.

## Верхние секции (таб-бар в шапке, `main.ts` → `section`, персист в localStorage)

- **🎮 Игра** — левый nav (свёртываемые группы конфигов) + инструменты-вкладки (🧪 Симулятор, 🗺 Забеги v2, 🎲 Генератор предметов, 👹 Генератор мобов, 🧮 Калькулятор, 🔥 Свипы, 🔨 Ковка); справа — авто-форма страницы (`renderPage`) или инструмент. Мостик `editorNav` (напр. Симулятор → Калькулятор).
- **🧍 3D-эдитор** — поз-редактор во всю панель через `iframe` (`pose-editor.html` клиента; dev кросс-ориджин 5173, prod относительный). Авторинг поз/анимаций/походки/поворотов/внешности/3D-моделей; сохранения — общий серверный `pose_store` (`/api/pose`).
- **📖 Документация** (`docs.ts`) — вкладки-описания механик. Контент — markdown в `packages/editor/docs/*.md`, втянут через Vite `import.meta.glob('../docs/*.md', {query:'?raw', eager:true})`; рендер — `marked`. Имя `NN-slug.md` задаёт порядок, заголовок = первый `# H1`. Deep-link на конфиг: ссылка `[текст](config:<key>)` или `[текст](config:balance/<группа>)` → после рендера навешивается клик, переводящий в секцию «Игра» на нужную страницу (`gotoConfig`).
  - **Добавить/править доку:** положить/поменять `.md` в `docs/` (dev — перезагрузить страницу, glob eager). Формат: **Что это → Как работает → Ключевые рычаги → Где в конфиге** (с `config:`-ссылками). Стиль markdown — `.doc-body` в `index.html`.

## Секция «Игра» — возможности редактора конфигов

- **Страницы по механикам:** Баланс, Классы, Предметы, Аффиксы, Уники, Монстры, Подземелья, Скиллы (активные/пассивные), Квесты (основные/случайные) — навигация слева.
- **Полный CRUD** для конфигов-массивов: список записей + форма; «Новая», «Дублировать», «Удалить». Узлы деревьев скиллов редактируются как записи (поля `requires`, `x`, `y` — связи/позиции).
- **Авто-формы** из схем: `src/form.ts` рекурсивно строит контролы под тип поля (object/array/tuple/record/enum/number/string/boolean). Скаляры пакуются в адаптивную сетку `minmax(200px,1fr)`, вложенные объекты/массивы/union — на всю ширину.
- **Компоновка на один экран:** страница фикс-высоты (flex-колонка); слева скроллится навигация, справа — форма; тулбар «Применить/Экспорт/…» липкий сверху.
- **Валидация** при «Применить»/импорте — сломанный конфиг не пройдёт.
- **Live-apply в игру:** «Применить» пишет оверрайд в `localStorage` (`dm:configOverride`) + шлёт `BroadcastChannel('dm-config')`; клиент применяет через `ConfigRegistry.reload`. «Применить везде (в файл)» / актуальный конфиг — через сервер `/api/config`.
- **Экспорт/импорт** JSON по конфигу; «Сбросить» — к значениям по умолчанию.

## 🔨 Ковка — прототип ковки оружия из деталей

ГДД — `docs/CRAFT_WEAPONS.md`. Три вкладки:

- **⚒ Ковка** — в центре ИГРОВАЯ панель `client/src/modules/town/craftPanel.ts` (та же встанет в кузницу
  города): семейство → ключевая деталь (она определяет тип) → детали, у каждой свой материал; тип,
  историческое имя и ступень окно выводит само. Вокруг песочница (`craft.ts`): герой (класс, уровень, пресет атрибутов, бонусы урона/скорости
  для проверки конверта билдов), сырьё и журнал (бесконечные / реальные), материалы, которых ещё нет в
  игре, и **песочные правки данных** (лестница блока по классам, грань «колющий» стрелковому) — живут
  только в копии конфига вкладки. Под окном: настоящий бой (`simulateMicroFight`, бот только базовыми
  ударами, пачка ×1/×3/×5) и сравнение с 200 найденными той же базы и ступени (перцентиль). Справа —
  3D-превью (`craftPreview3d.ts`): модель из тех же деталей (`client/modules/town/craftMesh`) — свой силуэт
  у каждого варианта, цвет по материалу каждой детали. Обновляется сразу на любой выбор в окне (колбэк
  `onChange` у `craftWindow`), тянуть мышью — повернуть, колесо — приблизить, двойной клик — крутить.
- **▦ Сетка баланса** (`craftGrid.ts`) — лампочки инвариантов ГДД на текущих данных (разброс ДПС в
  конверте ≤ 8 %, площадь держака, «неключевые гнёзда не двигают ДПС», форма ≤ дропа, переплавка в минус,
  затенённые правила имён). Замеры — при ФИКСИРОВАННОЙ базе и ступени (`craftWeapon(..., { atTier })`),
  тепловая карта «ударная часть × конверт», держак в бою по пачке, оголовье, замер частот форм аффиксов
  против `balance.craft.formMult`.
- **📖 Каталог и разбор** (`craftCatalog.ts`) — петля открытия: нарезать дроп реальным генератором →
  разобрать → журнал, эскизы, сырьё по деталям; **кодекс типов** (видел / сковал / можно / чего не
  хватает) и каталог деталей по классам.

Классификатор правится в «Ковка → Типы» (`weapon-types`): таблица «семейство × ключ → база» и
упорядоченные правила имён (первое совпадение побеждает). Условия — `hands` и `гнездо.тег`, значения
всегда списком («любое из»).

⚠ Скованное живёт только в памяти вкладки — игру она не трогает. Всё считает ядро `@dm/shared`
(`formulas/craft.ts`, `craftType.ts`, `craftCard.ts`), своих формул во вкладке нет.

## Инструментальные роуты — только через `devFetch`

Все обращения к `/api/dev/*` идут через `devFetch` (`@dm/client/devAuth.js`): он подставляет токен админа и
переспрашивает вход при 401. ⚠ 15.09.2026 нашёлся ЕДИНСТВЕННЫЙ вызов в обход — кнопка «Сбросить к дефолту»
(`resetOnServer`) ходила голым `fetch`, всегда получала 401 и **не работала никогда**, причём сообщение об
ошибке списывало это на недоступный сервер. Если добавляешь новый инструментальный роут — проверь grep-ом,
что он не мимо: `grep -rn "fetch('/api/dev/" --include=*.ts packages/ | grep -v devFetch` обязан быть пуст.

Отдельная грабля со стороны сервера: `/api/config` отдаёт слабый ETag, и он обязан считаться по ВСЕМУ телу
(`server/src/configEtag.ts`). Была выборка каждого 64-го символа — правка числа той же длины давала тот же
ETag, редактор получал 304 и показывал старое.

## Ключевые файлы

- `main.ts` — оболочка (таб-бар) + `renderGame` (nav+страница) + `gotoConfig`; состояние `section`/`view`/`current`.
- `docs.ts` — секция документации (glob + marked + deep-link). `docs/*.md` — контент.
- `form.ts` — авто-формы из zod; `sim.ts`/`calc.ts`/`sweep.ts`/`itemGen.ts`/`monsterGen.ts`/`runGen.ts` — инструменты; `passiveGraph.ts`/`skillGraph.ts` — граф-редакторы; `gameHarness.ts` — мост к реальным панелям игры.
