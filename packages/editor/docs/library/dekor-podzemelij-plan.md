**Почему не поможет просто завести их в список.** Нынешняя случайная расстановка:

- кидает до 2 предметов на комнату на случайную клетку в глубине, с отступом 1 от стен;
- поворачивает только на 90°, а занятые клетки считает без учёта поворота: повёрнутый стол 1.4×3 вылезает за свой резерв;
- на стену ставит только 1×1 на каждую грань по шансу, без шага;
- вес объекта зашит в 1, плотность в конфиг не выведена.

**Чего нет совсем:**

- понятий «спиной к стене», «угол», «проём», «группа», «стопка»;
- высоты у декора — ящик на ящик не поставить;
- хранения проёмов — они нигде не записаны;
- проверки проходимости с учётом декора: сейчас проверяется только сетка.

**Эталон — твоя ручная комната** в `top_down/dungeon`: стол 3x и шесть табуретов с разными поворотами не по сетке; стол 2x у стены со стулом; полка в 0.25 м от стены и книги на ней; штабель из трёх ящиков в углу; ящик и сундук между статуями; камень у статуи; арки 01 и 04 в проёмах.

## Как это делают другие

Никто из больших ARPG не сыплет декор равномерным шумом: везде авторская единица (тайл, чанк, тематическая комната, сценка) плюс слоты, в которые случай подставляет вариант. У нас генератор поклеточный, поэтому авторская единица — не целая комната, а набор-сценка внутри комнаты плюс слоты, выведенные из геометрии сетки.

## Как устроено

Схема «Как устроено» (встроенный чертёж документа, переведён в список):

**Паспорт — в Unity, правила — в редакторе, решает сервер**

- **Unity · паспорт** — места, след, опора, теги; заполняешь в Мастерской → (паспорта) → **Манифест ассетов**.
- **Манифест ассетов** — art.json: пишет только Unity, читает сервер → (паспорта) → **Сервер: расстановка**.
- **Редактор конфигов** — «Оформление» биома: плотность, слоты, наборы → (правила) → **Сервер: расстановка**.
- **Сервер: расстановка** — проходы Р0–Р6, свой сид на комнату; проверка проходимости, откат прохода:
  - → (запись декора) → **Unity строит этаж** — ровно то, что пришло с сервера; разброс поворота — хэшем, только вид;
  - → (преграды) → **Коллизия на сервере** — движение, обзор, путь монстров; мелочь без коллизии не считается.

Ты заполняешь паспорт в Unity и правила в редакторе конфигов. Сервер по ним расставляет декор и строит преграды, Unity рисует ровно то, что пришло: так картинка и коллизия не расходятся, а редактор и игра показывают одно и то же.

## Паспорт ассета

Паспорт — компонент `DmDecor` на префабе модели в Unity: свойства самого ассета, не зависящие от этажа. Заполняешь ты в инспекторе, всё видно гизмо в режиме префаба. **Положил модель и заполнил паспорт — она сама попадает в генерацию.** Запись в списке объектов нужна только чтобы переопределить что-то: частоту, свет, огонь, выключить.

| Поле | Что значит | Умолчание | Читает |
| --- | --- | --- | --- |
| Места | Свободно в комнате · спиной к стене · на стене · вставка в стену (ниша) · угол · по бокам проёма · аркой над проёмом · на сокет другого предмета · мелкий сор. Можно несколько. | свободно | сервер |
| След | Сколько клеток занимает (w × h). | из габарита модели, видно в гизмо | сервер |
| Опора | Где точка опоры относительно следа: центр · на линии стены (как у статуи) · угол. | центр | сервер |
| Лицом | В комнату · вдоль стены · кратно 90° · свободно. | кратно 90° | сервер |
| Отступ | Сколько клеток свободного пола вокруг. | 0 | сервер |
| Не загораживает проход | Нельзя ставить на полосу прохода и у косяка двери. | да, если есть коллизия | сервер |
| Коллизия, закрывает обзор | Преграда для движения; преграда для взгляда монстров. | есть коллайдер → да; выше 1.2 м → закрывает | сервер |
| Коллайдеры | Для наборов — несколько форм из детей `collider*`. | одна форма | сервер |
| Высокий | Только у дальних стен или тает вместе со стеной. | нет | сервер + Unity |
| Теги | мебель, склад, завал, ритуал… — по ним правила биома выбирают предметы. | — | сервер |
| Веса по типам комнат | малая, большая, сокровищница, босс, коридор. | все 1 | сервер |
| Вес | Как часто выбирается среди подходящих. | 1 | сервер |
| Разброс | Поворот ±N° и масштаб — только картинка, считается на клиенте по хэшу точки, одинаково у всех игроков. | 0 | Unity |
| Биомы | Пусто = биом папки ассета. | папка | сервер |

Свет и огонь в паспорт не дублируем: маркеры `light*` уже в манифесте, числа — в записи объекта. Угадывания по имени модели нет: подсказывается только след из габарита, и он виден в гизмо.

**Почему паспорт в Unity, а не в редакторе конфигов:** геометрию, опору, свет и стену видно только там, а Unity уже единственный писатель манифеста ассетов. В редакторе конфигов в форме объекта паспорт показывается подсказкой, только для чтения.

## Правила биома

Правила — решения дизайна «что, где и сколько», они зависят от биома и типа комнаты. Живут в редакторе конфигов, в форме биома → «Оформление», рядом с нынешними факелами, статуями и кострами. Сервер подхватывает правку сразу, без перезапуска.

| Правило | Что задаёт | Пример для крипты |
| --- | --- | --- |
| Плотность | Предметов на комнату от площади, минимум и максимум. | 3–6 на комнату 10×10 (вопрос 1) |
| Пустые комнаты | Доля комнат почти без декора — ради ритма. | 25 % |
| Слоты | Какие места включены и с каким шагом и шансом: у стены, угол, проём, стена, центр. | у стены — шаг 3 клетки; угол — шанс 0.5; проёмы — арки |
| Коридоры | Что можно в коридорах. | только настенное и арки |
| Наборы | Какие наборы-сценки доступны, вес, требования к комнате, лимит на комнату и на этаж. | стол со стульями — не больше 2 на этаж |
| Теги по типам комнат | Какие теги предметов где уместны. | сокровищница — склад; босс — ритуал |
| Полосы прохода | Ширина свободных путей между проёмами. | 2 клетки |
| Одинаковое не рядом | Радиус, в котором предмет не повторяется. | 4 клетки |

Биом без новых правил даёт этаж байт-в-байт как сейчас — это проверяет сторож. Правила можно включать по одному и смотреть разницу.

## Расстановка на сервере

Расставляет сервер общим кодом: он же работает в симуляторе, фаззерах и превью редактора. Unity рисует ровно то, что пришло. Проходы идут в фиксированном порядке от крупного к мелкому; каждый следующий видит клетки, занятые предыдущими. У каждой комнаты и прохода свой сид: правка одного правила не перетряхивает весь этаж.

1. **Р0. Якоря и полосы прохода.** Спавн, выходы, рычаги, двери — неприкосновенны. Кратчайшие пути между проёмами каждой комнаты расширяются до 2 клеток — в полосе ничего твёрдого.
2. **Р1. Нынешнее оформление** — факелы, статуи в нишах, костры. Без изменений.
3. **Р2. Центральная вещь комнаты** — обобщение костра: любой предмет с местом «центр» и кольцом обхода.
4. **Р3. Наборы-сценки.** Выбор по типу и размеру комнаты, тегам, глубине; якорь из слотов; 4 поворота и зеркало. Сервер разворачивает набор в отдельные предметы, чтобы коллизия была честной.
5. **Р4. Одиночки по слотам:**
   - у стены — спиной к стене, отступ на полглубины модели, с шагом и «одинаковое не рядом»;
   - угол — шаблон 2×2 по двум смежным стенам;
   - проём — арка по ширине проёма или пара предметов по бокам;
   - стена — с шагом, а не «каждая грань по шансу»;
   - высокие — только у дальних стен (север и восток при нашей камере).
6. **Р5. Мелочь без коллизии** — кости, камешки, свечи. Равномерная рассыпка (Poisson-disk) в пределах бюджета, кластерами вокруг уже стоящего. Ей можно в полосы — игроку она не мешает.
7. **Р6. Проверка на месте.** Проходимость с учётом декора (радиусом героя): спавн → выходы, рычаги, сундуки, без отрезанных карманов; свободные двери; бюджеты. Провалился проход — откатывается только он, этаж заново не строится.

**Что придётся доделать в нынешнем коде:**

- след с учётом поворота (сейчас стол на 90° вылезает за резерв);
- вес и плотность из конфига вместо зашитых;
- проёмы как сущность: сейчас нигде не хранятся;
- высота и родитель у записи декора — для стопок и сокетов;
- несколько коллайдеров у одного предмета;
- превью редактора и симулятор зовут генератор без декора — исправить, чтобы редактор показывал то же, что игра.

## Наборы-сценки

Набор — несколько предметов с авторской взаимной раскладкой, как в твоей ручной комнате. Собирается префабом в Unity (`Env/<биом>/sets/<id>/`), сервер разворачивает его в предметы. У набора есть:

- **якорь** — куда ставится целиком: у стены, угол, центр, проём;
- **члены** — ключи моделей с сдвигом и поворотом относительно якоря;
- **необязательные члены** — «оставить k из n»: один и тот же набор каждый раз выглядит чуть иначе;
- **сокеты** — точки `socket_*` на модели для «предмета в предмете»: книги на полке, свеча на столе, ящик на ящике;
- **требования** — тип и размер комнаты, глубина, биом; лимит на комнату и на этаж.

**Первые наборы крипты — из твоей комнаты:**

| Набор | Якорь | Члены | Необязательные |
| --- | --- | --- | --- |
| Трапезная | центр | стол 3x | 2–6 табуретов с разбросом поворота |
| Писарский угол | у стены | стол 2x | стул, ящик |
| Библиотека | у дальней стены | полка | книги на сокете, факелы по бокам |
| Склад | угол | два ящика | третий ящик сверху |
| Завал | угол или у стены | камень | второй камень |
| У статуи | ниша статуи | — | камень у основания, второй камень, ящик (✅ 14.10; «между статуями» отменено — статуя одна на участок стены) |

Необязательные члены выбирает только сервер: если бы клиент решал сам, картинка разошлась бы с коллизией. Разброс поворота табуретов — наоборот, только картинка.

## Мастерская декора в Unity

Одно окно в меню DM ▸ Decor: заполнить паспорт, увидеть предмет в комнате и проверить на настоящих этажах — без Play и без сервера.

| Вкладка | Что делает |
| --- | --- |
| Каталог | Все модели биома и их статус: в выпуске ли, есть ли паспорт, ставит ли сервер, предупреждения. |
| Паспорт | Инспектор и гизмо в режиме префаба: сетка 1 м, след, кольцо отступа, линия стены, стрелка «лицом в комнату», порог высоты, маркеры света и сокетов. Кнопка «Экспорт» — явная. |
| Сцена-стенд | Любой префаб открывается сразу «в комнате»: пол крипты, две стены, внутренний угол, проём, свет крипты. |
| Пробная комната | Выбранный предмет ставится во все разрешённые паспортом места синтетической комнаты. Строит настоящий код постройки этажа. |
| Этажи по сидам | Настоящий генератор на файлах данных выдаёт N этажей, Unity строит их в редакторе с наложением: полосы прохода, коллизии сервера, следы и отступы, типы комнат, дальние стены. Кнопка «Другой сид». |
| Наборы (Фаза 4) | Сборка набора префабом: якорь, члены, необязательные, общий след. |

**Проверки паспорта** — предупреждения прямо в окне:

- опора вне следа (ловит `arch_02`);
- модель больше следа больше чем на 10 см, коллайдер больше следа;
- модель висит в воздухе при месте «на полу» (ловит `books_01` — предлагает «на сокет»);
- тело уходит за линию стены у предмета «спиной к стене»;
- высокий предмет без отметки «высокий».

Итоговая проверка — в игре, по твоим скринам.

## Как проверяем

Проверка идёт на трёх уровнях: тесты на каждую правку, сводка по сотням сидов для настройки, предупреждения в редакторах.

**Сторожа (каждая правка):**

- полосы прохода без твёрдого декора; двери, выходы, рычаги свободны;
- связность с учётом декора на сотнях сидов — без отрезанных карманов;
- детерминизм: один сид — один этаж;
- биом без новых правил — этаж байт-в-байт прежний;
- паспорт читается одинаково на сервере и в Unity (эталон из TypeScript сверяется в C#);
- нынешние сторожа оформления, сундуков, проходимости и фаззеры сервера — зелёные.

**Сводка по сидам (как «документ средних» Path of Exile):** 500 этажей на биом → предметов на комнату (минимум, медиана, максимум), доля занятого пола, доля пустых комнат, сколько раз какой предмет и набор попали на этаж, сколько отказов проходов. По ней крутим бюджеты, а не на глаз по одному этажу.

**Предупреждения в редакторе конфигов:** предмета нет в каталоге Unity; набор шире самой маленькой комнаты биома; высокий предмет разрешён у ближней стены; предмет с ролью, которую расстановка молча пропускает.

**В игре:** замер fps с декором на наборах графики и твои скрины — вид оцениваешь ты.

## Фазы

Пять фаз подряд, каждая оставляет игру рабочей. На каждую — исполнитель и независимая проверка; после каждой — твои скрины и «дальше».

| Фаза | Что делается | Что увидишь | Твоя работа |
| --- | --- | --- | --- |
| **Ф1. Паспорт** | Компонент `DmDecor`, экспорт в манифест, «модель с паспортом — уже объект», сторож сервер↔Unity. Правки нынешнего кода: след с поворотом, вес и плотность из конфига, превью редактора с декором. | 14 моделей в игре россыпью по своим паспортам. | Паспорта для 14 моделей — около часа. |
| **Ф2. Слоты и полосы** | Проходы Р0, Р2, Р4, Р6; проёмы как сущность; правила в «Оформлении» биома; сводка по 500 сидам. | Полки и столы спиной к стене, ящики в углах, арки в проёмах; проходы свободны. | Плотность и шаги в редакторе конфигов. |
| **Ф3. Мастерская** | Окно DM ▸ Decor: каталог, гизмо и проверки, сцена-стенд, пробная комната, этажи по сидам. | Подбор паспортов и правил без Play. | Проверить паспорта по гизмо, починить модели с предупреждениями. |
| **Ф4. Наборы** | Набор — префаб в Unity; сервер разворачивает его (Р3); высота и сокеты; несколько коллайдеров. | Трапезная, писарский угол, библиотека, склад со штабелем. | Собрать 4–6 наборов. |
| **Ф5. Мелочь и скорость** | Россыпь без коллизии (Р5); склейка статичных предметов в куски, как пол; настройка бюджетов по сводке. | Живее и без просадки fps. | Модели мелочи (кости, камешки, свечи), если есть. |

Порядок можно менять: если важнее сначала удобно заполнять паспорта, Мастерская (Ф3) встаёт сразу после Ф1.

## Риски и что нельзя сломать

| Риск | Чем грозит | Что делаем |
| --- | --- | --- |
| Порядок выкладки | Сервер ставит предмет, модели которого нет в выпуске контента → невидимая стена. | Сначала публикация контента, потом конфиг; сторож «предмет есть в каталоге». |
| Перегенерация этажей | Смена правил меняет этажи на тех же сидах; у идущих забегов включится таймер «смена правил». | Новые проходы — свои потоки случайности; старые не сдвигаются. |
| Проходимость | Плотный декор отрезает кусок комнаты или выход. | Декор не меняет клетки сетки; полосы и проверка Р6 на каждом этаже. |
| Две копии правила «что расставляется» | Сервер и Unity разойдутся: предмет есть в коллизии, но не нарисован. | Сторож-эталон из TypeScript в C#. |
| Высокий декор | Полка или арка у ближней стены закрывает героя. | Высокие — только дальние стены или тают со стеной. |
| Декор похож на интерактив | Декоративный сундук рядом с настоящим путает игрока. | Вопрос 4. |
| Производительность | Сейчас каждый предмет — отдельный объект сцены; десятки на комнату ударят по fps. | Замер в Ф2; склейка статичных в Ф5. |
| Плохие модели | Смещённая опора (`arch_02`), накладка вместо предмета (`books_01`), высокая арка без затухания. | Проверки паспорта ловят сразу. |

**Не ломаем:** расстановку решает только сервер; один сид — один этаж; сетку декор не трогает; число монстров от декора не зависит; всё, что читает расстановка, входит в игровую ревизию конфига; значения живут в файлах данных, а не в коде; Unity строит этаж по кадрам.

## Что решить

Пять вопросов перед стартом Ф1. Выбери в последней колонке; если «иначе» — напиши комментарий к строке.

| # | Вопрос | Рекомендую | Почему | Решение |
| --- | --- | --- | --- | --- |
| 1 | Плотность декора | 3–6 предметов на комнату 10×10, включая набор; около 25 % комнат почти пустые; в коридорах только настенное и арки. | Ритм «полно — пусто» читается лучше ровной заставки; бой не застревает. Числа крутятся в конфиге. |  |
| 2 | Где собирать наборы | Префабом в Unity. | Форма, свет и взаимная раскладка видны только там; альтернатива — 2D-сетка в веб-редакторе, но веб-рендер заброшен. |  |
| 3 | Мелочь без коллизии: сервер или клиент | Ставит сервер. | Одна правда: её видят превью редактора и сводка; объём маленький — десятки записей на этаж. Клиент дешевле, но вне превью. |  |
| 4 | `crypt_wooden_chest_01` — декор или лут | Модель настоящих сундуков с лутом. | Сейчас сундуки — тонированные коробки; декоративный сундук рядом с настоящим путает игрока. |  |
| 5 | Арки | 01 и 04 — рамы для проёмов шириной 3 и 4; `arch_02` не ставим, пока не починишь опору. | Ширина коридора по умолчанию — 4; `arch_02` похож на обломок с опорой в 7 м от модели. |  |
