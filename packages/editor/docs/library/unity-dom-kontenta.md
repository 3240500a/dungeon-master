## Контекст

Решение владельца (07.10): полностью на пайплайн Unity. glTFast убираем, модели — FBX, импортированный самим Unity. Веб-клиент не трогаем и веб-рендер забываем. Поз-редактор остаётся как есть: он показывает, как меш живёт с анимациями. Вся красота — в Unity, удобно и без костылей.

Аудит (три читателя: Unity, сервер и поз-редактор, индустрия) показал:
- **В Unity-проекте нет ни одного художественного ассета.** Нет FBX, префабов, `.mat` и текстур, нет AssetPostprocessor. Всё собирается в рантайме: GLB через glTFast (персонажи, оружие, тайлы, ковка), PNG из `textures[]`, материалы кодом из `materials[]`.
- **Unity видит не исходный FBX, а дважды перегнанный GLB.** Цепочка: FBX → three FBXLoader → GLTFExporter → сервер → glTFast. Исходник рыцаря весит 6.1 МБ, GLB — 13.5 МБ: индексы раскрыты, 3800 лишних бинд-матриц. У мешей нет касательных, поэтому нормалмапы персонажей освещаются неверно.
- **Контента пока мало** (5 моделей, 5 материалов, 14 текстур), переезд сейчас дешёвый.
- **Ядро анимации от формата не зависит** (ClipPlayer, WebRig, Retarget, LegCanon, твисты, рэгдолл). На FBX оно работает без переписывания при пяти условиях импорта: Strip Bones off, Sort Hierarchy off, Optimize GO off, касательные MikkTSpace, имена как в файле.
- **Серверу из моделей нужен только коллайдер декора.** Остальное (`slots`, `boneMap`, `boneOffsets`…) читают Unity и поз-редактор; `modelId` и `atlasKey` сервер пересылает как непрозрачные строки.
- **Поз-редактор FBX уже читает** (`loadModelUrl` по расширению). GLB он делал только для веб-игры.
- **Уходит около 2.5 тыс. строк костылей:** CharacterLoader, сторож и нормировка EnvKit, FitModel/UpAxis, GlbMat, ModelHand, glTF-шейдеры в вариантах; с материалами-ассетами — ещё MaterialLoader, TexturePack, UrpLit.Map, MaterialsCheck, рантайм-сжатие.

## Как это делает индустрия
- Данные ссылаются на контент **стабильным ключом**: DisplayID у WoW, Primary Asset ID у Unreal, address у Addressables. Внешние инструменты питаются **манифестом, который выгружает движок**, а не читают его форматы.
- **Проверки на трёх уровнях:** редактор данных, сборка, рантайм (видимая заглушка, а не пустота).
- **Материалы собирают в движке** (мастер-материал + варианты), внешний редактор хранит только ключ.
- **Импорт FBX — правилами по папкам:** пресеты + AssetPostprocessor с `GetVersion()` и жёсткими проверками.
- **Контент — Addressables:** в разработке «Use Asset Database», без сборки бандлов; Resources Unity не рекомендует.
- **Оружие из деталей** (Borderlands): по сети ходит список деталей, а не геометрия.

## Решения (одобрены 07.10)
- **Р1. Материалы и текстуры живут в Unity** (`.mat` URP Lit + Material Variants для ступеней, биомов и редкости). В конфиге остаются только ключи (`materialByClass` и т.п.). Разделы «материалы/текстуры» редактора конфигов уходят.
- **Р2. Дом арта — проект Unity** (`Assets/DM/Art/…`, git LFS уже настроен на fbx/png/tga/psd/exr). Исходники FBX сейчас лежат вне репозиториев — переезжают сюда.
- **Р3. Ключ контента = id из конфига, он же Addressables address.** Пример: `knight_06_modular_rig`. Ключ не выводится из пути, иначе перенос папки сломает конфиг.
- **Р4. Unity выгружает манифест** (новая секция конфига `art`, у неё один писатель) и копию FBX для поз-редактора (`/assets/src/<key>.fbx`). Сервер берёт из манифеста коллайдеры, редактор конфигов — списки ключей.
- **Р5. Addressables сразу** (локальные группы, «Use Asset Database» в разработке). Удалённый каталог — позже.
- **Р6. Кованое оружие:** сейчас — компактный двоичный меш от серверной печи (без glTFast, «одна правда» о форме остаётся на сервере); цель — авторские детали-FBX с сокетами, когда будут ~40 клинков владельца.
- **Р7. Договор об единицах и осях:** Unity в метрах, 1 клетка = 1 м, Y вверх, лицом +Z, пивот оружия = хват. Импорт падает с понятной ошибкой, если модель не по договору.
- **Р8. Анимация остаётся своим кодом** (без Mecanim и Humanoid Avatar): иначе сломается «редактор ≡ игра». Rig = Generic, Avatar не используем.

## Фазы

**Ф0. Фундамент и сторожа** (видимых изменений нет)
- Убрать мусор из Assets: Screenshots (274 PNG), TutorialInfo, `_Recovery`.
- Раскладка `Assets/DM/Art/{Characters, Monsters, Weapons, Env/<биом>, Props, Materials, Textures}`.
- **Импортёр моделей** (пресеты по папкам + `DmModelImport : AssetPostprocessor`):
  - Convert Units on, Bake Axis Conversion — по замеру;
  - Rig Generic, Strip Bones **off**, Sort Hierarchy **off**, Optimize GO **off**, Import Animation off;
  - Normals Import, Tangents MikkTSpace, BlendShapes on, Mesh Compression off у персонажей;
  - Read/Write по категориям (тайлы и оружие — on, персонажи — по замеру BakeMesh);
  - Cameras/Lights off.
- **Импортёр текстур по суффиксу:**
  - `_a` — sRGB, BC7 или DXT1;
  - `_n` — Normal map, BC5, flip green по правилу источника;
  - `_m` — linear, BC7, маска R = металл, G = AO, A = гладкость;
  - Max Size по категориям, группы лимита мипов (персонажи / окружение / пропы).
- **Проверки импорта:**
  - оси (таз → голова = +Y, лицом +Z), рост в диапазоне, имена костей;
  - конвенции `collider*` / `light*` / `socket_*`;
  - имена без символов, которые чистит three;
  - у маски есть альфа. Нарушение — ошибка импорта с понятным текстом.
- **Сторож паритета:** рыцарь через импорт Unity против нынешнего GLB — имена, дерево, рест-точки суставов, `mirrorX`. До переключения.

**Ф1. Каталог, манифест, редактор конфигов**
- Addressables: группы `shared`, `char`, `family:<id>`, `biome:<id>`, `weapons`; address = ключ.
- **Экспорт манифеста** (после импорта, по меню и перед сборкой). По каждому ключу:
  - kind, сабмеши и слоты материалов;
  - кости с рест-позой узлов, сокеты, габариты;
  - коллайдеры, точки света, блендшейпы;
  - sha FBX. Отправка — `POST /api/dev/art-manifest`, плюс копия FBX в `/assets/src/<key>.fbx`.
- **Сервер:**
  - секция `art` со схемой;
  - тип загрузки FBX (сейчас octet-stream ложится как `.glb`);
  - коллайдер декора берётся из `art`, а не извлекается из GLB.
- **Редактор конфигов:**
  - выпадашки ключей из манифеста (модели, материалы, сабмеши атласа);
  - подсветка висячих ссылок;
  - убрать загрузку GLB, обрезку текстур, «Убрать битые».

**Ф2. Персонажи и монстры на префабах** (первый видимый результат: рыцарь из FBX в Unity)
- `CharacterLoader` → загрузка из каталога; FitModel → проверка с предупреждением.
- AtlasLook работает как есть: имена SMR = имена узлов FBX.
- Материалы: на префабе по ремапу имён, `materialByClass` — по ключу, все слоты рендерера.
- Перегенерировать `unity_rig_golden` с FBX; прогнать `RigMapCheck`; проверить заземление (BakeMesh) и трупы.
- `materialByClass` у пиров и монстров (сейчас только свой герой) — поле в протоколе, редеплой.

**Ф3. Окружение на префабах**
- Киты биомов — префабы: стены сразу на `DM/WallFadeLit`, свет — компонент Light из `light*`, коллайдеры — в манифест.
- EnvKit: убрать загрузку, сторож, нормировку эвристиками и GlbMat. Правила расстановки (EnvRules) и EnvBuild остаются, на префабах.
- Склейку пола кусками заменить инстансами (GPU Resident Drawer уже включён) — по замеру.
- Процедурные двери, сундуки и рычаги (WorldProps) — авторскими префабами по мере появления арта, с фолбэком.

**Ф4. Оружие**
- Префабы оружия с сокетами Grip/Tip, пивот = хват. Хваты `pe_grip` один раз перенастроить. Tip заменяет поиск конца по габаритам в DmFx.
- Ковка: двоичный меш с сервера (позиции, нормали, UV, индексы по группам, ключ материала `семья:ступень`) → Mesh API. Материал — из библиотеки Unity по ключу.

**Ф5. Материалы и текстуры в Unity**
- Библиотека `.mat` (семьи: iron, steel, leather, cloth, wood, bone, stone, trim) + Material Variants для ступеней, биомов, редкости.
- Удалить MaterialLoader, TexturePack, UrpLit.Map, MaterialsCheck и рантайм-загрузку PNG.
- Варианты шейдеров: материалы в сборке → варианты сохраняются штатно. `DmShaderVariants` остаётся только для шейдеров, которые код берёт по имени (Fx). Прогрев — `GraphicsStateCollection`.
- `Shader.Find` в коде заменить ссылками из профиля-ассета (10 мест).

**Ф6. Удалить glTFast и хвосты**
- Пакет, glTF-шейдеры и `FindShader` по GUID в `DmShaderVariants`, `ShaderKeywordSets.Gltf*`.
- Сбросы рантайм-кешей на Stop, `EnvLoadRules`/`EnvLoadCheck`, эталоны, снятые с GLB.

**Ф7. Поз-редактор на FBX**
- Модель по ключу из манифеста: `/assets/src/<key>.fbx`. GLB для моделей больше не экспортируется и не заливается.
- Сторож паритета «three FBXLoader ↔ импортёр Unity» на каждой модели (имена сабмешей, рест-точки костей, габариты).
- Две функции самолечения мерят по бинду вместо позы узлов (`poseModelsTab.ts:211,245`) — привести к правилу.
- Модули клиента, которые используют сервер и редактор (`craftMesh`, `modelAssets`, `devAuth`), не удалять. При чистке веб-клиента — сначала вынести в отдельный пакет.

**Ф8. Загрузка и прогрев**
- Прогрев по биому и этажу на FloorInit, пулы инстансов.
- У монстров — слияние SMR по подписи вида (меньше вызовов отрисовки), у игрока — SMR по деталям (экип меняется часто, нужны морфы).
- Проверка перед сборкой: каждый ключ конфига есть в каталоге, иначе сборка падает.
- Удалённый каталог Addressables — когда понадобится.

## Как будет выглядеть работа владельца
1. Кладёшь FBX и текстуры в `Assets/DM/Art/<вид>/<ключ>/`.
2. Unity сам ставит настройки, проверяет и показывает ошибки понятным текстом.
3. Материалы настраиваешь в родном инспекторе Unity. По суффиксам `_a`/`_n`/`_m` материал собирается автоматически.
4. Манифест уезжает на сервер: ключ появляется в выпадашках редактора конфигов, модель открывается в поз-редакторе.
5. В редакторе конфигов назначаешь ключ (предмету, монстру, объекту) — Unity в Play подхватывает без пересборки.

## Проверка
- Каждая фаза: `unity_check --player` (сборка + эталоны) и сторожа импорта.
- Ф0/Ф2/Ф7: паритет рыцаря «FBX в Unity ↔ поз-редактор» по рест-точкам суставов и именам, `RigMapCheck` на FBX.
- Живьём через MCP (без Play владельца): спавн героя и монстра, смена брони, этаж крипты, кованое оружие, трупы; кадры и консоль.
- Сборка плеера со Strict shader variant matching — не розовеет.
- Веб: `tsc` ×4 + `vitest` при правках сервера и редактора; фаззеры перед правкой сервера (секция `art`, коллайдеры).

## Риски
- **Два импортёра одного FBX** (three и FBX SDK Unity) могут разойтись на пре- и пост-поворотах — нужен сторож паритета на каждой модели.
- **Имена:** three чистит пробелы и `[ ] . : /`, Unity — нет. Договор об именах проверяется на импорте.
- **`modelId` записан в экземпляры вещей в сейвах** — ключи держать стабильными.
- **Хваты оружия** настроены под центр, запечённый в GLB — перенастройка один раз.
- **Правка арта больше не попадает в собранный плеер без пересборки** (в редакторе Unity — сразу). Это норма; удалённый каталог — Ф8.
