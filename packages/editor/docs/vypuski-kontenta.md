# Выпуски контента

08.10.2026 · Д3 плана [«Обновление контента без пересборки клиента»](doc:library/obnovlenie-kontenta.md) · вкладка редактора «📦 Выпуски»

## Коротко

- Каждая правка контента (конфиг, позы, клипы, арт Unity) нарезается сервером в **релиз**: номер и хэш манифеста. Канал **dev** переезжает на новый релиз сам, кнопок у него нет.
- **beta** и **live** меняются только кнопками вкладки «📦 Выпуски»: «⇢ В бету», «🚀 Выпустить» (можно по процентам), «↩ Откатить», версии клиента.
- Номер релиза у клиента **только растёт**. Откат и выпуск старого релиза — это перевыпуск того же содержимого под новым номером.
- Каждая кнопка сначала показывает подтверждение: что именно произойдёт с каналом. Если сервер заведомо откажет, вкладка скажет почему сразу, без подтверждения.

## Порядок выпуска: dev → beta → live

1. Правишь контент в редакторе или публикуешь арт из Unity. Нарезчик сервера режет релиз, **dev** встаёт на него. Проверяешь в сборке разработчика.
2. Щёлкаешь релиз в списке (строка «Выбран» над списком) и жмёшь **«⇢ В бету»**. Бета всегда получает его целиком, на 100%.
3. Тот же релиз — **«🚀 Выпустить»** в live. Процент по умолчанию — 100. Если релиз рискованный, выпускай частями: 10% → 50% → 100%.

Выпуск в live содержимого, которого нет в бете, вкладка не запрещает, но подтверждение предупредит: «в beta сейчас другое содержимое».

## Что на вкладке

- **Шапка:** ABI сервера, ключ подписи указателя (`keyId`) и что получают ещё не выпущенные каналы. Жёлтая плашка «ДЕВ-ключ» — см. «Подпись» ниже.
- **Карточки каналов** dev / beta / live:
  - **Раздаёт** — текущий релиз;
  - **Раскатка** — «100% на #15» или «10% на #18, 90% на #15»;
  - **Прежний** — тот, к которому вернёт «Откатить»;
  - **minClient / latestClient** — версии клиента;
  - **Изменён** — когда и кем: нарезчик, ключ `DM_ADMIN_KEY` или администратор.
- **Строка «Выбран»** — выбранный релиз, «⇢ В бету», поле процента и «🚀 Выпустить».
- **Список релизов** (последние 100 и все, на которые смотрит канал). У каждого релиза: номер, дата, первые 10 знаков хэша манифеста и его размер, метки каналов, ревизии конфига и игры, заметка нарезчика. Метки каналов:

| Метка | Значит |
| --- | --- |
| `live` | канал раздаёт этот релиз всем |
| `live 10%` | идёт раскатка: релиз получают ~10% устройств |
| `live · прежний 90%` | остальные устройства раскатки сидят на этом релизе |
| `live · цель отката` | прежний релиз канала: к нему вернёт «Откатить» |
| `перевыпуск #12` | релиз несёт содержимое #12 под новым номером |

## Проценты (раскатка)

- **Первый выпуск канала — только на 100%.** Тем, кто вне процента, давать нечего.
- На P% новый релиз получают ~P% устройств, остальные остаются на прежнем. Устройство попадает в «корзину» по хэшу своего id, канала и номера релиза. Внутри одной раскатки корзина не меняется: поднял 10% → 50%, и попавшие в первые 10% остаются на новом.
- **Процент только растёт.** Поднять можно двумя способами: кнопкой **«⬆ Поднять раскатку»** в карточке канала или «🚀 Выпустить» того же релиза с бо́льшим процентом. Опустить нельзя — только «Откатить».
- Пока раскатка не доведена до 100%, **другой релиз в этот канал не выпустить**: сначала доведи до 100% или откати.
- Клиент, который не прислал id устройства, получает новый релиз только при 100%.

## Откат

- **«↩ Откатить к #N»** возвращает канал к прежнему релизу. Канал сразу встаёт на 100%, идущая раскатка снимается.
- Откат делается **под новым номером** (перевыпуск). Клиент, уже взявший плохой релиз, видит номер больше своего и принимает откат. Подставной старый указатель с меньшим номером он отвергает. Файлы при этом не копируются: новая запись ссылается на тот же манифест.
- **После отката у канала нет прежнего релиза**, поэтому второй «Откатить» не вернёт плохой. Чтобы перейти к другому релизу, щёлкни его в списке и нажми **«↩ Откатить к выбранному #N»**.
- Выпуск старого релиза кнопкой «Выпустить» — тоже перевыпуск под новым номером, это нормально.

## Версии клиента (minClient, latestClient)

- Задаются на канал (и ABI), кнопка **«Сохранить версии клиента»** в карточке. 0 — не задано.
- **minClient** — сборки игры ниже этого номера видят экран «Вышло обновление игры — обновите её в Steam», вход закрыт.
- **latestClient** — сборки ниже видят плашку «Доступно обновление», играть можно.
- `minClient` не может быть больше `latestClient` (если тот задан).
- ⚠ **Поднимай minClient только после того, как Steam уже раздал новую сборку.** Иначе игроки застрянут на «обновитесь», как это было у Path of Exile 2.
- Новая нарезка версии клиента не сбрасывает: они принадлежат каналу, а не релизу. Номер сборки клиента Unity — `ContentSync.ClientBuild`.

## Если сервер отказал

Ошибка показывается красной плашкой над карточками, текстом сервера.

| Текст | Что делать |
| --- | --- |
| «нужен вход администратора» | войти: роль admin или ключ `DM_ADMIN_KEY` |
| «нет прав администратора» | выдать роль: `npm run grant-admin` |
| «первый выпуск только на 100%» | выпустить на 100%; проценты — со следующего релиза |
| «процент раскатки только растёт» | вернуть прежний — «Откатить» |
| «идёт раскатка #N» | поднять её до 100% или откатить, потом выпускать другой |
| «нет файлов в хранилище» | релиз нарезан не целиком, или файлы убрала уборка. Нарежь заново: правка контента или `POST /api/dev/content/release` |
| «откатывать некуда» | выбрать релиз в списке → «Откатить к выбранному» |
| «сервер не знает ручек выпуска» | сервер собран до Д3 — перезапустить |
| «сервер не отвечает» | сервер не поднят, или прокси редактора смотрит не туда (`DM_API`) |

## Подпись и ДЕВ-ключ

Указатель версии подписан Ed25519. Клиент Unity проверяет подпись своими зашитыми ключами (`contentKeys` в `server.json` сборки). Если `DM_CONTENT_SIGN_KEY_FILE` не задан, сервер в разработке сам заводит **ДЕВ-ключ** (`packages/server/dev-secrets/`, вне git), и вкладка показывает жёлтую плашку; на проде без ключа указатель вообще не подписывается. Сборка игрока с боевым ключом такой указатель отвергнет и останется на старом контенте, а выпускная сборка без ключа не собирается вовсе. Для беты и продакшена нужен свой ключ — как его завести и сохранить, описано в `docs/DEPLOY.md`.

## Чего пока нет

- CDN и ветки Steam — позже. Пока файлы раздаёт наш сервер, а beta и live — каналы указателя, а не ветки Steam.
- Уборка хранилища — ручка `POST /api/admin/content/gc` (по умолчанию сухой прогон). Кнопки во вкладке нет.
- dev во вкладке — только просмотр. Сервер разрешает задать minClient и на dev, для проверки экрана обновления, но только прямым запросом.
