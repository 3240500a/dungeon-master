# Модуль: progression (клиент — вью + команды)

Опыт, уровни и распределение очков атрибутов. **Авторитет — сервер** (анти-чит): XP/левелапы
и распределение считает сервер; клиент отображает `save` и шлёт команды.

- **XP/левелап (сервер):** shared `economy/progression.ts` → `gainXp(save, balance, amount)` —
  ЕДИНАЯ истина прокачки, используется и боевой наградой сессии (`GameSession.awardXp`), и
  сдачей квеста (`turnInQuest`). Клиент показывает событие `levelup`/`xp` из сессии (лог+звук).
- **Распределение (команды):** `panels.ts` шлёт `allocAttr`/`respec` серверу (`townActions`
  `allocAttr`/`respec`); клиент отображает серверный `saveUpdate`, локально ничего не мутирует.
  ⚠ R4-08: сброс атрибутов отказывает, пока надета вещь, которая держится на вложенных очках
  («После сброса не хватит атрибутов на «…» — сперва сними её»): иначе она висела бы без опоры.
  ⭐ R5-15: `respec` несёт цену с кнопки (`maxGold: respecCost`) — конфиг клиента мог отстать от серверного, и дороже
  показанного сервер не возьмёт (отказ «Цена изменилась» строкой в лог). Так же — сбросы скилов и мастерств
  (`respecPrice.test.ts`).
  - ⚠ **«OK — применить (N)» = команда на АТРИБУТ с числом очков** (`allocAttr {attr, n}`, чистый
    `allocAttrs.ts`, R2-15), а не на очко: после сброса у героя 40-го уровня ≈ 195 очков, и 195 кадров
    разом рвали соединение на 121-м (потолок кадров, 4008). «+» в окне мастера шлёт одно очко без `n`.
  - `characterPanel` (клавиша C): **полный лист персонажа (D2-стайл)** — шапка, Атрибуты (+),
    Наступление (урон/скор. атаки/крит/меткость), Защита (броня/блок/HP/мана/реген),
    Сопротивления, Прочее. `masterPanel` (NPC мастер) — «Дерево мастерства» и «Атрибуты»(+респек).
  - Производные статы (`@dm/shared` DerivedStats): accuracy, blockChance, hpRegen, manaRegen,
    resFire/Cold/Lightning/Poison. Реген HP/маны тикает в серверной `GameSession`.
- **Конфиг:** `balance` (xpTable, attributePointsPerLevel, skillPointsPerLevel,
  passivePointsPerLevel, respecCost), `classes` (старт героя при создании; респек — от старта, записанного в сейв, R18-07).
- **Формулы:** `levelForXp`, `xpForLevel`, `xpProgress` (полоса опыта, D2) (`@dm/shared/formulas/xp`); `gainXp`, `creditEarned`
  (`@dm/shared/economy/progression`); `pointsHeld`, `settleEarned` (`@dm/shared/economy/townActions`, D2).
- ⚠ **Кривая опыта строго растёт (R20-05):** `balance.xpTable` = 0, 0, дальше строго по возрастанию, числа конечные ≥ 0 — иначе
  схема отказывает (редактор получает 422). Опечатка хозяина (ступенька «xp[11..20] = 100», пропущенная цифра, повтор) поднимала
  героя 10-го одним очком опыта до 20-го с очками всех уровней, и по R9-05 это навсегда. Вторая линия — `levelForXp` по ступеньке
  не лезет. Тесты — `shared/config/registry.test.ts`, `shared/formulas/formulas.test.ts`, фаззер экономики (`xpCurve`).
- **Тесты:** XP-таблица — `shared/formulas.test.ts`; начисление/сдача — `questLogic.test.ts`;
  пачка очков — `allocAttrs.test.ts` (300 очков — не больше 4 команд), ядро и сервер — `townActions.test.ts`,
  `room.run.test.ts` (R2-15).
- **Сброс атрибутов (R6-11):** кнопка «Сбросить атрибуты» — `respecAttrs.ts`: гаснет, когда сбрасывать нечего (`attrRespecRefund` — то же число, по которому ядро отказывает «Атрибуты не вложены»), спрашивает, как сбросы скилов и мастерств, и ждёт ответа (`app.request`) — вторая команда, пока первая в полёте, не уходит (двойной клик платил дважды). Тесты — `respecAttrs.test.ts`, ядро — `shared/economy/townActions.test.ts`.
  ⭐ R19-07: горит ⇒ сервер сбросит. Гашение — `respecRefusal` (проверки ядра `respec` без записи, в том же порядке: класс, «не вложены», цена кнопки
  как согласие `maxGold`, золото, надетое без опоры), подсказка кнопки — причина сервера. Раньше кнопка смотрела только на возврат и золото: герой,
  вложивший очки ради надетого оружия, подтверждал «Вернётся 45 очк.», а в лог приходило «Не вышло: После сброса не хватит атрибутов на «…» —
  сперва сними её» (R4-08). Сторожа — `respecAttrs.test.ts`, `shared/economy/respecRefusal.test.ts` (сверка с ядром на случайных героях), шаг
  `respec` фаззера паритета B3 (`town/uiParity.fuzz.test.ts`, `FIXED` R19-07 и его «зубы»). ⚠ Unity: `MasterPanel.cs` гасит только по золоту.
- ⚠ **Сброс — от старта, с которым герой создан (R18-07):** возврат = вложенное сверх `save.startAttributes` (пишет создание
  героя), сброс ставит их же. Раньше мерил от нынешней строки `classes`: правка старта класса хозяином (живьём или деплоем) дарила
  старым героям очки, а опущенный старт делал очки базы свободными. ⚠ Сейв без поля (старше правки, R19-01) — старт по атрибуту не
  выше своего и не выше нынешней строки (`legacyStartAttributes`), пишут его вход (`RoomManager.sanitize`) и сброс; итог (Σ атрибутов +
  свободные) сброс не меняет ни при какой правке. Раньше возврат урезался очками за уровень живого конфига: «5→4» — воин 50-го терял 49
  навсегда, опечатка в строке дарила очки. Кнопка берёт то же число (`attrRespecRefund`). Тесты — `townActions.test.ts` («R18-07»,
  «R19-01»), фаззер — `economyFuzz.test.ts` (правки старта и очков за уровень, книга очков героя, сейвы без старта, I4 `respec-total`).
- ⭐ **D2 — одно правило для живой правки конфига и героев, которые уже есть:** правка хозяина (живьём или деплоем) не чеканит и не
  отнимает заработанного. Сейв помнит, что выдано: старт (R18-07) и книгу заработанного `save.earned` — очки атрибутов, скилов и мастерства,
  выданные уровнями по очкам за уровень ТОГО мига (`gainXp` → `creditEarned`), и очки скилов наград заданий; держится «вложенное + свободное
  = выдано» (`pointsHeld`). Сброс возвращает ровно вложенное — атрибуты сверх старта, скилы и мастерство Σ рангов (и за узлы, убранные из
  древа), — от живого конфига независимо; уровень не опускается (R9-05; и `sanitizeSave` больше не пересчитывает его по кривой вниз); новые
  числа — только будущим уровням. Сейв старше правила (без старта или книги) дописывают ОДИН раз вход (`RoomManager.sanitize`) и сброс —
  `settleEarned`, из того, что у героя есть, по конфигу того мига; записанное не трогается никогда. Полоса опыта (окно персонажа, HUD 2D и
  3D) — `xpProgress`: уровень выше потолка — полная, опыт ниже порога после правки кривой — с нуля, а не минусом. Тесты —
  `shared/economy/earned.test.ts`, `shared/formulas/formulas.test.ts`, `server/net/roomManager.d2server.test.ts`, профиль D2 фаззера
  экономики (`progEdit`, `reenter`; I4 `earned`, `earned-held`, `level-drop`, `refund-config`), книга в фаззере правил (I6 `earned`).
- ⭐ **Эталон паритета Unity — с ВЫВОДА настоящих окон** (`unityStatsGolden.gen.test.ts` → `__golden__/unity_stats.json` → Unity
  `StatsCheck`; разбор U5/U6): окна веба рисуются в node на поддельном DOM (`unityGoldenDom.testkit.ts`: элементы и SVG, `style.cssText`,
  `innerHTML`, подсказка `attachTooltip` — посланным `mouseenter`) с настоящим `App` без сети и `GameState` — копий правил почти нет.
  Снимается: деривы героя целиком (гир, класс брони, мастерства, древо, ауры) и резерв пулов, `xpProgress`, HUD 3D (`hud3d`: полосы, зоны
  резерва, «(−N)», «этаж · сложность · вызов ур.»), блок атрибутов мастера (`derivedBlock`), лист персонажа (`characterPanel`: блоки, строки
  ячейками, подсказки), карточки оружия и таблица «в руках → скую» окна ковки (`cardWith`, `compareTable`), предпросмотр верстака
  (`benchTarget` → `diffStrings`), древо скилов (`renderSkillTree`: свои ветки, ромбы-вставки, подсказки). Случай `caps` — со своими таблицами
  конфига (`patch`: класс брони сверх потолков бега, атаки и выдержки). Перезапись — `npx vitest run …/unityStatsGolden.gen.test.ts`.
  Рождённое часами (uuidv7-`uid`, `createdAt` сейва) пишется постоянным по порядку появления — эталон не меняется от прогона к прогону
  (иначе каждый `npm test` делал копию Unity «устаревшей»).
