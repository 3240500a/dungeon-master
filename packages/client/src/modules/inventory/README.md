# Модуль: inventory

Инвентарь, экипировка и пересчёт статов. DOM-панель поверх canvas.

- **Раскладка авторитетна на СЕРВЕРЕ.** Инвентарь (`item.pos`) — часть авторитетного сейва.
  Клиент НИЧЕГО не мутирует локально: перекладка идёт командой `moveItem` (сервер применяет
  `placeWithDisplacement` в `economy/townActions.ts` и возвращает `saveUpdate`), экип — `equip`/
  `unequip`, подбор/сброс — `pickup`/`drop`. Клиент только рисует серверную раскладку. Это чинит
  давний баг «переставил вещи → подобрал лут → раскладка сбросилась/не даёт взять, хотя место
  есть» (клиент и сервер расходились). Старые сейвы лечит `packInventory` на загрузке (`sanitize`).
- **Контракт:**
  - `equip.ts` — только `effectiveAttributes(state, exclude?)` (клиентская пред-проверка требований;
    авторитетно экипирует сервер). Локальные мутации инвентаря удалены (были мёртвым кодом).
  - `itemView.ts` — `itemCard(item, onClick?)`, `itemLines(item)`, `STAT_LABEL`, `SLOT_LABEL`.
  - `grid.ts` — реэкспорт ЧИСТОЙ сетки из `@dm/shared` (`cellFree`, `findFree`, `packInventory`,
    `addToInventory`, `hasSpace`, `placeWithDisplacement`); используется сервером, панель — только
    `itemsOverlapping` для хит-теста клетки под курсором.
  - `materialsView.ts` — склад сырья для вкладки «Ресурсы» СУНДУКА (не инвентаря!): семья ×
    ступень, в клетке ДВЕ цифры — сколько лежит в сундуке и сколько **несёшь**.
    ⚠ В панели инвентаря вкладки «Материалы» НЕТ: она имела смысл, пока сырьё было невидимым
    кошельком, а теперь оно лежит в самой сетке стеками — вторая вкладка дублировала бы её.
  - `inventoryPanel.ts` — `PanelFactory` (клавиша `I`): пупсик D2-стайл (слоты, вкл. `belt`) слева,
    сетка справа с **мульти-клеточными предметами**. Модель **«предмет на курсоре» (Diablo 2)**, но
    держимый предмет — ЧИСТО ВИЗУАЛЬНЫЙ (из сейва не удаляется, в сетке прячется): клик — взять на
    курсор, клик по клетке — шлём `moveItem` (сервер: пусто→кладёт, один под следом→обмен, 2+→отказ);
    клик по слоту пупсика — `equip`; по надетому — `unequip`; **клик держимым в мир — `drop`**; ПКМ по
    предмету (рука пуста) — меню Надеть/В пояс/Выпить/Выбросить. Размер сетки — `balance.inventory`.
- ⭐ **Сырьё лежит СТЕКАМИ в сумке** (`kind:'material'` + `count`), а копится в кошельке АККАУНТА
  (вкладка «Ресурсы» сундука). Это отдельный вид предмета, а НЕ общее стекирование: общий стек
  потянул бы за собой продажу за количество, разделение, слияние в сундуке и пояс с колбами
  (`beltBar` считает по `.length`). Материалы не экипируются, не продаются и не идут в кузницу.
  `addToInventory(items, item, dims, stackMax)` сперва доливает существующие стеки, потом занимает
  клетки; ⚠ предмет-носитель НИКОГДА не кладётся в сумку — его `count` это ОСТАТОК, который не
  влез и остаётся лежать на полу. Счётчик рисуется в ВЕРХНЕМ углу клетки: нижний занят ценой
  магазина. Размер стека — `balance.inventory.materialStack`; тесно — `rows` 6→7 даёт +10 клеток.
- **Мульти-окна:** `ui/domUi.ts` держит несколько панелей открытыми одновременно
  (инвентарь + скиллы + …), перетаскиваемых, не блокирующих игру.
- **Требования оружия:** надеть можно, только если хватает атрибутов (с учётом бонусов
  остальной экипировки) — `meetsRequirements` из `@dm/shared`.
- **Пересчёт:** производные статы считаются на лету через `GameState.derived()`
  (`deriveStats` + `modifiersFromItems`).
- **Конфиг:** `items.base` (косвенно, через предметы).
- **События:** слушает `item:picked` (косвенно — предмет уже в inventory); шлёт
  `state:changed` после экипировки (перерисовка панелей/HUD) и сохраняет через модуль save.
- **Использование:** регистрируется в `main.ts` (`domUi.register('inventory', …)`).
