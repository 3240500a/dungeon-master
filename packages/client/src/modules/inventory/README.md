# Модуль: inventory

Инвентарь, экипировка и пересчёт статов. DOM-панель поверх canvas.

- **Раскладка авторитетна на СЕРВЕРЕ.** Инвентарь (`item.pos`) — часть авторитетного сейва.
  Клиент НИЧЕГО не мутирует локально: перекладка идёт командой `moveItem` (сервер применяет
  `placeWithDisplacement` в `economy/townActions.ts` и возвращает `saveUpdate`), экип — `equip`/
  `unequip`, подбор/сброс — `pickup`/`drop`. ⚠ Всё, что экип снимает (прежняя вещь слота, щит под
  двуручником, лишние колбы меньшего пояса, пояс с колбами), примеряется в сумку РАЗОМ на копии — не
  влезает всё, значит отказ «Нет места для снятого» и сейв цел. Раньше место проверялось по вещи поодиночке,
  и второе снятое молча пропадало (R1-02). Клиент только рисует серверную раскладку. Это чинит
  давний баг «переставил вещи → подобрал лут → раскладка сбросилась/не даёт взять, хотя место
  есть» (клиент и сервер расходились). Старые сейвы лечит `packInventory` на загрузке (`sanitize`).

- **Мульти-окна:** `ui/domUi.ts` держит несколько панелей открытыми одновременно
  (инвентарь + скиллы + …), перетаскиваемых, не блокирующих игру.
- **Требования оружия:** надеть можно, только если хватает атрибутов (с учётом бонусов
  того, что останется надетым после смены) — решение сервера `equipRefusal` из `@dm/shared` (R16-08).
- **Пересчёт:** производные статы считаются на лету через `GameState.derived()`
  (`deriveStats` + `modifiersFromItems`).
- **Конфиг:** `items.base` (косвенно, через предметы).
- **События:** слушает `item:picked` (косвенно — предмет уже в inventory); шлёт
  `state:changed` после экипировки (перерисовка панелей/HUD) и сохраняет через модуль save.
- **Использование:** регистрируется в `main.ts` (`domUi.register('inventory', …)`).
