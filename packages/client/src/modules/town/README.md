# Модуль: town

NPC города: магазин, кузница и сундук (мастер прокачки — в модуле progression).

- **Магазин** (`shopPanel.ts`): продажа предметов инвентаря и покупка из ассортимента.
  Ассортимент генерируется `generateItem` (персистентен на сессию, `resetShopStock()`
  при входе в город, кнопка «Обновить»). Цены — `pricing.ts` (`buyPrice`/`sellPrice`).
- **Кузница** (`forgePanel.ts` + `forgeBench.ts` + `forgeActions.ts`): ВЕРСТАК — одна вещь
  в слоте, а не список из пятнадцати строк с шестьюдесятью кнопками. Решение всегда про ОДНУ
  вещь, и освободившееся место ушло на предпросмотр результата и построчную цену.
  - ⚠ **Вещь НЕ уходит из сумки**: слот держит только `uid`, положить — значит ВЫБРАТЬ.
    Поэтому серверной команды на «положить» нет, откатывать нечего, закрытое окно ничего не теряет.
    Цель для общего курсора `inventory/heldItem.ts` — своего перетаскивания не заводили.
  - ⚠ **Выбранный uid живёт в замыкании ПАНЕЛИ**, а не в `render`: тело окна перерисовывается на
    каждое `state:changed`, и слот очищался бы сам собой.
  - ⭐ **Первая карточка не меняет места, только смысл**: целой вещи «Улучшить», сломанной
    «Починить». Кнопки не прыгают, а какое действие главное — решает вещь. Разбор ВСЕГДА
    последний: он уничтожает вещь. Порядок и доступность стережёт `forgeActions.test.ts`.
  - ⭐ **Предпросмотр = дифф того же `describeItem`**, которым рисуется тултип: свой форматтер
    завёл бы второй источник правды и спорил бы с тултипом в одном окне. Для сломанной вещи дифф
    сам показывает снятое «Сломано» — то есть «надеть нельзя → можно».
  - ⚠ Результат улучшения считает `upgradedItem` из `@dm/shared` — ТА ЖЕ функция, которой
    `forgeUpgrade` меняет предмет. Выход разбора — `salvageRange`: настоящий `salvageYield`,
    вызванный дважды с крайними бросками, а не своя формула среднего.
  - ⭐ Инвентарь открывается ВМЕСТЕ с кузницей (`ui.openPanel('inventory')`): класть на верстак
    больше неоткуда. `DomUi` держит несколько окон — своего механизма не нужно.
  - Действия авторитетны на сервере: `forgeUpgrade` / `forgeRepair` / `forgeReroll` / `forgeSalvage`.
    Цены — `balance.forgePrices`; материалы тратятся СПЕРВА ИЗ СУМКИ, потом из сундука.
- **Ковка из деталей — ПРОТОТИП** (`craftPanel.ts` + `craftMesh/`), в игру не врезан (показывает песочница
  редактора, ГДД — `docs/CRAFT_WEAPONS.md`). `craftWindow` — окно: семейство → ключевая деталь → детали с
  материалами; тип, имя и ступень выводит ядро `@dm/shared`. Колбэк `onChange` зовётся после каждой
  перерисовки — чтобы модель рядом обновлялась сразу, а не по «Ковать».
  - ⭐ `craftMesh/` — модель оружия ИЗ ДЕТАЛЕЙ, без файлов моделей: `index.ts` (`buildCraftMesh`) собирает
    контекст из конфига, построители по классам — `blades.ts` (меч, кинжал), `hafted.ts` (топор, булава),
    `polearms.ts` (копьё, алебарда), `ranged.ts` (лук, арбалет), `magic.ts` (жезл, посох). Общие
    примитивы и КОНТРАКТ — `core.ts`: сантиметры, рукоять в начале координат, рабочий конец в −Y, четыре
    группы гнёзд с именами `strike`/`grip`/`bind`/`head`.
  - ⚠ Сторож `craftMesh.test.ts`: у разных деталей одного гнезда обязана быть разная геометрия. Новый
    вариант в `weapon-parts` без своего силуэта краснеет тестом, а не тихо рисуется «как соседний».
    Гонять свои классы: `CRAFT_MESH_ONLY=sword,dagger npx vitest run packages/client/src/modules/town/craftMesh`.
- **Сундук** (`stashPanel.ts`): ОБЩИЙ на аккаунт (shared stash) — доступен всем героям
  пользователя (перенос шмота между персонажами). Вкладки + сетка; раскладка авторитетна на
  сервере (кадр `stash` → `app.stash`), команды `stashOpen`/`stashMove`. Курсор общий с
  инвентарём (`inventory/heldItem.ts`), сетка — общий `inventory/gridView.ts`. Хранится вне
  `SaveState` (таблица `account_stash`); см. [SERVER_AUTHORITY.md](../../../../../docs/SERVER_AUTHORITY.md).
  ⭐ **Вкладка «Ресурсы»** (ключ `'mats'`) — кошелёк сырья аккаунта и кнопка «Сдать всё».
  ⚠ Она живёт ВНЕ `balance.stash.tabs`: счётчик вкладок задаёт валидные индексы для `stashMove`,
  и попадание в него сделало бы валидным перенос вещи в несуществующую сетку. Сырьё хранится
  отдельным полем `AccountStash.materials`, а НЕ ещё одной вкладкой `tabs`, потому что леджер
  предметов разворачивает `tabs` в строки `items` по uid — слияние стеков убило бы uid, и
  ночной аудит записал бы исчезнувший как `gone`.
- **Конфиг:** `items.base`, `affixes`, `uniques`, `dungeons` (для генерации), `craft-materials`,
  `salvage-rules`, `balance` (forgePrices, `stash {tabs,cols,rows}` — деф. 2×20×12,
  `inventory.materialStack`).
- **События:** открытие — по `ui:open` (NPC города шлют его при взаимодействии); операции
  шлют `state:changed`/`gold:changed` и сохраняют через модуль save.
- **Формулы:** `generateItem`, `rollAffixes` (`@dm/shared/formulas/itemgen`); сундук —
  `economy/stashActions.ts` (`stashMove`, `migrateWalletToStash`), кузница и сдача сырья —
  `economy/townActions.ts` (`forgeUpgrade`/`forgeRepair`/`forgeSalvage`/`depositMaterials`).
  ⚠ Команды, трогающие И сейв, И сундук, идут через `withStash` в `server/net/room.ts`: пишет
  атомарно и откатывает ОБА в памяти при сбое (образец — `stashMove`).
- **UI:** регистрируются в `main.ts` (`shop`, `forge`, `stash`).
