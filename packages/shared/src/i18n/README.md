## ⭐⭐ Ф1 (06.11): сервер говорит на языке игрока

С С2–С11 сервер авторитетен и в тексте: модели окон (`views/`), причины отказов и итоги команд, ответы входа, лобби и маршрута
собирает он. Решение владельца: **сервер рисует каждый свой текст на языке игрока, Unity переводит только свою обвязку**. Ф1 — серверная
сторона: русский не сдвинулся ни на байт (`__golden__/unity_views.json` после перегенерации — без изменений), а английский включается
правкой данных (`locales.en.enabled` + строки `srv:`).

### Шов (`tr.ts`)

```ts
tr(key: string, source: string, params?: TextParams): string                              // фраза кода
trn(key: string, n: number, forms: PluralForms, params?: TextParams): string               // фраза от числа
cfgText(table: string, path: readonly string[], field: string, source: string): string    // текст конфига по пути
cfgRowText(reg, table, row, field = 'name'): string | undefined                            // текст конфига по САМОЙ строке
setTextProvider(fn: (() => Localizer | null) | null): void                                 // область (ставит сервер)
setTextObserver(fn: ((key, text) => void) | null): void                                    // коды отказов (сервер)
withTextLang<T>(locales, lang, fn: () => T): T                                             // синхронная область
localizerFor(locales, lang): Localizer | null                                              // один на (таблицу, язык); источник — null
```

* **Язык не передаётся параметром** — он ТЕКУЩАЯ ОБЛАСТЬ. Иначе его пришлось бы протащить через сотни подписей формул (`itemDescribe`,
  отказы `townActions`, карточки ковки), и каждая забытая дала бы русскую строку посреди английского окна. Без области — язык-источник:
  редактор, сим и тесты работают как раньше.
* **Ключ — строковый литерал** `srv:<область>.<camelCase>`, один ключ — один исходник; исходник — литерал (или `const` со строковым
  литеральным типом: `tr('srv:salvage.starterKnown', STARTER_KNOWN)` — константа осталась текстом источника, по ней сверяются тесты и сим).
  Предложение — ОДНА строка со `{слотами}`: склейки «фраза + хвост» разобраны на варианты (`salvage.gotSketch` / `salvage.got`,
  `portal.entryOpen` / `markClosed`…). Подстановка — `String(v)`, как у шаблонной строки сегодня: число печатает тот код, что печатал.
* **Формы по числу** — только там, где код УЖЕ выбирал текст по числу (`timesWord`: «в 5 раз» / «в 2 раза»): категории `Intl.PluralRules`
  языка (русский `one/few/many/other`, английский `one/other`), а не своя арифметика окончаний.
* **Таблицы подписей** (`STAT_LABEL`, `SLOT_LABEL`, `DEBUFF_LABEL`, `RUN_NODE_LABEL`, `INTERACT_LABEL`, `RUN_*_TEXT`, `FAMILY_LABEL`…) —
  ГЕТТЕРЫ (`get armor() { return tr('srv:stat.armor', 'Броня'); }`): модуль грузится раз на процесс, а язык у каждого игрока свой.
* **Текст конфига — по объекту строки** (`cfgRowText(reg, 'skill-tree', node)`): путь ключа (`cfg:skill-tree/nodes/<id>/name`,
  `cfg:weapon-anatomy/sword/strike/tags/type/values/XXII/adj`) берётся ТЕМ ЖЕ обходом, что у извлекателя (`walkRows` в `keys.ts`), а не
  угадывается руками. Сторож `tr.test.ts` проверяет каждое текстовое поле разобранного реестра: путь по объекту = ключ корпуса сырых данных.
  ⚠ Копия строки (`{ ...row }`) — не строка таблицы: исходник. Поэтому `finishOf` переводит имя ДО копии.
* ⚠⚠ **Запекаемое — языком-источником.** Имя вещи (`Item.name`), печати (`sealName`), задания (`questFromTemplate`) и тип ковки
  (`resolveType`) кладутся в сейв — их шов НЕ трогает: имя, испечённое на английском, уехало бы в сейв русского. Переводится ПОКАЗ —
  ⭐ сделано в Ф2 (раздел ниже).

### Область на сервере (`server/src/net/textScope.ts`)

`AsyncLocalStorage`: область переживает `await` (транзакция команды ждёт базу, итог «после записи» приходит из промиса). Ставится один раз
на процесс (`installTextScope` — в `index.ts` и при загрузке модуля); язык-источник не заводит `Localizer` вовсе.

| Путь | Чей язык |
|---|---|
| `Room.handleCmd` (вся команда, с журналом кодов) | того, кто прислал |
| `Room.viewRequest`, `pushHero`, `sendSave`, `personal` (`died`/`voteStart`) | получателя |
| `sendText` / `broadcastText` (ошибки голосования, «Подойдите…», кадры `areaChanged`/`reveal` с подписями [E]) | каждого — собирается раз на язык |
| `RoomManager.onFrame` (лобби: вход, статус, «Завершить») | соединения: `join.lang` или кадр `lang` |
| HTTP: `/api/register|login|characters`, `/api/route` | запроса: поле `lang` → `Accept-Language` → источник |

### Коды отказов (`cmdResult.code`)

Клиент решал по ТЕКСТУ причины (`reason.startsWith('Цена изменилась')` — Unity `DmClient`, редактор `App`): на первом переводе это
молча ломается. Теперь у `cmdResult` есть `code` (`CmdCode` в `netTypes.ts`), и он выводится из КЛЮЧА фразы, а не из её текста: сервер
наблюдает фразы своей области (`setTextObserver`), и все ключи `srv:consent.*` — `priceChanged`; прочие — таблица `CODE_OF_KEY`
(`rateLimited`, `duplicate`, `invalid`, `townOnly`, `stationFar`, `frozen`, `noCharacter`, `serverError`, `stockRenewed`, `boardRenewed`,
`craftClosed`). Повтор номера отвечает тем же итогом и тем же кодом (код — до памяти повторов). ⚠ Поле в объекты `ActionResult` ядра не
кладётся: их сверяют `toEqual` десятки тестов и Unity-эталоны.

### Кадры языка

`{t:'lang', lang}` — в любой момент (и до входа: язык ответов лобби). Сервер принимает только включённый язык `locales` (прочее — источник),
при смене шлёт заново лист героя и отвечает `{t:'langChanged', lang}` (язык, который принят) — клиент перезапрашивает открытые окна.
⭐ 07.11: следом — `{t:'interactables', …}` (подписи [E] области на новом языке); смена платит лимит видов аккаунта — раздел «Хвосты Ф1».

### ⚠ Осталось русским нарочно

Логи, метрики, аудит и `why` записей сейва; `/api/dev/*`, нагрузочные боты (`loadtest/`), `sim-cli`, отчёты сима (`session/runner`,
`stats`); сторожа конфига для редактора (`buffTiming`, `salvageGuard`, `storedOverride`, `sets`, `dressing`, `waypointData`, схемы,
`decorStats`); грамматика (`ruAgree`); сообщения схем провода (`netSchemas` — уходят в лог, игроку — «Неверная команда»);

## ⭐⭐ Ф2 (06.11): запечённые имена в кадрах, корпус фраз кода, сторож утечек

Ф1 перевела всё, что сервер СОБИРАЕТ. Но часть текста кадров не собирается, а ЛЕЖИТ готовой: имя вещи (`Item.name`, испечено при
рождении), имя монстра (`ScaledMonster.name`, при генерации), имя и описание задания (`QuestDef`, при сборке доски — уезжает в сейв).
Печать трогать нельзя (испечённое на английском уехало бы в сейв русского) — переводится **ПОКАЗ**.

### Имя вещи для показа (`formulas/itemDisplay.ts`)

```ts
itemDisplayName(reg, item, loc = textLocalizer()): string   // язык-источник — item.name без единой операции
localizeItem(reg, item): Item                                // имя другое — копия с ним, то же — сама вещь
itemNameRecomposes(reg, item): 'ok' | 'fallback'             // сверка рецепта с испечённым (оракул)
```

Рецепт собирается из данных самой вещи тем же швом `composeItemName`: база (`baseId`), ступень (`tier`), слова первого префикса и
суффикса (`affixes[].affixId` → `affixes.word`), титул уника (`affixes[0].affixId` → `uniques`), бросок рарного имени (`nameRoll` →
`rare-names`), у скованной — ТИП по деталям во главе (`parts` → `resolveType`, показ — `typeDisplay`), у печати — вид и ступень
(`sealId`, `sealTier`), у сырья — `craft-materials`; расходник — база без ступени. Ключи фрагментов — по самим строкам таблиц
(`cfgRowKey` → `rowPathOf`), а не руками.

* ⚠⚠ **ОРАКУЛ НА КАЖДОМ ПОКАЗЕ.** Рецепт сперва собирается ЯЗЫКОМ-ИСТОЧНИКОМ и сверяется с испечённым именем; язык игрока — только
  если сошлось слово в слово. Не сошлось (база переименована после рождения, рар из сейва старше `nameRoll`, ступень сменили, а имя
  осталось) — испечённое как есть. Показ не может назвать вещь иначе, чем её назвал сервер при рождении, — только перевести.
* Сторож `itemDisplay.test.ts`: **4 315 вещей** всех путей рождения (дроп всех редкостей с пулом рарных имён и без, найденное оружие с
  деталями, уники, каждая база явно, расходники, 12 поколений лавки, стартовый набор каждого класса, подъём ступени, `retierItem`, ковка
  всех семейств × 40 сборок, зачарование скованного и найденного, печати со ступенью и без, сырьё) — на источнике **сходятся все, запасов
  0**; на псевдоязыке ни в одном имени нет кириллицы.
* ⚠ Ключ головы у `itemgen.baseHead` был `cfg:items-base/…`, а таблица в корпусе — `items.base`: перевод головы не нашёлся бы никогда.
  Исправлено (и в предпросмотре вкладки); источник строк не читает — имя не сдвинулось.

### Монстры, задания, тип ковки

* `monsterDisplayName` / `localizeMonsterDef` (`session/frameText.ts`): уник — имя пула (`monster-uniques`, по испечённому тексту) или
  «Уникальный {name}»; магический/редкий — слова первого префикса и суффикса (`monster-item-affixes`) вокруг базы, показ — шаблоном
  `item.magic` языка; иначе база (`monsters`). Снаряжение (`gearRolls[].name`) — `monster-gear`, кулаки — `srv:monster.fists`. Та же сверка.
  Последняя цель листа героя (`Room.lastTargetShown`) — тем же швом.
* Задания: доска — рецептом доски (`boardQuestName` печатает, `boardQuestText` показывает, `srv:quest.board*`), цепочка — строкой

* Тип ковки: `typeDisplay` — имя, подзаголовок и строка-формула на языке области тем же правилом (`typeTexts` — одно на печать и
  показ); `typeNameOfItem` — «кодекс «…»». ⚠ Было `cfgRowText(reg, 'weapon-types', typeOfItem(…))`: итог типа — не строка таблицы,
  перевода у него не было.

### Кадры получателю (`localizeFrame`, `NAMED_FRAMES`)

`joined` / `saveUpdate` (сейв), `stash`, `shop`, `questBoard`, `events` (выпала/поднята вещь, смерть монстра, задание), `monsterInfo`,
`view`, `hero` — проход `localizeFrame` на иноязычного получателя (обход `localizeDeep` узнаёт вещь и определение задания по виду);
дельта мира — `localizeDelta` (только вещи вновь показанной добычи `du`). Язык-источник — ТОТ ЖЕ объект.

| Путь комнаты | Как |
|---|---|
| `send` (один получатель) | кадр из `NAMED_FRAMES` — `namedFor(клиент)` |
| `broadcast` / `broadcastExcept` | `broadcastNamed`: сериализуется РАЗ НА ЯЗЫК |
| `broadcastEvents` | общая строка — раз на язык, своя строка героя — на его языке |
| `emitShared` (общий кадр мира) | буфер на всех; иной язык — свой буфер, только если в кадре есть вещь-добыча с другим именем (`langBufs`, раз на язык за тик) |
| `emitWorld` (свой кадр, AOI) | `deltaFor(клиент)` |
| `monsterInfo` новым и вошедшим | раз на язык |
| вид (`viewRequest`) | модель окна — `localizeDeep` в области игрока |
| вход | `Room.attach` берёт язык ОБЛАСТИ входа (язык соединения): `joined`, прилавок и доска уходят уже на нём, а не до `setLang` |

**Цена русской комнаты — ноль** (сторож меряет): ни одного пересобранного кадра (`counters.textFramesLocalized`), кадр мира — один буфер
на всех (`counters.worldLangEncodes`, тот же объект у каждого получателя). Смешанная комната: лишний буфер — только на тике появления
добычи, и ровно один на язык.

### Корпус фраз кода (`corpus.srv.json`, `srvExtract.ts`, `srvCorpus.ts`)

`npm run i18n` теперь проходит **дерево TypeScript** `packages/shared/src` и `packages/server/src` (без тестов и тесткитов), находит
каждый `tr()`/`trn()` и ПЕРЕПИСЫВАЕТ снимок `packages/shared/src/i18n/corpus.srv.json` (ключ → исходник; у `trn` — формы по категориям).
Исходник — литерал или `const ИМЯ = 'литерал'` (по имени во всех файлах; два значения одного имени — ошибка). Регулярка не годится:
пример в комментарии — не ключ, а исходник константой — ключ. Покрытие и `i18n:stub` идут по `cfg:` + `srv:`.

Сторож `srvCorpus.test.ts` падает, когда ключ кода не в снимке или с другим исходником, у ключа два исходника, ключ/исходник не литерал,
перевод `srv:` висит на ключе, которого в коде нет, или потерял `{слот}` источника. Сегодня **959 ключей в 1 106 вызовах** (хвосты Ф1, 07.11; `trWith` — тоже вызов шва: ключ 2-м аргументом, исходник 3-м). ⭐ 07.11: и ведущий знак (`LEADING_MARKERS`: `⚠`, `✦`, `🔒`, `▮`) — перевод начинается с того же знака, что исходник.

Вкладка «🌐 Языки» показывает фразы кода рядом с конфигом — «таблицы» `код сервера · <область>` в конце списка, правятся так же; у фразы

### API шва (для перевода литералов обвязки)

```csharp
DmText.T("ui:settings.language", "Язык:");                                    // фраза; источник — тот же объект строки, 0 байт
DmText.T("ui:altar.seals", "Печатей: {n} из {max}", "n", n, "max", max);      // подстановки парами (до 4), больше — словарём
DmText.Tn("ui:town.items", n, new PluralForms(one: "{n} вещь", few: "{n} вещи", many: "{n} вещей", other: "{n} вещи"));  // {n} — само
DmText.With(DmLang.LocFor("en"), key, source);                                 // явным языком (окно выбора — подписи выделенного)
```

* Ключ — СТРОКОВЫЙ ЛИТЕРАЛ `ui:<область>.<camelCase>` (как `srv:`), один ключ — один исходник; предложение — одна строка со `{слотами}`.
* Семантика — `tr` / `trn`: перевода нет или он пустой → таблица источника (`locales.ru.strings`) → исходник; без подстановок строка не
  трогается; `{имя}` (`[a-zA-Z0-9_.-]`) — `String(v)` JS (число — кратчайшей записью, `true`/`false`, `null`); неизвестный слот — как есть;
  `{n}` формы по числу перебивается подстановкой; ПУСТАЯ форма исходника — значение (`??`, не `||`), пустая форма перевода — как нет.

### Корпус `ui:` (`corpus.ui.json`, `uiExtract.ts`, `uiCorpus.ts`)

`npm run i18n` проходит рантайм Unity-репо (`DM_UNITY_REPO`, иначе соседняя `../ashes of the past/Ashes of the past` от корня веба), находит
каждый `DmText.T` / `Tn` / `With` / `WithN` своим лексером C# (комментарии, символы, `@`/`$`-строки, дыры интерполяции — пример в
`///`-комментарии `DmText.cs` не ключ, вызов в `$"{…}"` — ключ) и переписывает снимок `corpus.ui.json` (форма — как у `corpus.srv.json`) и
эталон Unity `__golden__/unity_ui.json` (корпус + таблица языков: источник `ru` и псевдоязык `xx`, каждый ключ — транслитом). Unity-репо
нет — берётся закоммиченный снимок, отчёт так и пишет. Ключ — литерал `ui:<область>.<camelCase>`, исходник — литерал (без `$`, `@`,
склейки; формы — `new PluralForms(other: "…", one: "…", …)` именованными литералами), один ключ — один исходник: нарушение — отказ.

* Покрытие, сироты и заготовки `i18n:stub` — по трём корпусам (`cfg:` + `srv:` + `ui:`); псевдоязык (`pseudoLocales`) покрывает и `ui:`.
* Вкладка «🌐 Языки» — «таблицы» `клиент Unity · <область>` после фраз сервера, правятся так же (у фразы по числу — поле на категорию).
* Перевод `ui:` ложится в ту же таблицу `locales` и уезжает в Unity с конфигом (`DmLang` → `DmI18n.Loc`); сервер ключей `ui:` не читает.

## Ключи

* **Текст конфига:** `cfg:<таблица>/<путь по id>/<поле>` — `cfg:items.base/quilted-cap/name` (таблица — ключ реестра, с точкой).
* **Литерал кода:** `ui:<область>.<вещь>` — `ui:town.forge.title`. Авторский, русский источник лежит в

Путь идёт **по `id`, а не по индексу**: вставленная в середину списка вещь не должна сдвигать ключи
остальных. Опора берётся тремя ступенями (`anchor()` в `keys.ts`): `id`-подобное поле → хэш условия

(`rare-names.nouns`, `rare-names.epithets`): переупорядочивание ключи не двигает, а правка слова даёт
новый ключ, и это верно — другое слово требует другого перевода.

⚠ Поля, в которых живёт игроцкий текст (`I18N_TEXT_FIELDS`), **не угаданы**: собраны замером всех полей
конфига с кириллицей (23 поля) и отобраны вручную. В список входят **фрагменты сборки имён** (`adj`,
`with`, `epoch`, `word`, `t`, `name2h`, `template`): имена вещей не хранятся, а собираются по шаблону, и
пропуск фрагмента дал бы вещь с переведённым описанием и непереведённым именем. Внутренние поля
перечислены явно (`I18N_INTERNAL_FIELDS`: `ref`/`source` — скрытая справка ковки, `seam` — имя кодового шва).

## Где живут переводы

Таблица реестра **`locales`**: `язык → { name, enabled, coverage, grammar, strings }`. Новый язык — **правка
данных, а не кода**.

Почему в реестре, а не сбоку — решение владельца 26.10: «все языки должны и на сервере быть, чтобы при
создании новой вещи сразу было видно, как она будет называться на всех языках». Имя вещи не хранится, а
собирается, значит предпросмотр требует всех языков **рядом, в одном процессе**. Из реестра это получается
даром: редактор берёт таблицу телом `/api/config`, live-apply и сверка 409 работают как у любой таблицы. ⭐ 07.11 (шаг 9): редактор — ПОЛНЫМ
телом (`CONFIG_FULL_URL` = `/api/config?locales=full`), игрок — тонким (мета пакетов + `ui:`, `playerLocales`).

⚠ **Но перевод не входит ни в одну ревизию конфига** (`CONFIG_TEXT_ONLY_KEYS` в `configRev.ts`,
фильтр `CONFIG_KEYS` в `registry.ts`, `gameView` отдаёт `null`). Иначе каждая из сотен правок перевода
закрывала бы кузницу и лавку **всем игрокам** с «Цена изменилась» и заново резала релиз контента — тот же
случай, что с правкой текстуры в Д1, только частотой выше. Сверка 409 от этого не страдает:
`staleConfigKeys` считает ревизии по **правленым** таблицам отдельно.

## Грамматика — данные языка, а не код формулы  ✅ 27.10

Русское согласование было зашито в **код**, и притом в четырёх независимых реализациях:
`craftType.agree`, `itemgen.declineTier`, Unity `DmTownCraft.Agree` и Unity `DmTownUpgrade.DeclineTier`.
В паритете их держали только золотые эталоны окон, а те сверяют итоговые строки — расхождение правила
видно в них лишь если оно попало в показанную вещь.

⚠ **Замер 27.10: две TS-копии расходились.** На 65 прилагательных живых данных × 4 согласования
расхождение одно — «падающий» в среднем роде: `agree` даёт «падающее», `declineTier` давал «падающое».
Слово живёт в `weapon-anatomy`, то есть ходит только через `agree`, поэтому объединение на `agree` **не
сдвинуло ни одного живого имени** — и попутно унесло заготовленную ошибку: стоило бы «Падающий» попасть
в ступени или в слова аффиксов, и игрок увидел бы «Падающое копьё».

### Как теперь

| Роль | Слоты | Что делается |
|---|---|---|
| голова | `base` | **несёт** согласование: его объявляет перевод, запас — `items-base[].gender` |
| согласуемое | `tier`, `prefix`, `title` | прилагательное: берётся форма под согласование головы |
| инвариант | `suffix`, `noun`, `epithet` | родительный падеж, вставляется как есть |

```json
"cfg:item-tiers/t3/name": { "m": "Кровавый", "f": "Кровавая", "n": "Кровавое", "pl": "Кровавые" }  // ru
"cfg:item-tiers/t3/name": "Bloody"                                                                 // en
"cfg:item-tiers/t3/name": { "m": "Sangriento", "f": "Sangrienta", "pl.m": "Sangrientos" }          // es
```

**Токены признаков — закрытый словарь** (`AGREEMENT_FEATURES`): род `m|f|n|c`, число `sg|pl`, падеж
`nom…loc`. Закрыт намеренно: в WoW признаки накопились двумя несовместимыми нумерациями, и живут до сих
пор обе. Ключ формы — токены через точку в любом порядке при чтении (`gen.pl.f` = `f.pl.gen`),
канонический порядок при записи — падеж, число, род. Признаки отбрасываются **от падежа к роду**: род
держится дольше всех, потому что согласование в наших данных — это прежде всего род.

⚠ **Падежи заложены форматом, но НЕ ЗАПОЛНЯЮТСЯ.** Имя всегда в именительном: ни одно игроцкое
предложение не вставляет имя вещи внутрь себя (замер 26.10), а падежи — это ×6 работы переводчику без
единого видимого следствия. Так же сделано в Grim Dawn. Если решение пересмотрят, менять придётся
данные, не код.

⚠ **Старое `p` конфига — это ЧИСЛО, не род** («Сапоги», «Перчатки»). Поле в данных не трогали (232
записи и золотые эталоны), приводим на входе: `normalizeAgreement('p') === 'pl'`.

### Порядок слов — тоже данные

```json
"es": { "grammar": { "join": " ", "agrees": true }, "templates": { "item.tiered": "{base} {tier}", "item.titled": "{base} de {title}" } }
"zh": { "grammar": { "join": "",  "agrees": false }, "templates": {} }
```

⭐ **Китайскому не нужен ни один шаблон** — только `join: ""`: пробельный разделитель шаблона берётся из
грамматики языка. Это и есть проверка того, что порядок слов действительно вышел из кода.

⚠ **Литерал между пустыми слотами не выводится.** Пустые слоты — норма (у клинка без навершия слот
`{head.pommel.with}` пуст), и дословная подстановка дала бы висящую связку: «Sword of» без слова.
Правило: литерал между двумя слотами выводится, только если непусты **оба**.

⚠ **Регистр правится у ТОКЕНА, а не поиском подстроки.** В русском PoE заглавные ставили подстановочной
заменой, и вышло «поЛукафтан».

### Запас арифметики

`formulas/ruAgree.ts` — **единственная** в проекте арифметика русских окончаний, и она **запас**:
работает там, где формы ещё не заполнены **и** язык русский. По мере заполнения таблицы каждая запись
перебивает арифметику; когда таблица полна, сюда не заходит никто. На любом другом языке арифметика не
зовётся вовсе — русские окончания на испанском это мусор, который выглядит как перевод.

### Рецепт имени живёт на вещи

⚠ Имя **запекается при рождении** вещи в поле `Item.name` и уезжает в сейв. Почти все части имени из
вещи выводятся (база — `baseId`, ступень — `tier`, слова аффиксов и титул уника — `affixes[].affixId`),
а основа и эпитет рарного имени выбраны случайно и не выводятся ничем. Поэтому их id запоминаются в
`Item.nameRoll`: без них клиент не смог бы пересобрать имя на своём языке, а сервер не может собрать его
за клиента — он не знает языка игрока и текста ему не шлёт. Так же устроен живой API Guild Wars 2: он
отдаёт **части** имени, а не склеенную строку. ⭐ i18n Ф2 (06.11): с Ф1 сервер язык игрока знает и шлёт весь текст сам — и
`nameRoll` пригодился ему: показ пересобирает имя по этим частям на языке получателя (`itemDisplayName`, раздел Ф2 выше).

⚠ `nameRoll` пришлось заявить и в схеме сейва (`validation/save.ts`): схема срезает незаявленные ключи,
и срез означал бы, что после перезахода имя рарной вещи больше нечем собрать — молча и навсегда.
Серверный фаззер экономики поймал это сам: его инвариант «зачарование меняет только rarity/affixes/name»
увидел четвёртое поле. `nameRoll` — часть имени, а не отдельное свойство, и в инварианте стоит рядом с
`name`.

## Шов

`Localizer` — **класс**, а не модульное «текущий язык», сознательно: редактору нужно показать имя новой
вещи сразу на всех языках, то есть несколько языков в одном процессе. Игровой клиент держит один
экземпляр, редактор — по одному на язык.

```ts
const es = new Localizer(reg.get('locales'), 'es');
es.text(key, sourceFromConfig);        // перевод → источник → пусто
es.form(key, agreement, source);       // форма под согласование существительного
es.agreementOf(key, 'm');              // род, объявленный переводом
es.t('ui:altar.seals', { n: 3, max: 8 });   // подстановки — только у `ui:`-ключей
es.join(parts);                        // склейка по правилам языка (zh — без пробелов)
es.template('item.tiered');            // шаблон порядка слов: свой у языка → русский по умолчанию
es.name('item.tiered', { tier, base }); // собрать имя по шаблону локали
```

Сборка имени вещи — один шов на все формы и все языки:

```ts
composeItemName(loc, { shape: 'tiered', base: head, agreement: base.gender, tier: frag(key, 'Кровавый') });
```

### ⚠⚠ Три правила, без которых порт расходится молча

Их назвала встречная проверка порта, и каждое подтверждено ЗАПУСКОМ обеих реализаций, а не чтением.

**1. Имена собираются ЯЗЫКОМ-ИСТОЧНИКОМ, пока перевод не раздаётся.** Имя печёт сервер (кодом веба),
и там сборку зовут без разрешителя: `retierItem` принимает `opts.loc`, и не передаёт его НИКТО.
Подключи клиент к живой таблице — и с первой же строки, набранной во вкладке «Языки», верстак обещал
бы одно имя, а в сумку легло бы другое. Поэтому в Unity сборка зовётся через `DmI18n.Src()`, а сторож
проверяет, что `RetierItem` в `cfg["locales"]` НЕ СМОТРИТ. Когда перевод начнут раздавать (шаг 9),
переводить надо ПОКАЗ готового имени — одинаково во всех окнах и по `Item.nameRoll`, — а не эту сборку.
⭐ i18n Ф2 (06.11): так и сделано — на сервере: сборка печати не тронута, показ — `itemDisplayName` со сверкой с испечённым.

**2. «Пробел» — по ECMAScript, а не по рантайму.** Наборы НЕ совпадают в обе стороны: U+0085 (NEL)
для `char.IsWhiteSpace` пробел, для JS — нет; U+FEFF (BOM) наоборот. Слот из одного U+0085 веб
считает заполненным и выводит связку, а .NET выбросил бы и слот, и связку; BOM в имени слота шаблона
веб подрезает, а .NET потерял бы ступень целиком. Оба знака — обычный мусор импорта (0x85 из CP1252,
BOM из копирования), и санитайзер вкладки их не снимает: там тот же `trim()` JS. В порте за это
отвечает `JsSpace`/`JsTrim`, в эталоне — три случая.

**3. Регистр не зависит от локали хозяина.** Было `toLocaleUpperCase()` — то есть правила ОС того,
кто запустил процесс: на турецком хосте `i` даёт `İ`, и одно имя выходит разным у сервера, редактора
и игрока. Снято (`toUpperCase`), русский не сдвинулся ни на байт. ⚠ Остаток, НЕ закрытый портом: JS
делает ПОЛНОЕ юникодное отображение (`ß` → `SS`, `ﬁ` → `FI`), .NET — только простое. На русском не
видно, оживёт на первом латинском переводе — решать вместе с его включением (таблица полного
отображения в C# либо `capitalize: "none"` у таких языков).

Там же закрыты мелочи: `\z` вместо `$` в арифметике окончаний (в .NET `$` совпадает ещё и ПЕРЕД
завершающим переводом строки, в JS — нет), `NaN`/`∞` в `coverage` (zod их отвергает, Newtonsoft
принимает), таблица языков собирается без прототипа (язык с кодом `__proto__` ронял разбор ВСЕЙ
таблицы, а с ней весь конфиг — вход достижим фаззером инвариантов).

⚠ И про сам прогон: **`Assembly.LoadFrom` в .NET Core сперва ищет сборку ПО ИМЕНИ** рядом с
`Harness.dll`, поэтому прибор `tools/unity-check` с переданным путём к `Library/ScriptAssemblies`
молча грузит СТАРУЮ копию из `out/`, если она там лежит. `unity_check.py` этим не страдает (он сам
пересобирает `out/`), а вот быстрый прогон «против свежей сборки редактора» надо делать из ПУСТОЙ
папки с одним `Harness.dll` — иначе проверяешь чужой бинарник и не знаешь об этом.
