# dungeon (shared) — генерация этажа

Один код этажа на сервер, сим, фаззеры и превью редактора. Сетка мира `grid[y][x]` (`world/grid.ts`), клетка = `TILE` = 32 ед. мира = 1 м
в Unity. Точки мира — центры клеток (`cellToWorld`), x — столбец, y — строка.

## Порядок сборки (`generateFloor.ts` → `generateFloorParams`)

1. **Геометрия** по алгоритму этажа (`algorithms/`: rooms / bsp / cellular / maze / prefab) + выходы + замки «дверь↔рычаг»,
   инвариант `validate()` с перегенерацией (16 попыток) и фолбэком «снять замки». ⭐ 13.10: ширина коридоров rooms / bsp — «от `corridorWidth`
   до `corridorWidthMax`» на каждую связку комнат, свой поток `seed ^ 0xc0dd` (крипта — 2…4; раздел «13.10» ниже).
2. **Пост-обработка биома** (`biomes[].pillars/torches = false`): клетки-колонны → пол, процедурные колонны и стоячие факелы прочь.
3. **Фичи этажа** (`applyFeatures`, поток rng `seed ^ 0xfea7`): портал, лавка, теги комнат (босс/уники/сокровищница).
4. ⭐ 08.10 **Оформление биома** (`dressing.ts`, поток `seed ^ 0xd7e5`) — только если у биома есть `dressing` (см. ниже).
   ⭐ 12.10 (Ф2) **Слоты пропов** (`slots.ts`, свои потоки на комнату и проход) — только если у биома есть `dressing.props`: пропы с паспортом
   встают по слотам (центр, полосы, арки, у стены, углы, грани), а россыпь шага 5 остаётся строкам `objects` без паспорта (раздел «Ф2» ниже).
5. **Россыпь** (`decor.ts`): `placeFloorDecor` (поток `^ 0xdec0`) и `placeWallProps` (поток `^ 0x3a11`) — по `spawnChance` объектов.
   Объекты оформления в россыпь не попадают (правилом, без броска), занятые оформлением клетки и грани она обходит.
   ⭐ 08.10: стоящий напольный декор занимает весь след (не только клетку под точкой) и держит свой **отступ** (ниже).
   ⭐ 12.10: плотность — из биома (`biomes[].decorDensity`), вес — из конфига, объекты — и неявные из паспортов декора Unity (ниже).
6. **Сундуки** (`placeChests`, поток `^ 0xc4e5`): не под преградой декора (`obstaclesFromDecor`, запас ¼ клетки).
   ⭐ 13.10: вид сундука — только Unity: модель биома `environment[].chestModel` (крипта — `crypt_wooden_chest_01`; не декор — паспорта нет,
   сервер поле не читает), лицом от ближайшей стены, крышка откидывается по `chest-opened`, сундук стоит до конца этажа; сундук-декор
   сокровищницы (`applyFeatures`, та же точка, что у её сундука) под ним не рисуется. Расстановка, коллизия (сундук — не преграда) и радиус
   открытия (56 u от точки) прежние. ⭐ 13.10: `floorInit` шлёт и открытые сундуки (`opened: true`) — после повторного входа в узел
   (продолжение, вход посреди этажа, реконнект) открытый стоит открытым и без [E] (было — его не было вовсе). Сундук-декор (зоны префабов,
   центр сокровищницы) Unity рисует с откинутой крышкой — «уже взят» ([E] у него нет и не было); у стены вид сундука сдвинут вперёд, чтобы
   откинутая крышка не уходила в стену (точка сервера и радиус открытия — прежние).

Каждый шаг — свой поток rng: новый шаг не сдвигает остальные. Сетку после шага 2 ничто не меняет — проходимость держит `validate()`,
декор даёт только суб-тайловые преграды (`obstaclesFromDecor` → `WorldState.obstacles`). Монстры (`floor.ts spawnPacksEl`) и сундуки
обходят преграды тем же предикатом. ⭐ 08.10: путь монстров в погоне и ботов сима — по маске навигации декора (`world/pathfind.ts`
`navMaskFor`): клетки под преградой и рёбра сквозь неё путь не берёт, сетку маска не меняет.

## ⭐ 08.10: отступ напольного декора (`objects[].clearance`, `decor.ts` `FloorClaims`)

Кольцо в `clearance` клеток вокруг следа, где не стоит ДРУГОЙ напольный декор (решение владельца: костёр и решётка рядом — некрасиво).
Правило в обе стороны: объект не ставится, если его след попал в «след + отступ» стоящего, или его «след + свой отступ» задел след стоящего —
у двух объектов с отступом 1 между следами всегда клетка пола (ни гранью, ни углом). След — `footprintRect` (центр следа в точке декора;
центр посреди клетки — на клетку шире: костёр в комнате нечётной ширины лежит на трёх клетках); декор без `footprint` (портал, лавка) —
клетка под точкой; настенный (факелы, ниши) — не напольный. Держат и россыпь (`placeFloorDecor`, стоящий декор — по всем спекам биома,
вместе с выпавшими из россыпи объектами оформления), и костры (`placeDressing`). Отступ 0 у всех — раскладка байт-в-байт прежняя
(замер 08.10: 900 этажей всех биомов + синтетика с многоклеточным декором). Крипта: костёр и решётка — 1.

## ⭐ 12.10: паспорт декора и неявные объекты (Ф1 плана декора)

Два слоя: **паспорт** — свойства самого пропа (пишет Unity: компонент `DM.Art.DmDecor` на префабе → `ArtManifestExporter` → `art[].decor`,
схема `artDecorSchema`), **правила** — где и сколько (конфиг биома). Поля паспорта: `contexts[]` (floor / againstWall / wall / wallInsert /
corner / doorFlank / doorway / socket / scatter), `footprint` (клетки по осям модели; Unity считает из габарита ⌈размер − 0.1⌉), `anchor` +
`backOffset`, `facing`, `clearance`, `keepPath`, `blocks`, `blocksSight`, `tall`, `tags[]`, `rooms` (веса по типу комнаты и коридору), `weight`,
`variance` (только картинка — в игровую ревизию не входит), `biomes[]` (пусто — биом папки, группа `biome_<id>`), `doorway.width`, `stack.max`,
`hosts[]`.

- **Неявный объект** (`placeableObjects`): ключ манифеста вида env/prop с паспортом и без строки `objects` (ни `id`, ни `modelId` этого ключа) —
  расставляемый объект `id = modelId = ключ`, роль prop, поверхность — стена, только если все контексты настенные, частота 1 (сколько — решают
  слоты биома и веса; настенный неявный объект в Ф1 не ставится — ниже), прочее — паспорта. Строка `objects` с моделью-паспортом главнее паспорта во всех своих полях; из паспорта ей приходят
  контексты, веса по комнатам и вес (если нет своего `objects[].weight`). Выключенная строка выключает и ключ. Без биома — не ставится
  (предупреждение редактора `decorWarnings`, там же — роль `decor`, которую сервер не ставит, G15). Тот же список у Unity (`EnvRules.PropSpecs`,
  сторож — раздел `decor` эталона `EnvCheck`).
- **Ф1 ставит паспорта только прежними проходами:** россыпь пола (`placeFloorDecor`) — объекты с контекстом `floor`, грани стен (`placeWallProps`) —
  с контекстом `wall`; у стены, угол, проём, сокет, сор — слоты Ф2–Ф5 (сейчас не ставятся). Без паспорта — как прежде. ⭐ 12.10 (Ф2): так — только
  у биома БЕЗ правил пропов (`dressing.props`); с правилами паспорта ставят слоты (раздел ниже), россыпь — только строки без паспорта.
- ⚠ **Грани стен — только строкой `objects`** (ревью 12.10): у прохода граней НЕТ бюджета — бросок на каждую открытую грань, плотность держит
  только `spawnChance` строки (умолчание 0.35). Неявный объект идёт с частотой 1 и с контекстом `wall` занимал 82 % граней этажа, коридоры тоже
  (проба ревью: 1680 из 2046 граней, 5 сидов), — в проход граней он не допускается и ждёт слотов стены Ф2 (с бюджетом); в списке объектов он
  есть (кит Unity знает модель заранее). Строка `objects` с поверхностью wall и паспортом модели — своей частотой, а вес — с множителем паспорта
  `rooms` по МЕСТУ грани: тип комнаты, в прямоугольнике которой клетка перед гранью (первой, как зоны `wallRuns`), иначе `corridor`
  (`corridor: 0` — не в коридорах). Без паспортов место не считается — поток rng прежний. Сторож — `decorPassport.test.ts` («грани стен», проба
  ревью на живых этажах крипты).
- **Вес** (G2): `objects[].weight` → `art[].decor.weight` → 1 (был зашит 1), × `rooms[тип комнаты]`; у всех 0 — никого.
- **Повёрнутый след** (G3, `rotatedFootprint`): `footprint` в записи — в осях модели, в клетках — с поворотом (90°/270° меняет стороны);
  неквадратный след россыпи поворачивается ДО выбора места (квадратный — после, как прежде: поток rng прежний). Тот же счёт — `footprintRect`,
  `FloorClaims`, Unity `EnvRules.CoveredCells`, веб-стенд `env3d.ts`.
- **Правило проходимости** (G11, только для преград россыпи): вокруг следа — кольцо в клетку пола без следа другой преграды; тогда путь сквозь след
  обходит его по кольцу, и декор не отрезает ни клетки (коллайдер внутри следа).
- **Плотность** (`biomes[].decorDensity`: `chancePerRoom` / `maxPerRoom` / `areaPerSlot`; в data у всех — прежние 1 / 2 / 60).
- **Входы этажа одни на всех** (G12, `floorInputs.ts`: `floorInputs` / `generateFloorFor`): сервер (`Room.enterNode`), сим (`runSessionSim` — теперь с
  декором, оформлением и преградами), нагрузочный бенч, превью редактора (забег, «Этажи», «Дроп» — сырыми данными рабочей копии): спеки декора
  биома, плотность, сундуки, оформление. ⚠ Фаззер правил (`rulesFuzz.ts`) ещё зовёт `generateFloor` сам без плотности биома — те же этажи, пока
  `decorDensity` = умолчаниям; перевести на `generateFloorFor`.

Без паспортов этаж байт-в-байт прежний: сторож `decorPassport.test.ts` сверяет путь сервера на замороженных входах со снимком кода до Ф1
(`__golden__/floors_pre_passport.json`, все биомы × этажи × 6 сидов); намеренная правка генерации — `DM_DECOR_GOLDEN=write` в том же тесте.

## ⭐ 12.10: слоты и полосы (Ф2 плана декора, `slots.ts`, правило `biomes[].dressing.props`)

Отзыв владельца по скринам Ф1: «столы и стулья посреди комнат — странно». Пропы с паспортом у биома с правилом `dressing.props` ставит не
россыпь, а СЛОТЫ — проходами от крупного к мелкому, каждый видит занятое предыдущими (`placeSlots`, зовётся из `generateFloorParams` после
оформления, до россыпи строк без паспорта — решётка пола крипты вернула свои слоты, — граней `placeWallProps` и сундуков). Сетку не меняет:
пропы — суб-тайловые преграды, клиенту — прежний `FloorInit.decor` (протокол и Unity без правок: Unity рисует, что пришло).

**Правило биома** (`biomeDressingSchema.props`, числа — в `data/biomes.json`, в редакторе — «Оформление» → «Расстановка пропов по слотам»,
подписи `editor/src/decorLabels.ts`):

| Поле | Что | Крипта |
|---|---|---|
| `density` `min`/`max`/`perArea` | пропов на комнату — от min до max на каждые perArea клеток её пола (центр, углы, у стены — в счёт; арки и грани — сверх; вход — без пропов) | 3–6 на 100 |
| `emptyRoomShare` | доля почти пустых комнат (ритм «полно — пусто»: ни центра, ни углов, ни у стены; арки и грани есть) | 0.25 |
| `sameNotNear` | тот же проп не ближе, клеток (между точками); ⭐ ревью: арок не касается — арка рама КАЖДОГО проёма | 4 |
| `lanes.width` | ширина полос прохода, клеток | 2 |
| `center` `on`/`chance`/`minRoom`/`minFoot` | Р2: центральная вещь большой комнаты (меньшая сторона от minRoom; проп контекста floor со следом от minFoot, не высокий; кольцо пола в клетку; одна на комнату) | да / 0.35 / 9 / 2 |
| `againstWall` `on`/`step` | спиной к стене; центры соседей на стене — не ближе step граней | да / 3 |
| `corner` `on`/`chance`/`pair` | угол — шаблон 2 × 2 на двух смежных стенах: шанс угла и шанс второго по другой стене (диагональ свободна) | да / 0.5 / 0.5 |
| `doorway` `on`/`chance`/`clearBeyond` | арка в проём: ширина паспорта (`doorway.width`) = ширине проёма; ⭐ ревью: «тень» арки — `clearBeyond` клеток за проёмом в сторону от камеры — не на полу другой комнаты (0 — без правила; ниже); ⭐ 13.10: кандидаты — все арки ширины проёма, выбор по весу паспорта (крипта: обе — проём 3; проём 4 — без арки) | да / 1 / 6 |
| `wall` `on`/`step`/`chance`/`corridors` | грань стены (контекст wall) — позиции с шагом, на каждой шанс; и в коридорах; ⭐ 13.10: у крипты выключено — настенного паспорта (лишь wall / wallInsert) нет, а включённый пустой слот — вечное предупреждение «Проверить конфиг», за которым прятались бы новые | нет / 4 / 0.5 / да |

**Контексты паспорта в Ф2:** `floor` — центр большой комнаты (не россыпь!), `againstWall` — у стены (пивот — линия стены + `backOffset` при якоре
back, иначе ПОЛГЛУБИНЫ МОДЕЛИ — ⭐ 13.10, ниже; `facing` room — лицом в комнату, along — вдоль, иначе все четыре), `corner` — угол (следы 1 × 1, 2 × 1, 2 × 2),
`doorway` — арка по центру проёма поперёк него (не преграда, клетки проёма резервирует; ⭐ 13.10: след записи — проём, `doorway.jambs` — колонны
косяков, раздел «13.10»), `wall` — грань (⭐ ревью: только НАСТЕННЫЕ спеки — паспорт
лишь wall / wallInsert; смешанный «грань + у стены» — поверхность пол: Unity рисовал бы его на полу и не гасил со стеной, — на гранях не встаёт,
предупреждение редактора). Высокие (`tall`) — только у ДАЛЬНИХ стен (`isFarFace`, север и восток при азимуте −45°), угол — обе стены дальние, не
перед факелом; арки — только в проёмах дальних стен, с рамой стен по краям, не дверь рычага и не тенью на другую комнату (ниже). Перед нишами
статуй — ничего. `socket` / `scatter` / `doorFlank` / `wallInsert` — наборы Ф4 и сор Ф5 (не ставятся):
стулья и табуреты крипты — сокет столов (решение владельца: ждут наборов).

**Порядок в комнате** (Р0 → Р1 → Р2 → Р4 → Р6 плана; по комнатам `L.rooms` по порядку, коридоры — в конце):
1. Р0 якоря — спавн, выходы, рычаги, клетки дверей, сундук/портал/лавка/арена заняты сразу; Р1 (факелы, ниши, костры) уже стоит.
2. Бюджет комнаты — бросок «пустая», иначе цель `round(U(min, max) · площадь / perArea)`.
3. Р2 центр (с кольцом пола вокруг).
4. Р0 полосы — ДЕРЕВО кратчайших путей (Прим) между серединами устьев проёмов и якорями комнаты, кистью `width × width`, вписанной в пол, + устья
   проёмов с клеткой у каждого косяка. ⚠ Полосы ведутся ПОСЛЕ центра и костра и огибают их кольцо (иначе центр почти не вставал бы); дерево, а не все
   пары — все пары покрывали ~60 % пола комнат. В полосе нет преграды и пропа «не запирать проход» (`keepPath`). ⭐ Ревью: полоса идёт только по
   клеткам, где можно стоять (центр не под коллайдером стоящего декора радиусом героя — ниша статуи выходит в клетку перед собой и сужала полосу 2
   до 1: 499 клеток на 300 этажей → 0; устье проёма — полоса всегда), и держит преграды россыпи строк без паспорта (`placeFloorDecor(…, lanes)`:
   решётка крипты — не преграда, её раскладка прежняя; сделанная твёрдой — 58 % на полосах → 0). Полосы держат только преграды и `keepPath`.
5. Арки в проёмы (⭐ ревью: не тенью на другую комнату — ниже). 6. Заявки углов берут свою долю бюджета. 7. Спиной к стене — остальное (раньше углов;
   выбор по весу паспорта). 8. Углы; ⭐ ревью: НЕДОБОР УГЛОВ (заявка не встала — нет места, откат Р6) снова идёт спиной к стене (тот же поток):
   без возврата слоты выбирали 80 % цели, 39 % комнат ниже цели (замер ревью; ширина полос тут почти ни при чём — полосы 1 дали 80.7 %), с
   возвратом — 88 % и 22 %. 9. Грани стен (сверх бюджета; только настенные спеки); коридоры — только грани и арки (`corridor` веса паспорта).
- Р6 на каждой преграде: `Passability` — маска навигации с запасом `PLAYER_RADIUS` и достижимое от спавна при открытых и закрытых дверях рычагов;
  быстрый путь — локально (сменившиеся клетки в рамке: достижимые клетки рамки связаны внутри неё), иначе обход этажа. Отрезала клетку, выход, рычаг,
  проём — откатывается ТОЛЬКО этот проп (счётчик `rejected`), этаж заново не строится. ⭐ 13.10 (финал ревью): преграда на клетке спавна —
  отказ сразу (быстрый путь её пропускал: спавн, став непроходимым, выпадал из нужных клеток рамки; фаззер ревью — 684 из 36 000 вызовов на
  синтетике, в данных крипты — 0 на 2000 этажей); кэш достижимого (открытые и закрытые двери) пишется только после ОБЕИХ проверок — раньше
  отказ закрытой оставлял в кэше открытой дыры отвергнутой преграды. Сторож — фаззер против оракула (`buildNavMask` + обход, 300 сеток ×
  12 преград: решения и маска — те же) и две синтетики.

**⭐ Пивот у стены — по модели (финал ревью, 13.10).** Проп у стены и в углу (якорь center/corner) стоит спинкой МОДЕЛИ на линии стены: от линии
до пивота — полглубины модели поперёк стены при выбранном повороте, по коллайдеру спеки (тот же, что даёт преграду: бокс — `h`, при повороте

## Оформление биома (`dressing.ts`, конфиг `biomes[].dressing`, в редакторе «Оформление»)

Правила вместо случайной россыпи — по эталонной комнате владельца (крипта). Нет `dressing` — этаж байт-в-байт прежний
(сторож `dressing.test.ts`). Едет опцией генерации `GenFloorOpts.dressing` (`dressingOf(biome, balance)`), НЕ в `FloorSpec`:
спецификация ходит по проводу в `runPlan`.

- **Грань** — открытая сторона клетки-стены с нормалью `(dx, dz)` к проходимой соседке. Грань, чья соседка — дверь, — косяк: не берётся.
  **Пробег** (`wallRuns`) — прямая цепочка граней одной нормали, клетки перед которыми в одной зоне (комната из `L.rooms` / коридор).
- **Факелы** (`torch`): шаг `spacing` в комнате (минимум один на пробег), `corridorSpacing` в коридоре (только целый шаг; 0 — нет),
  от концов пробега (углы, проёмы) — `cornerGap`. Узор по центру пробега.
- **Статуи в нишах** (`statues`): только на ДАЛЬНИХ стенах — `dot(n, (sin az, cos az)) > 0`, `az = balance.camera.azimuthDeg`
  (камера веба `camDirXZ`/`placeCamera`, Unity `CameraRig`; при −45° — северные и восточные стены). `min…max` на комнату, в коридоре —
  `corridorChance` на подходящий пробег. Блок [факел][статуя × `width`][факел] по центру пробега, не у дверей/выходов/рычагов/спавна.
  Модель статуи несёт свой кусок стены: `DecorObject.wallFaces = [cx, cy, dx, dz][]` — грани, сегменты которых клиент не ставит.
  ⚠ `width` обязана равняться ширине модели статуи (габарит X в манифесте арта, у статуй крипты — 2 м): шире — модель влезет в соседние
  сегменты и фланговые факелы, уже — дыра в стене. Сторож — `dressingWarnings` (редактор, «Проверить конфиг» — предупреждение).
- **Костры** (`firePits`): центр не-входной комнаты с меньшей стороной ≥ `minRoom`, с шансом `chance`; footprint и кольцо в клетку
  вокруг — пол без спавна/выходов/рычагов/прежнего декора (костёр обходится со всех сторон); ⭐ 08.10 + отступ объекта (`clearance`).
- Объекты — из `objects` (коллайдер, свет `objects[].light`): выключенный или чужой биому объект не ставится.

## Провод клиенту

`FloorInit.decor` — весь декор (в т.ч. `wallFaces` у ниш); `FloorInit.rooms` (⭐ 08.10) — прямоугольники комнат в клетках, только в
подземелье (пробы отражений по комнате в Unity).
