# anim-ai — шим генерации анимаций

Сервис на конце провода, который в поз-редакторе был проложен, но никуда не вёл: вкладка «ИИ»
шлёт `POST {prompt, seconds, character, weapon}` и ждёт BVH либо GLB, а `clipBaker` запекает
ответ в наш `Clip`. Здесь — вторая половина.

Движок генерации живёт **на другой машине** (Ryzen 9950X + GTX 1070), весит больше десяти
гигабайт и собирается своим тулчейном. Поэтому это отдельный процесс, а не роут игрового сервера:
игра не должна ни зависеть от него, ни падать вместе с ним.

## Быстрый старт (проверка канала без движка)

```bash
ANIM_KEY=любой_длинный_секрет npm run anim-ai:stub
```

Сервис напечатает свои адреса в локальной сети. Дальше в поз-редакторе, вкладка **ИИ**:
адрес `http://<адрес>:8790/gen`, тот же ключ в поле «ключ», кнопка **⌘ проверить связь**,
затем **✦ сгенерировать**.

Заглушка отдаёт настоящий разбираемый BVH с нашими каноническими именами костей, поэтому проходит
**ровно тот же путь**, что пойдёт ответ настоящего движка. Движение намеренно нелепое (обе руки
машут, корпус качается): клип, случайно оставшийся в библиотеке, обязан кричать о себе.

## Настоящий движок

Команда задаётся шаблоном, поэтому и `kimodo.cpp`, и вариант на PyTorch подключаются **без правок кода**:

```bash
ANIM_KEY=... \
ANIM_CMD='kimodo_gen --prompt {prompt} --frames {frames} --steps {steps} --seed {seed} --out {out}.bvh' \
ANIM_MODEL='Kimodo-SOMA-RP-v1.1' ANIM_DEVICE=vulkan \
npm run anim-ai
```

Подстановки: `{prompt}` `{seconds}` `{frames}` `{steps}` `{seed}` `{out}`.
Расширение после `{out}` задаёт формат ответа: `.bvh` → текст, `.glb` → двоичный скелетный GLB
(его отдаёт `kimodo.cpp`; конвертер не нужен — запекатель читает оба).

| Переменная | Умолчание | Что делает |
|---|---|---|
| `ANIM_PORT` | 8790 | порт |
| `ANIM_KEY` | `DM_ADMIN_KEY` | ключ доступа; **без него сервис не поднимется** |
| `ANIM_ORIGINS` | дев-серверы | белый список источников CORS |
| `ANIM_CMD` | — | шаблон команды движка; без неё нужен `--stub` |
| `ANIM_FPS` | 30 | кадров в секунду |
| `ANIM_STEPS` | 50 | шагов диффузии (точка «скорость/качество») |
| `ANIM_TIMEOUT` | 600 | потолок на генерацию, секунд |
| `ANIM_MODEL`, `ANIM_DEVICE` | — | что показывать в «проверить связь» |

## Решения, которые лучше не откатывать

**Ключ обязателен, даже локально.** Сервис слушает `0.0.0.0` и **запускает процессы по запросу** —
это ровно та служба, которую нельзя оставлять открытой. Без ключа он отказывается стартовать,
а не стартует молча с предупреждением.

**Оболочки нет.** Промпт пишет человек, и `shell: true` означал бы выполнение чего угодно из текста
запроса. Шаблон разбирается в argv, подстановки идут в **уже разобранные аргументы** — пробелы,
кавычки и точки с запятой внутри промпта остаются данными. Проверено тестом `parseCmd.test.ts`.

**Ключ в редакторе лежит в `pe_prefs`, а не в `pe_ai`.** Адрес сервиса общий для всех машин в сети,
поэтому он едет в рабочей копии и публикуется. Ключ — учётные данные, а рабочая копия уходит
на сервер целиком; таким данным там не место.

**Причина отказа доходит до автора.** Хвост `stderr` движка попадает в `{error}` и показывается
в панели. Иначе на «сервис отказал» остаётся только гадать, что именно не собралось.

**Кэша результатов нет намеренно.** Повторная генерация того же промпта обязана дать ДРУГОЙ дубль —
на этом держится «перегенерировать». Кэшировать имеет смысл эмбеддинг промпта (самая дорогая часть:
энкодер `Llama-3-8B` на CPU), но это делается внутри адаптера движка, когда движок появится:
`kimodo.cpp` принимает готовый LLM2Vec-эмбеддинг вместо текста.
